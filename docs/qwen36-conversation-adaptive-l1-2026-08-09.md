# Qwen3.6 adaptive-L1 multi-turn benchmark (2026-08-09)

## Question

Does a single 512-token completion end before adaptive L1 has enough time to
pay back its update cost?

## Workload

- Three coherent four-turn conversations: coding, humanities/social science,
  and medical/health education.
- 256 generated tokens per turn; 1024 generated tokens per conversation.
- The same session ID and adaptive layout are retained across all four turns.
- Auto checks at token 64 and then every 256 tokens, with a maximum of 40
  promotions per layer and the existing cooldown policy.
- Each Auto run performed two physical L1 commits.

The first natural-generation matrix exposed a correctness problem: every
Off/Auto pair matched on turn 1 and diverged from turn 2 onward, immediately
after the first L1 commit. Arena Off also diverged from Flesh/Tiered Off on
some longer prompts. Because different token streams are not a valid speed
A/B, the performance matrix below replays the exact token IDs generated by a
Flesh/Off reference conversation through every backend and policy.

Decode timing includes the in-generation L1 update pause and excludes prefill.

## Fixed-token results

Arithmetic mean change:

| Engine | Overall | Last 2 turns |
|---|---:|---:|
| Flesh | +8.30% | +8.69% |
| Arena | -0.03% | -2.54% |
| Tiered | +3.57% | +3.01% |

The two commits cost 0.58-0.66 seconds for Flesh, 0.44-0.53 seconds for Arena,
and 0.42-0.44 seconds for Tiered in these runs.

## Interpretation

Longer sessions reveal material additional adaptive value for Tiered and keep
Flesh's improvement clearly positive. Arena does not benefit reliably from the
same Auto policy: its mean is flat and one scope regresses substantially.
Therefore Auto should be tuned or gated per backend rather than sharing one
threshold and promotion policy.

The natural multi-turn divergence must be fixed before Auto is enabled by
default. The timing evidence is useful because all engines replay identical
tokens, but forced replay does not prove generation correctness after a bank
update.
