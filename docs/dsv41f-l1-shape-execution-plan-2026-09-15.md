# DS4.1F 初始 L1 形状构建执行方案

状态：2026-09-15 已完成1～4的实施和检查。用户在性能阶段要求缩减原240次测试，最终采用5例×4次；300条采样、60次容量校准、长Decode和持续会话检查全部完成。小样本Decode变化−0.82%，没有稳定收益证据，默认Main40保持不变。结果见 [执行报告](dsv41f-l1-shape-results-2026-09-15.md)。以下原完整统计验收方案保留备查，本轮未完成其60例性能门槛，不应自动重启扩测。实施脚本见 `experiments/dsv41_analysis/l1_shape/PIPELINE.md`，结果归档到 `artifacts/dsv41-l1-shape-20260915/`。

## 1. 目标和固定约束

从多任务路由数据得到一个通用的逐层容量向量 `C[0..39]`，在相同总缓存预算下优于均匀 Main40。这里的“形状”指每层可驻留的专家数，**不指固定的专家名单**：首轮专家仍从当前输入 Prefill 初始化，后续沿用动态 L1 晋升。

- 每层 L1 容量在32～48之间，第一版只取32/36/40/44/48。
- 总 L1 槽位固定1600，平均40/层；Hot/L0每层固定8，总计320槽。
- 不启用Burst、跨层投机Block、预测L2，不固定任何层全量驻留。
- 原SSD checkpoint、量化、Router、完整Top6、expert计算与归约顺序保持不变。
- 动态专家晋升继续使用当前间隔16步、最多4项/层、衰减与迟滞规则；第一阶段不同时调这些参数。
- 纯文本进程physical footprint峰值不超过65十进制GB。相同槽位数不保证相同峰值，仍需实测。
- 原生GLM/Qwen preadv直写与专家覆写安全栅栏保持。
- 当前均匀Main40保留为默认及回退路径；成功通过独立验收后才讨论替换。

每专家记录18,800,640 bytes。L1 1600槽约30.081GB，Hot320槽约6.016GB；合计36.098GB只是专家bank有效载荷，**不包含**主干、KV、scratch、临时数组及系统文件缓存。不得把此数当作总内存承诺。

## 3. 阶段A：数据清单、去重和冻结划分

交付 `dataset-manifest.json`，记录原文件SHA256、样本ID、任务/语言、消息结构、原划分、父样本关系、实际token数、family_id和最终划分。

1. 以740条集合为入口，不重复读入v2的600条。
2. 检查组合样本与父任务、模板近重复、复述/翻译关系。相同任务家族必须处于同一划分；中文/英文若是同题翻译，也按家族处理。
3. 若父任务分散在原有不同划分，先将整个家族归组，再重新作分层group split；记录变更，不能悄悄把验证/测试父任务并入训练。
4. 检查message与图像字段。本方案第一版仅纯文本，不把文本采样结果当成多模态验收。
5. 固定随机种子、抽样清单、权重和任务家族后冻结测试集。测试集不得用于选择容量或调阈值。
6. 若审计后某个任务/语言组合独立样本不足，补充该组合，不用同一原题改写填充数量。

第一轮建议分层抽样目标（审计后独立家族不足则如实调整）：
- 训练160条：10 Scope×2语言×8条。
- 验证40条：每Scope/语言2条。
- 封存测试40条：每Scope/语言2条。
- 从训练再取20条、验证取20条，先做采集/回放器校准，不额外污染封存测试。

先用该规模验证趋势，若任务间收益不稳定再扩大到剩余独立训练数据。不要一开始为每个容量各跑完整740条。

## 4. 阶段B：补齐长度与对话变化

新增样本必须先确定家族及划分，再生成长度变体，不能让同题短版进训练、长版进测试。

- 初始补充目标：每Scope/语言各2条独立长任务，共40条，原始上下文达到约2048 tokens；另选独立任务组成约4096-token与话题切换验证组。
- 内容来自可追溯、允许使用的本地材料、代码或人工构造任务；保留出处及生成方式，不使用私有用户对话作为默认采样源。
- 覆盖文档问答、代码阅读/修改、数学推导、长篇写作与多轮主题转换；禁止只重复一段短提示凑长度。
- 允许同一长任务派生不同长度版本，但同一家族不重复加大统计权重。
- 核心输入区间：短输入自然长度、2048、4096附近；记录精确token数，不截断到破坏消息或题目语义。
- 首轮训练采样以128步Decode为主；选分层代表子集跑512步，并在验证/测试中保留长Decode。将前128步、后续384步分别统计，避免短期初始化主导结论。
- 多轮同时覆盖延续同主题与明显换题。先做固定历史独立回放验证语义，再用持续会话验证缓存保持；两类结果分开标记。

第一版不承诺64K等超长上下文适用性。补充用例准备不足时，应将结论明确限制为已覆盖长度，不用Scope标签替代长度覆盖。

## 5. 阶段C：低开销路由采集

新增独立采样工具，复用DS4.1原runner与官方chat编码。默认只收集轻量路由，不保存所有层hidden states或全量attention张量。

每个样本记录：
- checkpoint manifest/source index、源码SHA、Python/MLX/native版本、精确配置。
- Prefill每层专家IDs及频次；Decode每步每层Top6 IDs、token IDs、步号与轮次边界。
- **初始**Main名单和Hot状态，Prefill→Decode交接状态；动态L1频次初始化规则。
- cache hit/miss、全命中layer-step、promotions、淘汰、逻辑读取bytes、native I/O计时。
- 带时间的forward/Prefill/Decode总计，采样physical footprint和MLX峰值。

Decode路由采用紧凑uint16：128步×40层×6×2=61,440 bytes/样本；512步约245,760 bytes。2048输入的完整Top6 Prefill路由约983,040 bytes/样本，量级可控。只在精度校准子集保存完整logits；其他用例保存输出、摘要和有限诊断信息，避免再次生成数十GB trace。

采集按固定步数有界暂存、在已有step边界排出，避免给每层新增`.tolist()`同步。采样运行的TPS不作为正常性能成绩。报告采集开销与自身驻留内存。

现有`profile_frozen_cache.py`只作参考：它以运行结束的Main名单计算Prefill覆盖率，不能将这个统计当成初始Main，也不能用最终状态“倒推”在线命中；新采集器必须明确保存状态发生时间。

## 6. 阶段D：因果回放及容量收益曲线

为每条已采样路由，离线模拟每层容量32/36/40/44/48，复用同一套明确的动态L1/Hot8规则。

- 初始化只使用该请求已完成的Prefill；Decode第t步决策只能用<=t的已知信息，并遵守实际晋升发生在前向前/后的顺序。
- 精确复现frequency prior、16步晋升时点、衰减、迟滞、tie规则、Hot recency、晋升后旧映射移除和Prefill交接。
- 禁止用未来Decode频次选择初始专家；离线全程最优解若计算，只能标成oracle上界，不进入候选配置。
- 分别计算路由miss、含miss的layer-step、Hot命中、晋升额外读取、冷加载成本；一次晋升不等于只消除一次miss。
- 推理路由的可重放性先用小样本实测校准：对20条分层校准样本，在32/40/48运行真实引擎，检查回放的逐步cache事件与真实记录完全一致。未对齐则暂停分配拟合，先修模拟器。
- 数值差异可能改变后续路由。若实际容量变化导致路由不同，记录分歧并重采实际路径，不能继续把固定路由回放称为精确端到端结果。

回放同时保留静态频次覆盖曲线作解释，但容量拟合以完整动态策略的有效收益为准。

## 7. 阶段E：初始形状求解

训练集合按任务/语言宏平均；同一家族及长任务的多个变体先在家族内平均，避免长生成或大量近重复样本主导结果。

对每层得到5个容量对应的代价：
- 主指标：每token实际专家加载数，包含晋升代价。
- 辅指标：每token含miss的layer-step数量；相同miss数可能产生不同的主机处理次数。
- 同时记录各任务分组的收益/回退和采样不确定性。

先求两个有限候选：
1. 按加载数最小化。
2. 在加载数接近的情况下，优先减少含miss的layer-step并降低任务间最差回退。

不能直接把native I/O与GPU时间相加作为精确延迟模型。若采用时间加权，权重只由训练校准样本的实测拟合，并在验证集检查预测排序是否成立。

每层先32槽，剩余320槽，即80份“4槽增量”。用多选背包/动态规划枚举40层各5种容量，强制总数1600。不能默认边际收益单调并直接贪心：Hot/L1交互可能产生非单调曲线。收益相近时优先靠近均匀40，减少对噪声的响应。

输出 `l1-shape.candidate.json`：
- schema版本、family、checkpoint与数据清单SHA。
- 完整40项容量向量，逐项范围/步长检查及sum=1600。
- hot_slots=8、动态晋升策略版本、拟合指标、适用任务/长度范围。
- 每层容量选择理由、验证集宏平均/最差组变化。
- 不包含从测试集生成的专家名单，不包含“提前知道未来路由”的数据。

样例schema只给字段，不先编造40项“最优”数字。候选文件在训练完成后生成；本次方案不产出假配置。

## 8. 阶段F：静态异构容量接入

第一阶段只在模型加载时按向量创建各层bank，一个会话运行过程中容量固定。无需先实现机动池。

需要检查的当前假设：
- `model.py`的标量main_slots、初始专家选择、L1/L0计数边界及lookup。
- `adaptive.py`的victim选择、promotion、Hot映射和安全覆写。
- `metal_bank.py`/`lru_metal_bank.py`的每层容量、连续数组和I/O长度。
- runner manifest、预算采样和错误输出；其他继承Model的Burst/vision路径。

标量`--main-slots 40`继续工作；新形状入口明确互斥或定义唯一优先级。缺层、多层、未知schema、非32～48范围、总预算错误、checkpoint不匹配均应拒绝，不能静默补默认值。默认不启用未经验收的shape。

仅将该变更对纯文本Natural路径验收；不自动声称Burst/vision/多轮服务化兼容。逐层数据仍为原六段专家记录，继续调用既有native loader，不改兄弟DMoE。

## 9. 阶段G：独立验收与采用门槛

基线：均匀32（解释用）、均匀40（同预算主对照）、均匀48（更大预算参考）；最终同预算候选最多两个，验证集选定后冻结一个进入封存测试。

### 精度

- 分层代表集、长上下文/长Decode及对话边界保存完整logits，默认以逐值一致为优先验收。
- 如出现用户已接受范围内的微小浮点差异，必须报告最大误差、Top1/Top10、生成与路由变化；不得事后提高容差掩盖漏专家。
- 任何错误专家ID、漏路由、错误权重或状态回滚问题一律不通过。
- 不要求两种容量cache计数相同，但要求各自真实计数与因果回放一致。

### 性能与内存（建议门槛，执行前固定）

- 相同总1600 Main槽、Hot8、完整Top6、相同模型/输入/生成预算和缓存策略。
- 自然运行计时，关闭采样额外回调；AB/BA或随机化交错顺序，每个代表用例至少2轮。
- 主报告：每任务宏平均Decode、尾段Decode、Prefill、TTFT、miss、全命中layer-step、维护开销、cold启动和内存；不只展示最好样本。
- 候选在封存测试的宏平均Decode目标>=3%提升，Prefill整体回退不超过3%；任务分组不应出现稳定>5%回退。以按任务家族bootstrap区间辅助判断，样本不足/区间跨零则不宣称稳定收益。
- 对>5%单样本回退做复测和原因分析，不能让均值掩盖明显退化。
- 65GB physical footprint门槛；记录allocation重排/临时峰值，不能只比较稳态bank大小。
- 文件缓存允许与F_NOCACHE结果分开。至少用代表子集复核冷I/O条件，不能把page-cache收益当物理SSD收益。
- 性能测试期间按已有流程暂停本任务上传并保证finally恢复；不停止其他用户App、不全局清系统缓存。

若验证失败，保留均匀40，并交付负面结果、可复用trace和收益曲线。测试集失败后如再调参，需建立新的独立测试集，不能反复调到同一测试集通过。

## 10. 机动L1：第二阶段，先离线模拟再改内存架构

逻辑配额可设每层保底32+全局320机动槽，每层最多借16；Hot8独立。借给某层的槽保存该层自己的专家，不是让不同层共享专家权重。

当前每层独立定长MLX数组，修改计数器不等于释放物理空间。真正跨层借还需要共享slab/分块bank及新的slot映射；不能每层预分配48然后宣称只用了平均40的预算，也不能频繁复制完整bank。

先在同一trace上模拟在线借还：
- 只用历史窗口估算“多4槽能减少多少miss”，扣除装载/淘汰/迁移开销。
- 建议以64-token窗口、每次4槽为起点，设置最短持有期、收益迟滞、每窗口最大调拨量；这些是候选参数，必须在训练/验证阶段确定。
- 削减某层前检查其近期边际收益，不以miss最低直接判定可回收。
- 无足够收益时保持原分配；轮次/主题变化时衰减旧历史。

真实共享池接入必须包含：`(layer_id, expert_id, generation)`身份、空闲/读取/就绪/使用/退休状态、GPU消费者完成后的覆写许可、取消/异常处理、总槽位和临时分配限制。实际kernel需支持新增映射，不能删除现有同步来假装加速。

机动L1与预测L2分开计账：前者管理持久容量，后者预取下一步可能需要的专家。不得复用同一槽位的预算同时承诺给两种策略。只有静态形状证明确有同预算价值后，再评估两者组合。

## 11. 实施顺序、成本与交付

| 阶段 | 主要交付 | 继续条件 |
|---|---|---|
| A/B | 去重/家族/长度清单、冻结split、长输入补充计划 | 无已知跨split家族泄漏 |
| C | 轻量route trace、采集开销与存储报告 | 不改变推理结果、不新增逐层同步 |
| D | 五档容量回放器、20条真实校准 | 事件逐步一致 |
| E | 训练曲线、最多两个shape候选 | 只用train拟合、validation筛选 |
| F | 每层容量加载、向量校验、标量回退 | 精度/65GB预算通过 |
| G | 冻结测试集A/B、完整结果报告 | 达到预先固定的采用门槛 |
| 第二阶段 | 机动池在线模拟及实现设计 | 静态形状有可靠收益 |

先跑20条pilot测实际每样本加载/Prefill/Decode耗时，再推算全批成本。按当前约7～9TPS，仅128步Decode约14～18秒/样本；740条约3～4小时是**纯Decode粗估**，不含模型加载、Prefill、数据准备、校验和512步子集，不作为完工承诺。优先一次采集、五档离线回放，避免五倍完整推理。

产物目录建议 `artifacts/dsv41-l1-shape-<run-date>/`，按dataset/trace/replay/candidate/validation/test分目录；控制大logits仅用于精度子集，默认不保存hidden states。模型权重零复制，不为采样重新下载checkpoint。

本方案不包含Runtime签名发布、模型Package升级或修改checkpoint。实际实现开始时同步更新Desktop release ledger；本轮仅方案文档。
