# AI2Apps Mini-App Chat Architecture

## Decision

`ai2apps.mini-app-chat/v1` is the conversational-control contract between one selected Studio Mini-App and
one Chat-Mini-Entry. The Mini-App provides a system prompt, a bounded snapshot of its current state, a lazy
`help.md` resource, and an explicit list of operations represented as model function Tools.

Mini-App Chat is an optional, recommended capability, not part of the minimum Mini-App validity contract.
A Help-only implementation may expose `help.md` with zero operation Tools; a Chat-control implementation
adds live state and operations. A Mini-App that declares neither remains installable and runnable, and Studio
does not show its Chat entry.

The model never receives a general DOM, JavaScript, HTTP, filesystem, or browser execution Tool. A model Tool
call returns to the owning Studio, which resolves it against the currently selected Mini-App and executes a
registered handler. Existing Capability Broker and WebDriver BiDi boundaries remain unchanged.

## Runtime flow

```text
Selected Mini-App
  -> capability declaration (`chat.enabled`)
  -> Studio shows Chat tab
  -> Chat-Mini-Entry requests live contract over channel-bound postMessage
  -> model receives system prompt + current state + declared function Tools (but not help.md)
  -> model calls reserved `read_mini_app_help` Tool only for usage/help questions
  -> Studio loads the current Mini-App's bounded help.md and returns it as a Tool result
  -> model emits Tool call
  -> Studio rechecks Mini-App + Tool + arguments (+ user confirmation when required)
  -> Mini-App handler updates the draft or starts the operation
  -> Chat receives result and a fresh state snapshot
```

The channel identifier is generated by the Studio and placed only in the Chat iframe fragment. Messages are
accepted only from the same origin and the bound iframe window. A child that does not know the channel cannot
query state or invoke Tools.

## Contract

The live object contains `schema`, `enabled`, current `miniApp` identity, `systemPrompt`, bounded JSON
`context`, a small `help` availability descriptor, and `tools` with a name, description, JSON input schema,
and confirmation policy. The signed
Package declaration uses snake_case while the live JavaScript bridge uses camelCase.

Package Entries serve the live half of the contract through two messages exchanged only with their parent
Studio frame:

- `ai2apps.mini-app-chat.provider-request`, method `context`, returns the current JSON snapshot;
- `ai2apps.mini-app-chat.provider-request`, method `help`, returns the declared `help.md` on demand;
- `ai2apps.mini-app-chat.provider-request`, method `invoke`, receives the declared Tool name and arguments;
- `ai2apps.mini-app-chat.provider-response` returns the matching channel and request ID.

Host-authored Mini-Apps can use `AI2AppsMiniAppChat.registerPackageProvider({context, help, invoke})`; packaged
Entries may implement the same small message contract in their signed JavaScript. Studio binds responses to
the exact mounted iframe window and accepts opaque `null` origins only for that already bound sandbox frame.

## Safety rules

- Context is untrusted model input and conveys no authority.
- Help text is not part of the normal prompt. The reserved `read_mini_app_help` Tool has no path argument,
  and the host accepts only the help resource bound to the current Mini-App. Help is Markdown and at most
  32 KiB.
- Tool names are a signed or host-owned allowlist; arbitrary method names fail closed.
- Tool handlers validate arguments against current state and domain constraints again.
- Operations that create work, publish, export, overwrite, spend Cloud points, or otherwise have material
  effects use `confirmation: always` unless an existing product-specific approval flow is stricter.
- Capability-requiring handlers continue through the Capability Broker.
- Browser work continues through authenticated, mount-bound WebDriver BiDi sessions; this protocol does not
  add a browser automation API.
- A Mini-App switch invalidates the previous live context. Chat requests the new contract before its next turn.

## Initial coverage

Video Studio, Read Aloud, and Imagine Studio expose Chat and a dedicated `help.md` for every built-in Mini-App. Their initial common
Tools update the visible draft and run the current operation. A Package Mini-App shows Chat only when its
signed declaration opts in; its constrained Entry then supplies live Context and handles allowlisted calls
through the provider bridge.
