# DS4.1F 四段小模型 L2 预测方案

日期：2026-09-17。状态：第一轮离线训练已完成，尚未接入在线推理或独立验收；结果见 `docs/dsv41f-l2-four-stage-predictor-results-2026-09-17.md`。

本文记录四段小模型预测的设计，供主任务后续评估；不代表已启动训练、修改推理默认值或替换当前实验。所有层编号统一为 **0～39**，以下范围均包含两端。

## 1. 目标与假设

用少量小模型计算，分阶段预测未来层的专家分数；利用真实推理过程中的新状态更新预测，并为 SSD 预取保留足够提前量。

希望探索是否能以明显低于 Block6 近似前向的预测成本，获得有实际 TPS 收益的及时 miss 覆盖。讨论中的“接近50%”是待验证假设，不是已有结果；必须说明它指 Top6 召回、目标层 miss 覆盖还是全部40层及时 miss 覆盖，不能混用。

与已有路线的区别：

- 全局小模型：在 token 开始时一次预测全部层，后续不利用该 token 的真实中间状态。
- 相邻层 rank64：从当前层预测下一层，信息较新，但 SSD 提前量很短。
- Block6：执行额外近似前向产生预测，成本较高。
- 本方案：一次预测一段未来层，共四次；后三段使用当前 token 已经计算出的真实状态，最短提前约5层。

## 2. 四段触发与目标

| 段 | 触发时机 | 预测／预取目标 | 说明 |
|---|---|---|---|
| A3 | 上一 token 前向结束，采样确定下一 token 后 | 下一 token 第3～9层 | 第一段起点候选A |
| A5 | 同上 | 下一 token 第5～9层 | 第一段起点候选B，与A3二选一 |
| B | 当前 token 第5层状态可用时 | 当前 token 第10～19层 | 距离5～14层 |
| C | 当前 token 第15层状态可用时 | 当前 token 第20～29层 | 距离5～14层 |
| D | 当前 token 第25层状态可用时 | 当前 token 第30～39层 | 距离5～14层 |

“第5/15/25层状态可用”初始定义为：该层 Attention 完成、FFN/MoE 输入归一化向量已产生、该层 MoE 尚未计算。实现和日志必须使用同一定义，不能把整层结束后的状态与这个触发点混为一谈。

第一段主动跳过第0～2层或第0～4层的 L2 预取；这些层仍正常执行，依靠 L0/L1 和原前台 SSD miss 路径，不跳过任何专家计算。A3/A5用于比较覆盖范围与加载提前量的取舍。

首次 Prefill 后也可用其末位置状态及采样 token 触发第一段。若输入特征不可用，必须记录跳过原因，不得偷偷补一次完整前向。

## 3. 预测输入与模型形状

第一段的候选输入：

- 上一次前向的最终 hidden；
- 已采样确定的下一 token embedding；
- 上一 token 对应目标层的 FFN 输入状态（若选择使用，需计入保留状态开销）；
- 当前缓存状态或训练时使用的缓存特征。

后三段的候选输入：

- 触发层当前 token 的真实 FFN 输入；
- 当前 token embedding；
- 上一 token 的最终 hidden，以及目标层历史状态的可选分支；
- 段／目标层位置参数及缓存特征。

输入全部必须在触发时已经可用。当前 token 目标层的真实状态和路由只用于训练标签或事后验证，不能进入在线预测。

初始模型直接输出每个目标层的384个专家分数：A3为7×384，A5为5×384，B/C/D各10×384。采用输入投影、GELU或残差 MLP、目标层输出头；不要求执行目标层的 Attention/MoE。

先比较独立分段头和共享输入投影的方案。共享 token／历史特征投影可在多个段间复用；只有新增的真实触发状态需要在段到达时计算。段内使用共享瓶颈和目标层输出头即可，不预先限定为每层一套完整网络。

容量实验先固定输入与数据，比较浅层结构、增加1个残差块、增加3个残差块；再决定是否调整宽度。报告参数量、实际权重字节、状态保留字节、GPU预测耗时，不能只用“rank小”推断总成本低。

第一段依赖采样 token：与 token 无关的投影可在采样前准备，其余计算在采样后完成。不等待客户端收到或显示 token 才启动预取；也不额外阻塞 token 输出以人为制造提前量。

## 4. 训练与离线评估

1. 从精确主前向采集触发点状态、各目标层真实 Router 分数／Top6、原始缓存标签、会话与 token 标识。尽量复用已有数据；先核验特征和 token 对齐，再决定补采哪些字段。
2. 按会话及主题族隔离训练和验证，不能将相邻 token 随机分到不同集合。已经消费的独立验收集不能重新用于候选选择或宣称新的独立验收。
3. 标签覆盖目标层全部专家的 Top6 归属；可以提高未缓存专家的损失权重，但同时报告不依赖缓存的预测质量。
4. 固定每层预测Top6，统计每层平均猜中几个、Recall@6及其与预测距离的关系，排除读取预算分配的干扰。
5. 再加入缓存过滤及全 token 预算，比较 miss 覆盖、每次预读的有用比例和误读字节。
6. 比较训练／验证曲线和至少两个随机种子，判断加深是否改善泛化，还是仅拟合训练数据。

无损主前向是初始训练数据来源。Burst下的状态分布可能不同，应单独验证；若需补充Burst训练数据，保持会话族隔离并标记模式，不能默认无损模型在Burst下一样有效。

## 5. L2 调度与 SSD 重叠

初始沿用 L0=8、L1=40、动态L1策略及65GB纯文本峰值限制。L2沿用有界物理暂存槽作为起点，额外权重、状态、工作区必须全部纳入内存测量。

全 token 实际预取总预算以48为主、64为对照，**不是每个段各48/64**。各段共享总预算；可在训练／验证数据上制定分段保留预算，避免早段耗尽额度。取消且尚未开始读取的请求可以回收额度，已经开始或完成的读取仍计入本 token 成本。

过滤已在 L0/L1 或已被本 token 预取的专家，按置信度、层截止时间和分段预算排序。优先保障前台缺失加载；过期排队请求取消。记录每次请求的生成、通知、排队、开始读取、读取完成、GPU可见及消费时刻。

L2 READY必须在安全发布后进入GPU可见的命中查找。不能重复旧实验的局限：专家虽然提前读好，正式推理仍按L0/L1 miss逐层返回CPU再消费。

首次实现可在已有安全边界发布READY快照，明确测量这一方式造成的可见性延迟。若探索运行中发布，需先建立资源生命周期和数据可见性协议，禁止GPU读取未完成的专家槽，禁止覆盖仍被GPU引用的槽。

统计预测通知与正式推理回读的总次数；四段通知也必须计入，不能把“异步”当成没有GPU→CPU事件。不得额外加入逐层等待来方便采集。

## 6. 在线实验矩阵

先在小规模开发会话完成正确性与计数验证，再扩大性能样本。比较对象至少包括：无L2、全局小模型、相邻层rank64、Block6及本四段方案。

对四段方案测试A3/A5、预算48/64；推理模式包含无损Top6、Burst Top2、Burst Top4，并对比逐层packet与显式跨层guarded/window路径。默认auto目前不等价于跨层推进，报告必须记录实际执行器、实际跨层长度和回退次数。

先选择少量有代表性的开发会话筛选，避免一开始展开所有组合。最终候选冻结后，另取未用于选择的新会话做独立验证。

无损路径应检查完整logits、生成token和状态一致性。Burst是有损模式，需固定尾部策略，并明确L2是否改变可执行的可选尾部专家；若改变，不能要求与无L2 Burst逐字相同，也不能把质量变化误认为执行器错误。进行执行器对照时，固定预测／缓存策略；进行成本对照时，可采用相同输入token回放，并与自然生成结果分开报告。回放token不能作为提前获得未来真实路由的来源。

## 7. 必须报告的指标

| 指标 | 口径 |
|---|---|
| Top6预测质量 | 每层固定预测6个，与真实Top6交集；不受缓存预算影响 |
| 目标层miss覆盖 | 单独列出，不能替代整体覆盖 |
| 全部40层及时miss覆盖 | 原有全部40层真实miss为分母，包含主动跳过的前几层 |
| 晚到读取 | 单列，不能并入及时READY |
| 误读和总SSD读取 | 专家数、MB/token、与无L2配对基线差值 |
| GPU→CPU开销 | 回读、通知、等待次数及时间，说明测量范围 |
| 连续GPU推进 | 实际连续层数分布、窗口失败和恢复成本 |
| 预测开销 | 每段和每token耗时，投影复用情况 |
| 内存 | 权重、L2槽、保留状态与总峰值，不只统计MLX分配器 |
| 最终速度 | 配对TPS、首token／暖态口径、重复运行波动 |

覆盖率分母还需匹配模式：无损统计Top6真实miss；Burst另列必须TopN miss，并保留完整Top6统计供理解。不能把Top2模式下的较小分母与无损Top6的百分比直接比较。

SSD读取区间与GPU执行区间应使用可对齐的时间线分析；“读取完成早于消费”只证明及时，不证明读取时间全部隐藏在正式GPU计算内。区分正式计算、预测计算、CPU调度和等待。带详细profile的诊断运行与低开销TPS运行分开。

## 8. 推进顺序与判定

1. 核验可复用训练数据，补齐四个触发点的因果特征，冻结训练／验证划分。
2. 训练浅层分段基线，再做残差深度对照，确定A3/A5与候选容量。
3. 接入有界L2调度和GPU可见READY；先通过精度、内存、资源安全与同步计数检查。
4. 跑无损／Top2／Top4的逐层与跨层对照，同时诊断SSD重叠与发布延迟。
5. 只有实际TPS有可重复收益，才考虑作为部署候选；候选冻结后使用新的独立会话验收。

如果预测质量改善但TPS没有收益，先检查预测成本、READY发布延迟和逐层同步残留；如果加深只改善训练集，优先检查数据覆盖与输入信息。若及时覆盖低于50%但实际TPS更好，也应如实保留结果，不能为了单一覆盖率数字放弃更有效的方案。

本文件只定义探索方案。当前不承诺50%覆盖，不改变原70.31%实验的结论，不替代生产Runtime、Package或视觉路径的验收。
