# DS4.1 Flash 可选预测 L2 外挂

状态：设计记录，尚未实现预测器训练或异步 L2。当前运行默认仍为动态
Main40/Hot8；冻结 v1 不变。用户明确不采用固定全量驻留层。

## 功能边界

外挂仅预测和预取下一轮专家，不生成草稿 token、不跳过主模型层、不改变
Router 或专家权重。关闭时不创建预测器/L2、不启动预取线程、不采集预测特征。
开关与动态 L1、未来 MTP 相互独立。

初始方案跳过前 5 层的预测预取：0..4 层正常执行，L2 从 layer_id=5 开始
覆盖。这是从第六个物理层开始；所有层号沿用当前代码的从 0 编号约定。

## 跨 token 调度

1. 当前轮结束，保留 head 前归一化后的最后 token 隐状态 h_t（5120 维）。
2. 真实生成 token_{t+1} 确定后，使用 [h_t, embedding(token_{t+1})] 预测
   下一轮各层专家入选概率。预测器只运行一次；其延迟单独计入总耗时。
3. 查询当前 L1/L0 tags，过滤已驻留专家。按目标层到达时限、概率和读取成本
   组织队列；临近需求读优先于远期投机读，限制并发与总读取量。
4. 下一轮 GPU 正常计算层 0..4；后台通过 native preadv 读层 5 起的候选。
5. 实际 Router 到达某层后选择原始 Top-6。L1/L0 已有的正常使用；缺失且
   L2 READY 的使用预取字节；其余沿用准确同步补读。恢复原有专家汇总顺序。
6. 已完成 GPU 消费的 L2 块回收，滚动为更后面的层加载。下一轮预测发生前
   取消过期排队任务；进行中的读取必须完成/确认退出后才能复用其目标内存。

不能将“预取线程已提交”视为命中。命中需要 key、generation、完整读取与
GPU 可见性同时有效。Prefill 后也可预测第一步 Decode；EOS 停止时取消后续
任务，不为已结束的请求继续预取。

## L2 容量

L1 管较长期热点，L0 管实际 miss 的短期热项，L2 管尚未到达层的投机候选。
L2 不遵循 L1/L0 的包含关系，也不直接把预测候选晋升到 L1。

一个原始专家记录 18,800,640 bytes，容量按专家槽位而不是完整层权重计算：

| 方案 | 槽位 | 原始 payload |
| --- | ---: | ---: |
| 4 个未来层，每层最多 6 个候选 | 24 | 451.2 MB |
| 上述读/算双缓冲总量 | 48 | 902.4 MB |
| 4 个未来层，每层最多 8 个候选，双缓冲 | 64 | 1,203.2 MB |

第一版建议 24 槽/组 × 2 组，上限约 0.90 GB 原始 payload。实际只预取过滤
L1/L0 后的候选；“4 层窗口”是初始调度设置，不保证每层都存在 6 个 miss。
预测器、allocator、I/O 临时数据也计入 65 GB physical-footprint 预算。
目前约 54.9 GB 的峰值只用于容量规划；加入外挂后的峰值必须重新测量。

## 安全异步读取

当前 MetalBank._load 先 mx.eval(pending)，再全局 mx.synchronize，最后
调用原 GLM native loader。直接在线程中调用它不能证明实现了并行。

新 L2 使用独立、预分配且已 materialize 的缓冲；后台复用原始 native
preadv 实现，不在工作线程执行 MLX 图计算。槽位/缓冲生命周期：

`FREE → READING → READY → IN_USE → RETIRED → FREE`

- READING 与 IN_USE 的内存绝不能互相覆盖；初版按独立层缓冲隔离，不能仅凭
  槽位不同就假设同一 MLX 数组允许 CPU/GPU 并发访问。
- 完整字节数校验与读取成功后，主线程才能发布 READY tags。
- GPU 消费完成后主线程确认退休；Python 函数返回、lazy tensor 创建或
  token generation 变化都不是消费完成证据。
- 优先利用现有逐层结果 materialization 的完成边界；若无法证明 buffer
  已释放，则延后复用或安全等待，不能直接移除原有同步保护。
- 取消/异常/关闭时先停止提交、等待 in-flight I/O、回收 GPU 使用中的缓冲，
  最后关闭 fd 和释放内存。失败缓冲不发布为 READY。
- 动态 L1 晋升期间可能出现重复任务，采用 (request, generation, layer,
  expert) 标识并在发布/消费前重新查询驻留映射，不能依赖早先槽号。

L2 数据如何接入 GPU 专家算子需要比较：直接按 bank 分组执行，或提交到
安全的 Hot 槽。直接执行可以避免一次拷贝，但必须保留各专家原始汇总次序。

## 预测器与训练

先做 rank=128 的低秩预测头，输出 40×384 入选概率。共享原 token embedding，
不新增大词表。输入两个 5120 向量时，矩阵约 328 万参数、BF16 6.6 MB。
保留后续增加逐层状态摘要的空间，不将最后状态视为完整 KV/Engram 状态。

监督对齐：[h_t, 真实 token_{t+1}] → forward(t+1) 各层真实专家。
优先训练 Top-6 多标签预测，可用带 correction bias 的排序分数辅助；不能
把不含 bias 的贡献权重直接当作专家选择分布。按独立文档/会话划分数据，
不能随机拆分相邻 token。当前重复 benchmark 不足以训练/验收通用预测器。

## 开关与验收

拟定接口（尚未实现）：`--predictive-l2 off|on`、`--predictor PATH`、
`--l2-start-layer 5`、`--l2-window-layers 4`、`--l2-slots 48`。
关闭为初始默认，打开需要匹配模型/层数/专家数的 predictor manifest。

先用 recorded-route oracle 离线回放测窗口和容量收益上限，明确标记 oracle；
再训练小模型测 held-out miss 覆盖与误读率；最后接入异步 I/O。实际预取运行
不得读取当前任务未来真实路由。

验收记录：缺失专家提前 READY 的覆盖率、deadline miss、无效预取字节、
前台同步等待、SSD 并发、预测耗时、L2 GPU 等待、内存与端到端 TPS。
保持关闭/开启的路由、生成 ID 和 logits 对照，不以命中率替代实际加速。
