# Bot 委派任务的记忆回传 v1

2026-11-04；接续 [记忆与历史总体方案](bot-memory-and-history-plan-v1.md)、[自动记忆方案](bot-memory-automatic-v1.md)。本机制属于 Messager owner，不向 General Agent 添加 Bot 业务规则。

## 目标与语义

子 Bot 执行任务时获得的有用信息，可以返回给直接上级作为**待审阅的记忆候选**。任务结果正常返回，不等待记忆保存；上级用户确认后，候选进入现有独立记忆维护 Task，在当前业务任务结束后整理。同一 Bot 的聊天继续可用，维护不抢占正在执行或等待审批的任务。

这里不复制子 Bot 的整个记忆库，也不把上级/子级身份职责、私人历史、App Access、审批或调度权限带到另一 Bot。父子仍是相同用户、相同本机安装下经过审阅的委派关系。子任务发现属于任务观察，不据此宣称已核实用户身份。v1 采用上级用户审阅，尚未开放无人审阅的自动接受策略。

## 回传协议与证据

新增 owner AaAT `messager.memory.return`，只有真实、当前、有效的委派子任务 Run 能使用。父任务、普通聊天、伪造 Run、其他用户或其他 Bot 不能借此导入记忆。声明随 Provider 复核，执行沿用冻结授权、委派交集、预算、取消与版本检查。

每次 1–3 条，每条包含字段 subject/predicate/variant、类型、展示文本、值和证据。每条委派边最多 6 条。允许三种证据：

1. `tool_step`：本次 Run 已完成的业务 Tool 结果，提供真实 step ID，或能唯一匹配引用结果的 Tool 名及原文 quote。事实值及保存文本保留原文；资源 artifact ID 必须真实出现在结果且归本 Session 所有。记忆控制、Agent 控制、App 发现收据不能充当业务发现。
2. `memory_change`：子 Bot 当前生效的结构化记忆变更，证据必须是真实用户输入，且已由宿主导入本次任务，或明确绑定本逻辑 Task。普通私人便签和继承记录不能重新包装成新来源。
3. `return`：中间 Bot 显式继续回传用户已接受的候选。字段、值、最初来源保持不变，必须属于当前逻辑 Task 和同一个委派 root；中间记录已经保存时，其记忆版本也必须仍有效；已经审阅、正在等待维护的候选可保留其批准凭据继续回传，避免等待当前业务任务结束形成相互等待。上级仍需独立审阅。

宿主只在子任务成功完成后投递候选。失败、取消、过期、不确定执行不投递，不自动重跑业务工具。候选存储于 `messager_memory_returns`，记录直接父子、委派边、子任务、Run、源 epoch、目标 epoch、原始证据及路径。稳定 origin key 去重，同一来源经重试/恢复不重复创建记忆。路径最多 4 个 Bot，禁止同 Bot 重复、跨 root 转发及自动广播。

## 上级交互与合并

投递后在上级信息流给出“子 Bot 回传记忆候选，尚未保存”的稳定提示，附现有查看/取消入口。“待整理记忆”展示来源 Bot、任务、原文证据、用途和传递路径；用户确认记住或取消。普通字段冲突仍需明确确认新值，候选不得直接覆盖旧记忆。

确认仅将候选置为 queued。现有 managed Todo 维护 Task 处理候选，没有额外模型调用；使用原有同值/同图合并、版本和 CAS 保护。原子保存记忆、证据、回执与候选完成状态，信息流可查看变更及撤销。资源仅确认后按实际字节复制到上级自己的 Session，限制 16 MiB；引用不赋予任意 Session 或文件访问权。

委派业务交付与记忆投影独立。投影暂时失败时记录日志、由持久恢复重试通知/入队；不因记忆 UI/队列已满重跑子任务。队列沿用 24 条待处理上限及固定批次、公平性规则。

## 撤回与上下文

候选在确认、复制资源及最终提交时重新检查来源和 epoch。源清理、记忆变更/撤销、Bot 停用、资源失效及委派取消会阻止待处理候选保存；已保存的继承记录若只依赖失效来源，不再进入新上下文、索引或任务资源水合。后来由用户独立确认的证据保留，不用源撤回来覆盖上级后续编辑。

撤销保存采用原有变更回执。取消/撤销后稳定来源不能再次投递，恢复只重建投影，不复活旧候选。传递链保留原始来源，中间记忆版本改变会使其后续转发失效。任务已执行的效果与冻结的授权/记忆快照不会被偷偷重写。

## 边界与后续

本次实现不改图片展示组件、共享 Agentic、Cloud 或 Package 协议。回传是可核验的显式 owner 调用，是否提出有用候选由任务模型决定；不会为每条消息增加一次提炼模型调用。后续可加入可审阅的自动接受策略、更多 owner 证据类型和来源查询体验，不能绕过证据与授权边界。

验证使用真实 SQLite/Todo/委派/审批链与确定性模型、业务输出夹具；单独记录 App-Dev 加载核验，不把夹具结果描述为真实模型质量验收。
