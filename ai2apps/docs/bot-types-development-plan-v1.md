# Bot 非标准类型开发计划 v1

2026-11-05。顺序经用户确认：B0 → Flash-Bot → 通用 App-State → ASC-Bot → Outlet-Bot → Mirror-Bot。类型语义继承 [Messager 设计](messager-ui-and-bot-task-v2.md) 的快捷 Bot、外部代理和跨实例映射章节。

## 分类合同

持久定义采用三个正交维度：`execution_mode=agent|flash|app_shortcut`、`audience=owner|outlet`、`location=local|mirror`。创建菜单中的标准、Flash、ASC、Outlet、Mirror 是预设组合，不是五种互斥的底层执行器。Outlet 可以在后续采用 Agent 或 Flash；Mirror 的真实执行权在来源实例，不能根据本地预设擅自执行。

类型不由名字、头像、职责或模型推断。身份、配置版本、来源身份和授权分别保存；类型配置不携带凭据，不授予 App/Bot Access。每种类型只有在输入、执行及授权合同完成后才允许创建，预留菜单项不表示可执行。

## 分阶段范围与交付

| 阶段 | 工作范围 | 验收出口 |
| --- | --- | --- |
| B0 类型基础 | 版本化定义、三个维度、类型目录、可用状态、入口/输入行为元数据；原子创建和目录投影；沿用现有 Desktop/Mobile 创建菜单 | 标准 Bot 行为不变；其它预设仍灰显；非开放类型、未知版本与任意配置被服务端拒绝；默认/直接/配置创建一致 |
| B1 Flash-Bot | 输入 schema/pattern、受信任代码验证器、版本化固定工作流、模板选择与类型专属输入界面；接入原系统 Task、串行 lane、取消、权限和结果回流 | 先安全表达式计算，再发票提取归档；无效输入不创建 Task，重复请求不重复执行，配置更新不改变已准入 Task |
| B2 通用 App-State | App/Mini-App 声明可导出字段、整体 validate/apply、schema 版本、跨端参数映射、敏感字段排除；先小范围接入再逐步推广 | 至少一个 App/Mini-App 在 Desktop/Mobile 恢复同一预设；失效参数明确反馈；未保存编辑不被静默覆盖 |
| B3 ASC-Bot | 基于 App-State 保存快捷 Bot、点击打开目标并恢复预设、输入就绪策略、缺失依赖的 ACPF 回接 | 风格转换案例：吉卜力、指定模型、比例、质量；当前端不支持/宿主离线清晰说明；不重复提交 |
| B4 Outlet-Bot | 已验证的外部消息信封、渠道绑定、去重、对外披露策略、给主人汇报、内部操作权限边界 | 先一个 API 渠道；外部身份不能批准内部权限；明确收到/发送/送达/执行回执；再扩展其它渠道 |
| B5 Mirror-Bot | 来源实例与 Bot 稳定身份、配对授权、消息/任务/审批映射、离线和撤销、附件范围 | 两个隔离实例验证乱序/重复/断线；源执行权唯一；未知效果不重放；本地不能扩大远端权限 |

B2 不要求一次改造所有 App。先稳定通用合同和参考接入，再逐步扩展；不以某个页面的 DOM/坐标保存替代 App-State。Outlet/Mirror 涉及 Cloud API 时只在本仓库输出交接需求，由 Cloud 项目实施。

## Flash-Bot 的下一批实施拆分

1. **F1 固定工作流准入**：可信宿主工作流注册表，含 ID/version、输入合同、代码验证与执行工厂。Bot 配置仅引用已注册版本及经过校验的有界配置；不接受用户/模型任意代码。标准对话路由不能代替 Flash 的代码输入验证。
2. **F2 系统 Task 执行**：校验成功后冻结工作流版本、配置、输入与授权，建立持久请求去重及原 Task/Run 关联。工作流自行处理有界模型步骤，通用 Agent 不规划或扩展流程。复用既有 Task、Bot lane 和取消机制，不另建私有调度器。
3. **F3 输入和结果 UI**：Desktop/Mobile 复用输入合同；拒绝时给出具体字段原因；成功后明确排队/执行/待确认/结果。附件沿用归属校验，结果沿用消息流和原 App 输出。
4. **F4 参考工作流**：数学表达式采用白名单解析与资源限制，禁止 eval；发票流程使用模型识别后再代码校验、重复材料识别及幂等归档，不把“识别完成”当成“归档成功”。
5. **F5 故障验收**：无效/超限输入、取消、重启、未知结果、权限撤销、版本更新、重复提交；特殊操作确认不能被固定工作流绕过。

先完成 F1–F3 和计算器，再开放 Flash 菜单；发票作为第二条流程验证扩展合同。B0 不提前开放没有执行器的 Flash 创建入口。

## B0 实施记录

- `messager/bot_types.py` 提供 `BotDefinition` v1 和类型目录。三个维度显式建模；当前只接受 `agent/owner/local`，标准类型配置为空且禁止额外字段。未知版本、未开放组合及任意脚本配置拒绝准入。
- 定义保存在 owner 绑定的 `messager_bot_definitions`，与原 Bot 稳定 ID 分离。首次创建 revision=1；当前不开放类型转换或任意配置更新接口，后续需独立 CAS、执行快照及类型转换评审。
- 配置创建在原身份、头像、模型、Access 和幂等回执的同一事务中保存定义；直接创建和默认 Bot 使用相同定义。既有无定义 Bot 只投影为标准类型，不重写权限、任务或用户设置。
- Desktop/Mobile 共用目录列表投影增加 `definition`，提供版本、维度、入口/输入行为。创建 options 增加 `bot_types` 和定义版本。保留现有共享类型菜单，标准可选，其余四项保持灰显；目录元数据不能当作执行授权。
- 本阶段不改 General Agent、AaAT 路由/声明、任务调度、记忆及图片显示，不加入不可运行的空工作流或跨端状态执行器。实际 Flash/ASC/Outlet/Mirror 各自的执行分派在对应阶段接入。

验证：类型定义、配置创建与原 Bot 行为 12 项通过（8.59s）；补充 Mobile 创建返回定义、事务失败回滚定义记录后，最终类型/创建 7 项通过（4.65s）。使用真实 SQLite 和宿主服务、夹具模型，不创建真实业务任务或外发效果。未改共享 Agentic/AaAT 执行、声明、交互或结果策略，因此本轮不重复完整 AaAT gate。

已通过标准 Helper 空闲检查重启固定 App-Dev，核对 App/Helper 源根、Local 的实际 Bot 目录导入路径、类型定义表结构和 served 资源。创建菜单及图片组件未修改；未重建 App、未重启 Dev，未中断活动任务。
