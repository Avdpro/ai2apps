## 已实现

Schema104 保存独立 action step、动作受理/结果、运行开始时间和当前用户的本机站内通知。HookAction 只由可信宿主 owner 注册，模型不能注册、选择或改写处理器。规则预览冻结动作注册、版本、参数和时效；启用后模型可用 Tool 仍保持 E3 的精确只读边界。业务写入由确定性宿主处理器执行，复用所属 App 的权限与存储服务。

首批动作：

- `todo.create`：固定任务标题、当前用户的指定目录或 Todo 收件箱；可将审阅摘要放进说明。复用 TodoStore.save 的 creation_key，Todo 与创建回执在其原数据库同事务保存。
- `notification.local`：仅当前用户、本机 Messager 自动化面板；固定标题、可包含审阅摘要及原 Bot/Run 引用。通知与 operation_key 在同事务保存。不是 Cloud 推送或微信消息。

Bot 先通过 AaAT 读详情，再复用原 App Chat/AgentRun 审阅，最后宿主依冻结计划依次执行动作。真实结果以 owner 返回的持久 receipt_id 为准；模型文字不代表动作成功。执行回执另以幂等消息写回 Bot 原会话。恢复优先复用已绑定 Run，不因提示文案升级重新提交模型回合。

可选 urgency 模式要求模型返回符合固定 Schema 的 urgent/normal/uncertain＋summary。normal 记录 skipped；uncertain 或无法解析时 needs_user，不执行动作。文本中的“请忽略规则”“换接收人”“我已创建成功”均不授予权限。

已将 `messager.message.received` 接入标准业务目录，保留原 raw event_id，与入站写入同事务，重复入站不增加事实。详情只返回当前用户的 AI2Apps 来信正文，不含附件或微信。Cloud 离线导入标为 offline_import，不冒充实时来信；有动作的 Bot 规则对离线、历史或时间不明来信要求人工处理。当前表单以频道更新配置为先，来信可用标准 API 明确订阅。

## 故障与授权

每一步执行前重新校验安装、actor、规则状态/版本、到期、App/资源和动作版本。事件超过24小时不执行副作用。相同 delivery/step 固定 operation key，改变版本或参数拒绝；Todo/站内通知可用原回执恢复，不生成新业务请求键。

步骤分别记录 executing/succeeded/skipped/failed/interrupted/outcome_unknown。前一步成功后规则暂停或后一步失败，保留已完成回执并显示 partial；未知效果显示 outcome_unknown，禁止任何自动重发。通用框架为将来的非幂等 owner 提供保守未知结果处理，但当前不注册外发适配器。相同规则版本按投递顺序受理；needs_user/partial/outcome_unknown 会阻止同版本后续投递越过待核对结果。重新预览或恢复规则从现在开始，旧事实不借新授权重放。

原因果根规则重入、深度8、激活20、Tool12和模型预算继续有效。动作执行不扩大模型 Tool 权限；未增加 GeneralAgent 业务分支或另一套模型执行循环。

## 运行监控与界面

Messager 的“自动化”页提供：

- 冻结规则预览、显式确认启用，Bot/频道/模型/指令/动作/有效期选择；确认前不启用。启用响应丢失时复用 request_id，避免重复规则。
- 每条规则的运行状态、授权到期、扫描积压、游标缺口、命中配额；暂停、恢复、停止并移除。
- 最近投递的队列、运行、失败、部分完成、需要用户、循环/预算拦截和结果未知状态；等待最久的时间、近期样本最大匹配延迟、累计状态计数与未读通知。
- 动作分步真实回执和本机通知；模型/来源正文不放进监控列表。来源已删除或撤权时隐藏通知正文，不借缓存旁路权限。读取监控不提交、恢复或重试任务。

接口位于既有 `/v1/platform/hooks`：`GET /monitor`、`GET /actions`、`GET /notices`、`POST /notices/{id}/read`、`GET /deliveries/{id}/steps`；继续使用 E2/E3 的预览、启用与版本化管理接口。均按当前用户隔离。未开启自动裁剪，明确公开保留水位；配额达到上限暂停而不是默默丢弃。
