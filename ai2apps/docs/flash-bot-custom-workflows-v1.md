# Flash-Bot 自定义固定工作流 v1

2026-11-08。Messager owner 实现，扩展 B1；普通 Bot、ASC-Bot 和通用 Agentic 不变。

## 用户流程

创建 Flash-Bot 默认进入“自定义工作流（根据职责生成）”，Role 可直接编辑。内置计算器仍可选作模板；编辑模板 Role 时自动转为自定义工作流，需重新生成与审阅。自定义类型填写 Role、执行模型，并按需选择 App/Mini-App。系统只生成草案，展示输入要求、固定步骤、输入适配和计费说明；用户确认后才创建 Bot。纯翻译只需一个固定 AI 步骤，不要求 AaAT。

修改现有 Flash-Bot 的 Role 时，同样重新生成、审阅并启用新版本。已排队和正在执行的任务保留提交时版本；新提交使用新版本。直接更新 Role 的 API 不能绕过工作流审阅。启用使用版本比较，过期编辑必须重新加载。

## 执行合同

工作流是经过 schema 校验的声明数据，最多 8 个顺序步骤：

- `ai`：固定提示词加本次输入/显式前步结果；不提供工具目录，不加载 Bot 历史，不做运行时任务规划。
- `calculate`：白名单 AST/Decimal 计算，禁止 eval 和任意代码。
- `aaat`：固定 capability、provider、version 和参数绑定；执行时重新检查版本、现有 Bot 权限、冻结准入授权和工具 schema，沿用特殊操作确认。

参数只允许字面 JSON 或向后数据引用：`input.text`、`input.files`、`input.files.0.artifact_id`、`steps.0.content` 等。禁止前向引用和可执行表达式。Role、模型、所选 App 和生成结果共同形成不可变审阅标识，草案按用户隔离。编译器不能选择未提供的能力或授予权限。编辑工作流不能扩大现有 App Access。

输入合同目前支持文本、算式、文件、文本加文件；最多 16000 字符、8 个附件，单附件 25 MiB。附件通过原会话归属检查和平台素材导入，不能由模型伪造路径。语音转写和附件入口保留。图片、文档等沿用现有附件内容适配，结果沿用 owner result policy 和平台 artifact 投影，不另写图片显示机制。

## 可选输入适配

先执行代码验证。只有验证不通过、且工作流显式允许时，才增加一次有界 AI 调用，把自然语言转换为已有输入合同；之后再次代码验证。适配没有业务工具、不能修改步骤或扩展能力。含附件的不合法输入不会自动改写。

例如“3 的 7 次方减 1 是不是 7 的倍数”可转换为 `(3**7-1)%7`，由计算器执行并回答“不是，余数为 2”。超出用途或缺少信息时返回使用说明/问题。不能把任意程序作为算式执行。

文本翻译的语言/风格由固定 AI 指令约束；本版本的文本代码验证只检查非空、长度和附件类型，不承诺通用语义分类器。复杂条件分支、循环、任意脚本、跨实例工作流同步和自定义验证器不在本次范围。

## 持久执行与成本

沿用系统 Task、Bot 串行 lane、Agent Run 步骤日志、取消和审批。每步使用稳定 key；恢复读取已完成步骤，不重新规划或自动重放有副作用的调用。队列输入保存定义快照和授权快照。每次正常翻译只有一次模型调用；编译只在创建或修改时发生，输入适配只在验证失败时发生。

## 验证范围

固定执行、输入适配、恶意算式拒绝、用户/版本隔离、旧队列版本保留、两个不同 AaAT 提供者的执行由真实数据库/队列配合夹具模型验证。浏览器夹具验证生成后必须审阅、返回修改会重新生成、内置计算器不需要模型、附件和语音入口可见。固定 App-Dev 已通过标准 Helper 空闲检查重启并验证 Local 导入当前源码；原生创建界面已显示新入口。原生自动化下拉框输入未能完成，因此不将本轮视为真实 Provider 端到端验收；没有执行付费图片生成。

## 2026-11-08 审阅与失败体验修正

审阅使用自适应高度对话框：用途、输入类型、编号步骤和明确的确认按钮；owner 名称用于操作标题，技术参数默认折叠。编译器先读取已选 provider 的当前精确参数合同，将模型枚举等约束交给生成模型，并在草案生成后校验固定字面参数，拒绝非法模型值；输入/前步结果引用仍在实际执行时校验。已有不合法工作流不静默改写，需要用户重新生成、审阅后启用。失败消息不再直接输出 receipt JSON；详细记录通过折叠详情查看，旧错误消息仅改善显示，不重写数据库历史。

输入附件显示修正：Flash 用户消息将已导入的附件 artifact 引用写入消息 metadata，复用 App Chat 的归属校验投影和现有媒体渲染。文件仍通过同一个 input.files 进入执行，不重复上传，不授予新权限。新增图片/文本输入与消息去重测试；既有历史消息不回写。

## 运行时有界自修复（2026-11-08）

Flash 执行器接入平台已有工具失败恢复入口。第一阶段支持 owner 明确返回 parameter_contract_mismatch，且 submitted=false、side_effects=false 的字面枚举预设纠错。每个失败步骤最多一次纠错模型调用和一次重新提交，同时受 Run 步数、超时及累计恢复次数限制。

纠错模型获得原用途、预设、错误字段和 owner 当前合同；只能替换被拒绝的字面枚举字段。代码再次验证，不允许修改 provider、版本、能力、步骤顺序、输入绑定、素材引用或权限。输入缺失、歧义、取消、未知执行结果、有副作用以及再次失败均停止。原失败、模型修正、重新提交分别保存为 Run step。

修正后仍通过现有 Bot 权限、冻结授权、特殊操作确认和 owner 动态合同。整个流程成功后，以 revision CAS 保存成功参数修正为新版工作流，并在结果中告知用户。当前配置必须仍等于提交版本，避免覆盖用户并发修改；旧排队任务快照不变，实际输入文件 ID 不会固化到预设。此阶段不自动增加步骤、扩权、跨 provider 替换或重试执行结果不确定的操作。

## 对话修改、用法咨询和说明一致性（2026-11-09）

Desktop 与 Mobile 的 Flash 对话提交共用 `messager.flash_conversation` owner 服务。合法的附件和表达式继续直接进入原 Flash 队列。其它文本进入一次有界、无工具的意图分析，区分普通执行、未来流程修改、用法咨询、已有输入适配和拒绝；不能把缺少文件的输入凭空补成文件。普通不匹配输入得到具体解释与当前用法，回复持久化到消息流，不再只显示 Request failed。输入适配仍需原计划启用且重新验证。

不提供 Run/Edit 模式按钮。纯翻译等任意文本流程也先识别自然对话意图：明确要求改变未来行为时准备修改草案；普通或引用的待处理文字继续固定执行；意图含混时询问一次，不擅自修改或运行。自动分析最多接收 2000 字；更长的合法执行文本直接执行，不合法输入返回当前用法。

修改时把原 Role 与用户修改要求组合为完整的新 Role，仅从当前已批准 App/Mini-App 目录编译新计划。若缺少必要能力，说明缺项，不自行扩权。草案显示原用法、新职责、输入类型和实际步骤；取消保持旧配置，确认沿用 actor 隔离草案、review_id、revision CAS、provider 版本与当前权限检查。已有排队/运行提交保留旧版本；新提交使用新版本。确认后的回执进入对话流。请求结果按 actor、Bot、request_id 持久化去重，重试相同请求不重复分析或执行。

编译新增独立的语义一致性审阅模型调用：逐项比较 Role 的要求、usage 的承诺、实际步骤和 owner 声明，检查外部副作用有真正的 AaAT 步骤、上下游数据绑定可完成交付、输入类型与用法一致。对话修改还比较原 Role 与变更要求，防止改一项却漏掉其它要求。检查失败不创建可启用草案，显示具体缺项；不能仅删改说明来掩盖遗漏动作。此检查是模型语义审阅，不能替代 schema、权限校验和用户审阅。

成本：合法附件/表达式不新增分类调用；其它短文本通常一次意图分析（包括翻译流程，以支持自然修改，不依赖模式按钮）；生成/修改草案另需一次编译和一次独立一致性审阅。均使用当前 Bot 的配置模型及现有计费入口，不能产生业务工具副作用。此机制属于工作流控制面，区别于运行时预设参数自修复。

意图识别、草案生成和一致性审阅分别校验模型返回。每个阶段遇到空回复、截断或结果格式无效时，只重新请求该阶段一次；截断时适度提高输出额度（最多 6000 tokens）。已成功的阶段不重跑，明确的模型拒绝、服务错误和有效的业务否决不重试。失败时对话说明具体阶段和原因，日志只记阶段、尝试次数、原因和请求标识；不会记录提示词或回复正文。修复只重新调用分析模型，草案仍须用户审阅后才能启用。

### Gallery 保存与模型约束（2026-11-09）

Gallery owner 新增 `gallery.save_material`，接收当前已授权 Session 的真实 artifact_id，复用 Gallery UI 的保存服务；支持图片、音视频、文档和文件，按内容去重。Recent 是虚拟最近视图，保存后自动可见，不创建同名目录。与 `gallery.import_materials` 的方向明确区分。流程说明承诺保存时必须包含此真实写入步骤，继续受 Bot 的 Gallery Access 校验。

编译目录包含 owner 的各模型约束；草案固定选择模型后，重新读取该模型的精确合同校验参数，再做独立一致性审阅。不能把未选择模型时的默认尺寸限制当成所有模型的限制。只有所选模型声明支持 auto 才能使用 auto；这不承诺像素级保持输入比例。缺少精确保比例能力时应说明限制，不假装已经实现。

发送可用性：Flash 对话的语音模型目录在后台加载，不作为固定流程或工作流修改消息的发送前提。目录缓慢、失败或一直未返回时，已打开会话的文字发送和附件入口仍可使用；仅语音候选模型列表稍后更新。

### 执行中的步骤连接纠错

Flash 编译目录提供工具的输出声明。AI 和计算步骤有文本输出 `content`。AaAT 的输出字段以工具声明为准，不能假定所有工具都有文本输出。新草案的会话产物连接在编译和启用时核对已声明的输出路径。

执行时如果资源参数引用的上游字段不存在，Flash 会检查原上游步骤已经完成的回执。仅当原 Provider 及版本仍匹配，且回执中恰好有一个工具声明为会话产物、实际存在于当前会话且符合目标参数类型的输出时，才修正引用。修正仍经过应用权限、参数检查和 owner 的会话产物校验。该规则适用于所有声明了这类输入和输出的 AaAT。已经完成的步骤不会重放，存在歧义时停止并指出步骤和缺失引用。整个工作流成功后，以现有版本比较与写入机制保存新连接，避免覆盖用户在执行期间修改的工作流。
