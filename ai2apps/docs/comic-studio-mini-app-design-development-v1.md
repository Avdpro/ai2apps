# 短漫工坊 Mini App 设计与开发方案

版本：设计 v1，2026-10-31。状态：需求与开发基线，尚未实现或发布。

短漫工坊以独立 Package 提供 Image Studio 内的系列漫画创作能力。用户维护系列与角色，
按自己的脚本或经过多候选审核的脚本生成 2～6 格漫画，并可为系列配置定时批量创作。
系列、角色、分集记忆及工作流属于 Package，不放进通用 Agent 或 Studio Host。

## 1 产品范围与基本决策

第一版包含以下完整能力，按阶段上线而不是一次并行开发：

- 系列创建、编辑、归档；风格、世界观、角色组和内容规则持久保存。
- 手写故事转分镜，或多候选编剧、模型审核、选择一集或多集。
- 2～6 格逐格绘制；固定角色参考、系列风格参考及最近画格参考共同约束。
- 新角色先生成并确认设定，再进入绘制；明确授权后才允许无人值守自动入库。
- 台词与气泡独立排版、单格重绘、整页合成、共享 Output 输出。
- 最近 20 集详细摘要加长期主题索引，防止剧情和笑点重复。
- 日期、指定地区季节、已有新闻频道信息作为可选编剧素材。
- 系列定时计划、单次目标集数、预算、恢复、取消及完成通知。

第一版不包括自动发布到社交平台、无限自动重试、跨系列共享角色、漫画动画、
任意脚本插件、全自动抓取任意网站或保证角色像素级一致。

“定时绘制”不等于仅在网页打开时有效；关闭 Mini-App 页面不应终止任务。
关闭 Local 或设备关机后不承诺继续运行，也不承诺秒级准点完成。

## 2 独立 Package 与架构边界

### 2.1 产品身份

以下 ID 为开发建议值，建立源目录前核对唯一性，发布前固定：

| 项目 | 设计值 |
| --- | --- |
| Package | `ai2apps/comic-studio`，底层类型 `app` |
| App | `ai2apps.comic-studio` |
| Mini-App | `ai2apps.imagine.comic-studio` |
| Studio | `ai2apps.imagine-studio` |
| 生命周期 | `project`，不是一次性 clip |
| 分类 | 显式 `catalog.categories: [image]` |
| Launcher | `navigation.launcher: false` |
| 语言 | 英文默认，中文 UI、帮助、可访问名称完整本地化 |

不并入静止时间或其它套件，不增加内置 Mini-App 的第二份注册表。
首次 App entry 与 app.yaml entry 一致，真正 UI Entry 在 mini_apps 中声明。
安装源、沙箱资源、帮助、声明、SBOM、测试与迁移均纳入签名文件索引。

### 2.2 所有权

| 所属层 | 负责 | 不负责 |
| --- | --- | --- |
| Package UI | 系列选择、参数编辑、角色确认、分镜、候选审核展示、进度观察 | 后台调度、保存凭据、私有成品下载实现 |
| Package 所属工作流服务 | 系列数据库、脚本/审核策略、去重、角色设定、参考选择、排版、检查点 | 通用 Agent 全局规则、任意 Host 文件访问 |
| Host 通用能力 | 受控挂载/身份、模型调用、素材引用、任务观察、共享 Output | 角色命名、笑点评分、漫画分镜或业务重试判断 |
| 模型 Package/Provider | 各自模型能力、许可、参考上限和执行 | 决定漫画业务状态或用户授权 |

UI 的“绘制”、Mini-Chat 的“绘制当前集”和定时任务复用同一 owner 提交流程。
Mini-Chat 只调用可信声明动作，不拼另一套图片请求，也不需要模拟鼠标坐标点击。
表单回填不等于执行授权，提交时仍由 owner 校验全部条件。

### 2.3 后台服务与单包约束

产品必须有一个独立 App Package 作为唯一用户入口；不能把后端业务硬编码到 Image Studio。
当前已记录的 `app-service-exports/v1` 通过**显式依赖的隔离 Service Package**执行，
并不允许纯前端 App 导入 Python 到 Host、任意注册系统 Task handler 或执行 shell。

P0 必须确认采用哪条受支持部署路径：

1. 独立 App Package 加一个明确声明的业务 Service 依赖，用户从 App Package 安装入口解析依赖；
   仍是独立产品，但不是“只有一个物理发布工件”。
2. 如果要求严格只有一个发布工件，必须先验证现有 App 协议能否承载隔离后台工作流；
   不能支持时提出通用协议扩展设计，经评审后实施，不能临时把漫画逻辑移入 Host。

本设计不预先声称单工件后台执行已受支持。采用第二个 Service 工件前需明确产品方接受。
无论选择哪条路径，系列/角色业务和迁移都随所属 Package 版本发布，模型权重不打入本包。

## 3 核心数据模型

所有实体绑定 owner、Installation 与所属 App；跨用户引用必须拒绝。
稳定 ID 与显示名称分离，修改名称不改变引用关系。时间以 UTC 存储，并保留业务时区。

| 实体 | 主要字段与职责 |
| --- | --- |
| Series | id、名称、当前 revision、风格/世界观、受众、内容边界、格数/版式、默认画格比例、角色组 |
| SeriesRevision | 不可变系列设定、模型选择策略、编剧/审核规则、来源策略 |
| Character | id、名字/别名、系列归属、身份状态、当前设定版本 |
| CharacterRevision | 外貌、轮廓/颜色特征、性格、关系、标准图引用、许可与确认记录 |
| ContextSnapshot | 业务日期/时区/地点、季节、新闻条目/来源/时间、获取状态和内容摘要 |
| ScriptCandidate | 生成轮次、梗概、主题、笑点、2～6 格脚本、角色引用、内容摘要哈希 |
| ReviewReport | 规则版本、模型标识、评分、通过/拒绝理由、重复命中、入选组合 |
| Episode | id、系列、编号、设定快照、画格比例覆盖值及实际生效值、脚本版本、所选角色版本、任务和成品引用 |
| Panel | episode、序号、场景/镜头/动作、台词、参考清单、生成版本与结果引用 |
| Batch | 单次目标数、冻结设置、成功/失败/待确认集数、预算、根任务引用 |
| ScheduleBinding | 系列、计划配置、系统 schedule 引用、授权策略、下次触发和停用原因 |
| EpisodeMemory | 主题、场景、角色组合、情节、笑点、结局、时间与是否已对外完成 |

数据库/素材放在 Package 所属受管数据空间，不能使用浏览器 localStorage 作为唯一存储。
图片保留受管文件引用和摘要；任务 payload 只存有界 JSON 与引用，不存模型凭据或大 Data URL。
完成分集是不可变修订，重绘产生新版本；历史使用的角色和风格版本不随当前设定改变。
逻辑删除/归档、恢复、导入导出与 schema 迁移要保留关联完整性；删除正在使用的角色应阻止或归档。

## 4 系列设置

### 4.1 故事与视觉

- 名称、简介、世界观、主角/配角组、人物关系。
- 主题、受众、幽默方式、叙述口吻、内容禁区、独立单元剧/连续剧情。
- 风格文字与参考图、色板、线条、字体、气泡规则；人物参考与风格参考分开管理。
- 默认 2～6 格、阅读方向、版式、输出尺寸与语言；设定允许本集覆盖的字段。
- 默认每格画面比例（宽:高），例如1:1、4:3、3:4、16:9、9:16；支持有界自定义比例。
  比例指单格内容画面，不是整页漫画比例，也不包含边框、格间距或页标题。
- 默认文案/审核/角色设定/逐格绘图模型，可分别选择；审核与编剧可相同但不默认宣称独立。

角色参考不能保证绝对一致；UI 提供逐格复查和重绘，不能用审核“通过”替代图片实际质量。

### 4.2 信息来源

独立开关控制日期、季节、节日、指定已有新闻频道。开关表示允许使用，不要求强行加入每集。
日期默认实际执行时在系列时区的日期；可明确锁定某个故事日期。
季节必须指定故事地区/半球；没有地点时要求补充或禁用季节推断。
新闻配置包括频道 ID、回看范围、主题、允许使用方式和无新闻策略。

只读访问用户有权读取的已有频道内容；不隐式创建频道、抓取任意网站或增加订阅。
ContextSnapshot 同时记录发表时间与收录时间，生成时冻结。没有可用新闻时按系列策略
等待、跳过新闻或停下，不编造“今日新闻”。来源事实和漫画虚构清楚分离。
来源数据是不可信素材，不得成为系统指令、工具授权或角色身份定义。

## 5 手动创作与多候选编剧

### 5.1 手写故事入口

用户选系列，输入故事方向、Prompt 或完整分镜；选择格数及本集覆盖设置。
本集“每格画面比例”默认继承系列，可单独指定；第一版同一集所有画格使用同一生效比例，
不扩展为逐格不同的比例。优先级为单集显式覆盖 > 本次冻结的系列默认值。
覆盖值不反写系列；选择“继承系列”才清除覆盖。分集记录原始覆盖与最终生效比例，
系列默认值后续变化不改变已生成或正在执行的分集。
模型整理为结构化脚本，保留原输入。展示标题、梗概、逐格镜头/动作/表情/台词/旁白，
用户可以编辑后确认；完全按自有脚本绘制时不强制再生成候选。

### 5.2 自动编剧设置

| 参数 | 初始设计默认值 | 约束 |
| --- | --- | --- |
| 撰写模型 | 用户系列选择 | 记录实际 Provider/model/revision，不能静默换模型 |
| 审核模型 | 用户系列选择 | 与撰写分开选择 |
| 候选数 N | 4 | 建议 UI 1～8，最终按预算及能力校验 |
| 入选数 K | 1 | 1≤K≤N；批次还受剩余目标集数限制 |
| 最大撰写轮数 | 2 | 包含首轮；拒绝全部也可能正常结束 |
| 绘制前确认 | 开启 | 定时全自动必须单独授权关闭 |

这些是产品默认值，不是模型保证或已实现系统上限。
一轮流程：冻结设定/Context → 读取记忆 → 生成 N 个候选 → 结构验证 → 审核 →
组合去重并排序 → 展示入选理由 → 人工确认或按已授权策略进入绘制。

审核输出必须引用实际 candidate ID，不接受模型发明候选。人工可以改选、改稿或全部拒绝。
候选全部不合格可在轮数与预算内重新撰写；预算用完后 partial/等待，不为凑数强行选入。

### 5.3 审核规则

硬门禁：2～6 格结构合法、角色引用可解析、来源要求满足、内容边界、参考资源归属。
软评分：系列/人物一致性、趣味性、结尾落点、格间清晰度、视觉可实现性、台词长度和新鲜度。
硬门禁失败不能被高分抵消；“有趣”是模型建议，不包装为客观事实。
报告保存每项理由、重复命中集、修改建议与拒绝原因，用户可查看。

多集入选做组合去重，不能简单选前 K 个导致同一个梗重复。生成中的已选脚本纳入预留记忆，
避免同批后续候选重复；失败草稿不计为正式已发布集，但保留近期创作记录。

### 5.4 历史记忆

默认向用户展示最近 20 集详细摘要，可切换/查询历史；长期保存全系列主题与笑点索引。
检索采用结构化标签与文本相似性，嵌入检索可作为增强而非第一版硬依赖。
记录独立集、上一集续篇和指定续篇关系；连续剧情允许复用伏笔，不把所有相似都拒绝。
无法可靠检索历史时提示覆盖范围，不能声称已检查全部集数或保证永不重复。

## 6 新角色工作流

脚本角色用稳定 ID；新名字先做别名匹配，歧义时人工确认，不能自动当作新角色或旧角色。
新角色建议卡包含故事职责、外貌、性格、关系、固定特征和本集临时服装。
默认按系列视觉风格生成标准参考图与设定说明，展示后确认入库，再允许绘制相关画格。

状态：proposed → designing → awaiting_approval → approved/rejected。
分别标记固定角色和客串；客串保留可复用设定，不默认加入所有后续集。
本格临时造型、表情和生成缺陷不反写角色标准版本。
用户修改标准设定产生新 revision；已有脚本/画格绑定旧版本，必须明确决定是否替换。

定时策略：仅已有角色（默认）；新角色等待确认；或明确授权自动设定审核并入库。
自动入库保存 auto-approved 与授权/审核证据，不能冒充人工确认；失败时本集等待或跳过。

## 7 逐格绘制与排版

### 7.1 每格输入

每格必须包含系列风格快照、本格明确脚本、出场角色的 approved 参考、构图与气泡预留区域。
默认额外参考最近 2 个已接受画格，数量可选 0/1/2。前序图是连贯性参考，不是需要复制的画面。
参考附角色 ID/版本与画格编号/用途；实际图像排列与这些标签一致，不能只在文本里声称有图。

前序图可缩小，默认长边 512px 作为试验起点，保持比例、不拉伸；原图保留。
尺寸、编码质量及是否缩小按模型能力和实测调节，不承诺参考分辨率减半就等比例提速/省费。

### 7.2 参考预算

依据真实模型声明的图片数量/尺寸/总字节约束安排输入，不能按模型名字猜能力。
分配顺序：必要出场角色 → 必要风格参考 → 最近一格 → 再前一格。
超过预算时先减少前序图；必要角色仍放不下则停止准备，建议换模型或由用户确认组合参考板。
组合参考板须有可识别角色标签并验证可用，不默认认为拼成一张等于模型能区分所有角色。
文本生成但不支持图片编辑/参考的模型不能被宣传为有一致性参考能力。

角色设定是身份权威，前序格只提供连续性。上一格错误应先修正或停下，不能强行传播。
首格没有前序图；跨明显换景可减少连续性参考，仍保留人物设定。

### 7.3 顺序、检查点与重绘

同一集按格顺序生成，每格有独立提交标识、结果摘要、参考指纹及可恢复边界。
一格失败不丢弃已完成格；用户可以调整后重绘该格。
重绘第 i 格使依赖它的后续格标记 reference_changed，但不自动执行付费重绘。
用户可保留现有后续结果、选择受影响格或重绘全部；成品版本记录实际选择。

参考帧只接受已完成并被本轮接受的版本；候选/失败/迟到结果不能替代当前画格。
同一角色多格图像质量可做审核提示，第一版不承诺可靠自动身份判定。

### 7.4 文字与合成

默认模型绘制无文字或预留气泡区域，台词/旁白/音效由独立排版层渲染。
脚本保存文字、归属角色、气泡形状/锚点及阅读顺序。编辑台词或字体无需重新生成画面。
文字过长给出溢出提示，可调整字号/气泡或经用户确认缩写，不悄悄删除台词。
支持少量固定 2～6 格模板，阅读方向、格间距、边框、画布比例、标题由模板控制。
模板变化只重排版；改变画格裁切前预览，不拉伸人物、不承诺任意版式都无裁切。

### 7.5 画格比例与生成尺寸

系列默认画格比例与单集覆盖独立于整页模板、画布尺寸。绘制准备阶段按本集生效比例选择
模型支持的像素尺寸，分别保存目标比例、实际请求尺寸与最终画格尺寸；不把比例当成分辨率。
模型尺寸步长导致的轻微偏差要在预览中反映；不支持目标比例时提示兼容尺寸及必要裁切/留边，
由用户确认，不能静默改比例或拉伸图像。自动任务必须事先选择不兼容时暂停或明确的适配策略。

分镜编写、角色构图、气泡预留和排版均读取同一个生效画格比例。整页版式适配单格比例，
不为填满整页强行变形；长横格与竖格可以对应不同整页尺寸。
绘制前修改本集比例会使分镜构图/尺寸准备确认失效，保留脚本文字供重新检查；绘制后修改比例
不自动重画或扣费，用户选择重新构图生成，或对已有画格显式裁切/留边后形成新版本。

## 8 批量与定时生成

### 8.1 系列计划

计划包含启用状态、时区、下次时间、重复规则、单次目标集数、模型策略、候选 N/入选 K、
每集格数、人工/自动确认、新角色策略、来源失败策略、预算和通知偏好。
定时生成默认使用触发时冻结的系列画格比例；单次手动批次可统一指定本批分集的比例覆盖，
不改变系列默认值。定时配置第一版不另增一套隐式比例覆盖规则。
建议第一版每批目标 1～5 集，最终上限在性能/费用验收后固定。
“目标 3 集”不保证产量：只完成 2 集时报告 2/3 与剩余原因，不无限生成补足。

定时启用需显式批准实际自动行为与上限；修改模型、预算或自动角色入库策略可能要求重新确认。
每次触发冻结当时系列 revision 和模型选择，记录原计划版本；执行中不套用新设置。

### 8.2 与现有调度的衔接

复用已有系统任务准入、去重、取消、进度和恢复，不另建网页 setInterval 调度器。
当前文档中的 Schedule 只支持单次与固定间隔，不能直接承诺 cron、每周、夏令时日历语义。
P0 检查当前代码实际能力；若仍无日历支持，第一版只展示受支持规则，或者先交付经评审的
通用时区/日历调度扩展。不能把每 24 小时固定间隔等同于任意时区“每天 9 点”。

2026-10-31 已核对当前情报中心实现：

- 复用 `system_tasks/service.py` 的 `SystemTaskService`，计划保存在 `system_task_schedules`，执行和尝试记录保存在系统任务表中；页面关闭不影响 Local 调度。
- 情报中心在 `intelligence/collector.py::sync_system_schedules` 同步计划，在 `system_tasks/intelligence.py::register_intelligence` 注册受控处理器；漫画工作流应采用相同的“系统负责触发、业务负责执行”分层。
- 当前接口是 `next_run` 加可选 `interval_seconds`，固定间隔最少60秒。漏过的周期合并一次，不补跑全部历史周期；手动立即执行不改变原计划时间。
- 当前默认准入上限为全局4、单App2、单Owner2。该层只负责准入，模型/GPU继续由现有资源调度器管理；漫画批次内部保持逐集、逐格有序执行。
- 自动恢复只适用于明确声明可恢复的处理器；每次执行重验权限。漫画检查点须引用同一批次、模型请求和Output，不得把“不确定的绘图请求”作为普通任务自动重试。
- Todo 已有统一任务与计划观察入口，优先复用，不在Mini-App建立第二套定时历史。系统历史会清理，系列分集记忆必须独立持久保存。
- 现有 `execution_session` 明确限内置App；Package工作流需要身份和版本绑定的受控适配，不能直接套用情报中心的内置权限身份。现有App Chat任务适配主要观察已创建的Agent Run，并不等于已经支持定时启动任意Package工作流。

因此，后续Service依赖若采用，是为承载无人值守的漫画业务流程与持久状态，而不是另建时钟、队列或系统任务中心。MVP的通用图片序列后台任务作为下游绘制任务复用；上层系统任务保存批次与下游任务ID，只观察原任务并汇总进度，避免重复提交。

Package 不得任意注册 Host Python handler。必须通过受支持、身份绑定的隔离工作流适配。
后台身份不依赖前台手机 Cookie、当前 Chat 或页面存活；App 停用、权限撤销、成员失效时重验。
禁止直接调用只为内置可信 App 提供的 execution_session 解析器冒充授权。

### 8.3 并发、重复与遗漏触发

同系列批次串行；手动和定时使用同一系列级活动锁/去重键，冲突时显示现有任务。
触发标识绑定 schedule ID 与计划触发时间，重复通知不能创建第二批。
前一批未结束默认跳过/合并为一个待执行意图，不叠加无限队列。
设备离线漏掉多次默认合并一次，不自动补跑全部历史日期；UI 明确显示实际故事日期。

同批每集选择成功后立即预留其主题/笑点，后续编剧读取已有预留；确认完成再提交正式记忆。
一个批次一个根任务，分集/模型调用作为 owned 子阶段，不重复占根并发名额。
等待 GPU、模型、用户确认各有真实状态，不用虚假心跳伪造进度。

### 8.4 预算、恢复与取消

冻结单次最大集数、候选轮数、逐格尝试次数、调用/金额限制与截止时间。
价格未知时不伪造金额硬上限，改用可执行的调用次数上限并明确估算不保证实际账单。
所有模型调用登记请求标识与状态，能够查回已提交结果时先查询；超时结果未知不能自动重画。
检查点记录已审核候选、角色版本、每格完成结果和已发布 Output ID。
崩溃恢复不重复计费、不重复入库/发布；无法证明外部提交结果时等待核查。

取消先停止新增工作，再取消本任务拥有的调用，确认清理后才 cancelled。
保留已经完成集与可恢复画格；不杀共享模型进程、不取消其它系列任务。
批次部分成功返回 partial；通知只含有权接收的摘要，不泄漏脚本、新闻正文或凭据。

## 9 界面与输出

默认从“选择/新建系列”开始，不重复 Studio workspace 标题。系列设置、角色库、历史与高级参数
默认折叠；本集工作区展示创作方向、格数、候选数和“生成脚本/绘制当前脚本”。
候选卡显示梗概、完整分镜入口、审核理由及选择状态；新角色显示独立待确认门禁。
绘制区逐格显示排队/运行/完成/失败、预览和重绘动作，排版预览与文字编辑紧邻成品。

素材槽使用跨 Studio 标准组件，支持文件、照片、Gallery 和受控 Output 引用；不各做一套。
移动端单滚动容器，预览/选择/文字编辑可触控；曲线/拖拽不能阻止整页滚动。
所有控件有本地化可访问名称，真实挂载内用 role/name 验收，iframe 单独标识。

正式成品进入 Host 唯一共享 Output：

- 默认整页 PNG；可选 JPEG。
- 按需发布单格 PNG 与分集 ZIP（图片、脚本和版本清单），不默认把所有中间图塞进 Output。
- PDF、可编辑工程包可作为后续格式；第一版若提供工程导出，必须有版本化导入验证。
- 新格式转存复用已有画格与排版，不再次调用绘图模型。

候选脚本、角色候选、逐格过程预览属于 Package 编辑区，不创建第二份输出历史/下载体系。
共享 Output 中成品的保存、下载、Gallery 导入与拖放沿 Host 标准；Mini-App 不私自存 Downloads。
更改系列或草稿不删除已发布成品。业务保存与共享 Output 发布之间使用持久 outbox/幂等键，
避免一个事务成功、另一个失败导致成品丢失或重复卡片。

## 10 业务操作与状态合同

以下为 owner 内部逻辑接口建议，不是已注册 REST/Tool 名称；P0 后映射到真实签名 Schema。

| 操作组 | 功能 | 关键守卫 |
| --- | --- | --- |
| series create/get/update/archive | 管理系列与 revision | owner、expected_revision、归档活动任务检查 |
| character propose/design/approve | 提议、设定、确认角色 | 稳定身份、参考归属、设定哈希、明确确认 |
| script draft/review/select | 候选、审核、组合选择 | 模型版本、Context/历史快照、候选 ID |
| episode prepare/render/get/cancel | 准备、绘制、观察、取消 | 脚本/角色版本、预算、去重、所属任务 |
| panel regenerate | 单格重绘 | 明确目标版本、参考指纹、后续失效标记 |
| episode compose/export | 排版和转存 | 已完成画格、文件类型、幂等输出 |
| schedule configure/enable/disable | 计划管理 | 实际支持规则、owner、自动执行确认 |

分集业务阶段：draft → scripting → reviewing → awaiting_script_approval →
awaiting_character_approval → rendering → composing → completed。
没有新角色或无需人工审核时可以跳过对应阶段；failed/partial/cancelled 与等待状态单独记录。
这些是 owner 阶段，不替换系统 Task 状态；进度只投影一次，页面与 AaAT 观察同一任务。

重复请求相同参数返回同一业务回执，重复键不同参数拒绝。操作必须版本绑定，不因模型
返回“已确认”或声明 next_action 就执行。原任务未知副作用、取消或权限失败不得换入口重放。
模型输出先按严格 Schema 验证，拒绝不存在角色/候选和跨系列引用；纯文本不执行。

## 11 数据安全与生命周期

- 所有引用按当前身份解析，不接受任意本机路径、任意 URL 代理或用户传入的身份字段。
- 不把新闻正文当指令，不允许生成脚本要求泄漏凭据、修改调度授权或改变模型预算。
- 角色图片、参考素材使用权及模型许可由清晰 UI 和声明提示；不以使用开关替代许可确认。
- 升级迁移备份与版本验证，失败不覆盖旧库；禁用 Package 停止新增任务及计划。
- 卸载前提示数据保留/导出/清理选择；默认不静默删除系列及成品，恢复安装验证数据兼容。
- 临时缩略图/候选保留策略可配置；被历史分集引用的标准角色图不得当作缓存删除。
- 日志记录阶段、ID、错误和摘要，不记录 Cookie、API key、完整参考图或大段私密脚本。

## 13 验收清单

### 功能与图像

1. 同系列完成 2、3、4、5、6 格；模板阅读顺序、文字、图片比例正确。验证系列默认比例、
   单集覆盖/恢复继承、覆盖不污染系列、执行冻结、定时继承及模型不支持时的明确适配；
   不同整页版式不拉伸画格，生成后改比例不会自动扣费重画。
2. 两个角色连续三集保持标准版本引用；第三集新增角色，在确认前不能开始相关绘制。
3. 前序参考 0/1/2 格正确，第一格没有伪造参考；缩略图保留比例和用途标签。
4. 参考超限、缺模型、模型无图像参考能力时给出准确阻断，不静默删除角色或换模型。
5. 修改文字仅排版；重绘单格只提交一次，后续依赖变更可见；转存不重复推理。

### 编剧与内容

6. N 候选与 K 入选、审核全拒绝、组合重复、人工改选、轮数/预算耗尽均可解释和恢复。
7. 最近20集与长期索引实际参与检索；续篇不误判，历史缺失不谎称完整检查。
8. 时区跨日、南北半球、无新闻、过期新闻、频道撤权、提示注入有明确结果和来源证据。
9. 非法候选/角色ID、错误脚本Schema和审核输出拒绝，不能被模型自由文本绕过。

### 后台与安全

10. 计划目标3集只完成2集时partial；完成集和失败原因保留，不无限补足。
11. 重复触发、手动与定时冲突、GPU排队、断线、页面关闭、Local重启按原任务恢复。
12. 外部模型已提交但结果未知时不重复计费调用；已发布成品不会恢复成重复Output。
13. 取消确认资源清理；App停用/撤权/升级/卸载触发正确计划与任务处理，不影响其它App。
14. 跨actor/Session/Installation和伪造文件引用拒绝；凭据不进入任务、导出或日志。

### Package 与客户端

15. 生产严格沙箱下签名包挂载/帮助/所有业务接口可用，不依赖Development同源例外。
16. 独立Package图像分类、宿主检索、父包安装目标正确；纯组件不出现在普通App Launcher。
17. Desktop/Mobile统一素材槽、单滚动、可访问名称、键盘、中文/英文与历史恢复实测。
18. 最终制品安装后UI、Mini-Chat、定时入口复用owner工作流和共享Output；fixture不冒充实机。

## 14 开发前必须冻结的事项

- 最终名称/ID，以及“单独Package”是否允许显式后台Service依赖。
- 真实模型的参考数量/尺寸限制、批次上限及候选默认值是否足以覆盖目标机器。
- 当前调度桥接、时区日历、频道只读、隔离持久服务及输出发布是否满足要求；不满足则先列通用缺口。
- 全自动模式默认仍需人工确认的新角色策略、可接受预算与内容边界。

上述事项不改变已确认的产品目标；它们是进入实现与无人值守运行前的工程门禁。
