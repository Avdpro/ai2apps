# 官网账户页：我的应用与访客空间入口

日期：2026-10-09
状态：待 Cloud 项目实现与部署；本文不代表生产已上线。

## 用户需求

用户登录 AI2Apps 官网后，应在账户页直接看到「进入我的应用」和「我的访客空间」，不必再次寻找设备二维码。两个入口始终绑定当前登录账户，使用固定用户 URL，由 Cloud 解析当前主设备。

## 已核对的实现

- Cloud `web/app/account/page.tsx` 渲染 `web/components/AccountPanel.tsx`。
- AccountPanel 从 `/v1/auth/me` 获取 `user.id`，当前只显示个人资料、设备与退出登录，没有应用或空间入口。
- `src/spaces/page.ts` 已支持固定 `/u/{userId}` 和 `?entry=owner-home`。Owner 可用时仍显示两个选择按钮；该 query 目前不代表直接完成交接。
- 访客入口已有公开状态解析与匿名会话交接；目前没有显式的直达访客视图 entry 参数。

## 界面要求

在账户头像、姓名与邮箱下方、资料/设备导航上方放置两个明显入口：

| 文案 | 样式 | 用途 |
| --- | --- | --- |
| 进入我的应用 | 黑色主按钮、应用图标 | 进入自己主设备的 Owner 私有应用 |
| 我的访客空间 | 次按钮、地球图标 | 查看自己已发布的访客主页 |

沿用官网字体、圆角、间距与图标体系；手机上两按钮纵向排列，触控高度至少 44px，首屏可见。接入现有语言机制，中英文均完整。加载、错误与焦点状态须可访问。

不因空间关闭、未发布或设备离线而隐藏入口；点击后显示具体状态及可用的重试/返回账户操作。不得显示裸 JSON、跳转 coder 根目录或要求重新扫码。

## 路由与权限

1. 从可信登录结果 `user.id` 构造账户固定入口，禁止硬编码示例 UUID、缓存某台设备地址或使用邮件地址代替用户 ID。
2. 「进入我的应用」进入受信配置的 `https://coder.ai2apps.com/u/{userId}?entry=owner-home`，沿用现有 Owner 身份校验和独立 handoff。尽量复用官网登录状态；若目标源仍需登录，完成登录后返回这一准确的 Owner 入口。不得通过 URL 携带长期 Cookie、访问令牌或刷新令牌。
3. 如实现单次点击直接进入应用，必须在现有 Owner 验证通过后调用现有 handoff，不得把 `entry` 参数当授权。避免重复请求、回退重放或自动跳转循环；失败时保留明确的重试按钮。
4. **新增明确的访客路由意图**，建议 `https://coder.ai2apps.com/u/{userId}?entry=visitor`。该参数尚不存在，需要 Cloud 实现：直接复用公开空间解析与匿名会话交接，不再显示 Owner 入口选择页。
5. 即使当前登录者是 Owner，「我的访客空间」也只展示已发布内容，使用访客权限，不显示编辑草稿、不获得 Owner Bridge 或私有应用权限。闭站、未发布、离线仍遵循现有公开状态。
6. 普通 `/u/{userId}`、已有二维码、匿名访问和旧协议继续兼容；未知 entry 参数不能扩展权限。跳转目标必须限制在现有受信 origin 与路由，拒绝任意 return URL。
7. 明确验证 home 与 coder 的跨源登录衔接，不假设 `credentials: include` 就意味着两个源共享有效登录；遵循已有认证与 Cookie 安全边界。

## 验收

- 登录用户 A 的账户页展示两按钮，所有路径绑定 A；切换账户 B 后不残留 A。
- Owner 在线且就绪：从账户页进入自己的 Apps，返回后再次进入正常。
- 点击「我的访客空间」直接展示已发布主页；Owner 与未登录访问者看到相同公开内容，均不能获得私有权限。
- 未开启/未发布/离线/无主设备/客户端未就绪有清晰说明，入口不消失，无裸 JSON。
- 认证过期后登录恢复原目标，拒绝非 Owner 私有交接；访客空间不要求登录。
- 空间关闭、租约撤销与现有最长 8 小时、闲置 30 分钟规则不变。
- iPhone Safari 与桌面 Chrome 实测按钮、跨源登录、返回/重入和错误恢复；语言、键盘焦点与窄屏不溢出。
