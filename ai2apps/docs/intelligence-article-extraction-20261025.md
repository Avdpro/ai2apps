# Article extraction: noscript pollution and truncation

## Live reproduction

Source: https://timeandtidewatches.com/g-shock-renaud-tixier-armin-strom-last-week-in-watches/

The source owns a validated article region rule, `div.article__content`. This
path runs before generic Readability. Its previous implementation cloned the
region, removed some non-content nodes, then read `textContent`. It omitted
`noscript` and `template`. Firefox exposes a scripted document's noscript body
as text: this page has backup image HTML in noscript text nodes. Consequently
nine literal image tags entered the first 10,000 cached characters (4,367
characters of image markup), and the cache stopped inside a srcset attribute.
This is not a Readability HTML-versus-text result mixup.

Same native BiDi session, same live page, isolated owned tabs closed after each
probe:

- Before, actual compiled region helper: exactly10,000 chars,9 literal img tags.
- Readability comparison:8,607 chars,0 literal img tags.
- After, same region helper:8,683 chars,0 literal img tags, final EXOFI Wolf Rock42
  section and its concluding link present. Different length reflects region
  versus Readability selection, not missing article tail.

## Change

Shared compiled region extraction removes non-content nodes including noscript
and template and prunes hidden descendants against the live DOM using the shared
visibility policy. It does not strip markup-looking strings with a regex, so
legitimate visible code examples remain. Original live DOM is never modified.
Access/login/paywall checks and rule scope/drift guards remain before extraction.

The generic helper honors caller max_chars rather than hardcoding10,000; its
compatible bounded default is20,000. Intelligence requests20,000 within its
existing20,000-character Page storage ceiling. This is not unlimited collection:
longer results explicitly report truncation. Extracted/returned lengths, limit,
method, fallback reason and cleanup count now survive the Intelligence evidence
model into its page cache. No model prompt/evidence-validation rules are relaxed.

Existing cached summaries are not silently edited or regenerated by a reader
repair. Re-extraction probe receipts are /tmp/timeandtide-compiled-before.json,
/tmp/timeandtide-read-before.json and /tmp/timeandtide-readability-clean.json.
No paid model generation was invoked for the diagnostic re-read.
