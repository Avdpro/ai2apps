# 微信代理模式的图片 Work 对接要求

验收对象是 App-Dev 中已保存的 DarthFalcon 监听 Worker。它监听已选会话中的
新入站图片，按用户配置判断图片是否含色情内容，向同一会话只回「是」或「否」，
并在该 Work 的工作日志里记录处理结果。

## 现有接口和缺口

当前 `wechat-agent messages` 能返回消息类型、来源、时间、本地 ID、服务器 ID
及分库名。类型 3 可用于识别图片消息。返回的消息正文或 XML 是元数据，CLI
没有按会话和消息 ID 返回入站图片字节的入口。CLI 的 `send-image` 发送本地图片，
不提供入站图片读取。现有消息游标以分库为单位，从较早记录往后读。

当前文本发送可用持久请求 ID 入队。共享的 `queue run --execute --max-jobs 1`
按全局调度规则选下一条可发消息，接口不接收期望执行的请求 ID。

## 微信 CLI 需要提供的能力

- 按已绑定的 profile、namespace 和会话获取新的入站消息。消息流应提供可以从当前
  尾部建立的持久游标，或提供等价的有限增量读取。事件包含稳定消息身份、入站方向
  和类型，并能发现游标失效或覆盖不完整。
- 按会话和消息身份读取单张入站图片。适配器核对账号、会话、方向和消息类型，
  返回有界的 PNG 或 JPEG 字节，或者仅供本次调用读取的本地文件。缓存未就绪、
  图片缺失或身份变化应有明确状态。应用不需要数据库密钥，也不需要全库媒体导出。
- 使用现有共享调度规则和原请求 ID，提供只处理指定请求的入口，或等价的受管
  调度接口。在调度锁内确认指定请求就是当前允许处理的队首，否则报告等待原因。
  保留账号绑定、顺序、频率、暂停及未知结果停止规则。重复查询应返回原回执，
  未知结果保留原 ID，供后续核对。

## 传信接入与验收

启用时从会话当前尾部开始。传信只读取已启用 Work 的目标会话，按
账号、Work 和消息身份持久去重。仅把经过验证的图片交给获准的视觉识别入口，
并将图片中的文字视为待识别数据。发送前再次核对 Work 和目标，输出只接受
「是」或「否」。读图、识别失败或结果无效时，写日志并停止该次处理。

工作日志记录时间、消息身份、识别结果及发送状态。区分图片暂不可读、识别失败、
已入队、发送成功和结果未知。用合成消息验证入站过滤、去重及重启恢复。真实验收
由用户从 DarthFalcon 发一张普通测试图片，预期收到一次「否」，且同一 Work
日志出现对应回执。
