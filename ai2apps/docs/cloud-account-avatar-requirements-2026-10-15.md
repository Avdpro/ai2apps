# 账户头像上传与公开空间头像

日期：2026-10-15。状态：方案与 Cloud 接口需求，尚未实现或部署。

## 目标与已核对现状

Account App 支持从本地图片或 Gallery 选择头像，调整裁剪后上传；Cloud 统一存储 300×300 像素头像，各页面以圆形显示，公开空间复用账户头像。

当前 Local `web/templates/system_apps/account.html` 提供 avatarUrl 文本输入；`api/cloud.py` 的 profile PATCH 转发该字段。Cloud `src/profiles/service.ts` 仅校验 HTTPS URL，没有上传及图像规范化。Local 已有 `web/static/js/gallery_picker.js` 可复用。公开空间 schema/render 当前未包含头像。

## 用户流程

1. Account 账户身份区显示圆形头像，无头像或加载失败时显示姓名首字母。公共资料区域提供同一头像编辑入口，替换面向普通用户的 URL 输入框。
2. 点击「更换头像」选择「本地图片」「从 Gallery 选择」；已有头像另提供「移除头像」。Gallery 单选且仅接受可解码的图片，保留原素材不修改。
3. 裁剪窗口固定 1:1，显示圆形预览遮罩；支持拖动图片、缩放滑杆、触屏双指缩放、旋转 90°、重置、取消和「上传并保存」。裁剪范围始终被图片覆盖，不拉伸。
4. 只在确认保存后上传裁剪结果；取消不上传、不修改账户或图库。上传中禁止重复提交，失败保留编辑内容供重试，成功后使用服务器返回的规范 URL 更新显示。
5. 全站头像为同一账户资料，包括 Account 身份区、官网登录账户页、公开空间。公开空间名称与介绍仍遵循草稿/发布机制；头像作为账户身份资料更新，无需重新发布空间正文。尚未设置头像时不阻止空间发布。

## 图像规范

- 产物为 **300×300 方形位图**，圆形仅通过展示层 border-radius:50% + object-fit:cover 实现，不把文件裁成圆形。
- 客户端导出 300×300 PNG；Cloud 不信任客户端 MIME、后缀或声称的尺寸，必须实际解码、验证并重新编码为 300×300 PNG。移除 EXIF/GPS 等元数据，按方向信息规范化后处理。
- 建议上传体积上限 5 MiB、解码像素上限 1600 万；限制宽高及处理资源，拒绝损坏图片、SVG、动画和伪装文件。支持 PNG/JPEG/静态 WebP 输入；非方形直调输入中心裁剪后缩放。客户端正常路径已按用户意图裁剪，服务器不应改变其构图。
- 客户端本地原图建议上限 20 MiB/4000 万像素，解码前尽量检查，超限明确提示。HEIC 仅在当前客户端可以可靠解码并导出 PNG 时支持，否则提示转为 JPEG/PNG，不宣称跨浏览器支持。

## 建议 Cloud 契约（待 Cloud 确认实现）

- `PUT /v1/profile/avatar`：现有认证上下文，multipart/form-data，单个 `file` 字段。服务端仅更新当前用户，不接受任意 ownerId。成功返回完整 UserProfile（含规范 avatarUrl），兼容现有 Local applyProfile。
- `DELETE /v1/profile/avatar`：清除当前用户头像并返回完整 UserProfile，幂等。不得删除他人的资源。
- 原子更新：图像处理、存储成功后再替换资料引用；失败保留旧头像。客户端请求防重复；服务器明确并发更新/冲突语义，避免旧请求覆盖较新头像。
- 建议错误码 `AVATAR_TOO_LARGE`、`AVATAR_INVALID_IMAGE`、`AVATAR_UNSUPPORTED_FORMAT`、`AVATAR_PROCESSING_FAILED`，对应 413/400/415/503；统一现有错误 envelope 与限流规则。
- `avatarUrl` 指向 Cloud 托管的版本化公开头像资源，只包含处理后头像；无令牌、无邮件地址、无本地路径。更换头像使用新 URL 避免缓存旧图，删除/替换后定义旧资源清理与缓存有效期，不承诺回收浏览器已下载副本。
- 头像是公开身份素材，编辑器注明「头像将用于你的账户和公开空间」。不得公开原图、Gallery 文件地址、私人资料或认证凭据。
- 原有外部 avatarUrl PATCH 保持旧客户端兼容；不能被新上传接口自动下载处理，避免任意 URL 服务器抓取。新 UI 不再提供任意 URL 上传途径。旧头像显示失败使用首字母兜底。
- Cloud 公开空间解析/匿名交接需提供最小公开身份投影（建议 ownerAvatarUrl），只能取该空间所属用户当前头像。Local 依赖可信 Cloud 返回值，不接受访客提交头像 URL；确认具体携带位置与刷新方式，避免自行增加签名断言字段破坏现有严格校验器。
- 核对官网与设备空间的 img-src CSP：仅增加正式头像资源源，不增加任意外部图片通配符。保留匿名空间/Owner 应用的现有权限和租约边界。

## Local 后续实现范围

- Account 选图/裁剪组件、圆形展示、上传进度及错误处理、中英文文案。
- 复用 Gallery Picker 与现有拥有者鉴权内容接口，不把 Gallery ID 或原始地址交给 Cloud；选定内容在 Local/客户端完成裁剪，仅上传成品。
- `api/cloud.py` 增加本人头像 PUT/DELETE 转发，复用现有 Cloud 认证；不新增公网上的管理入口，不允许匿名上传。
- 公开空间 bootstrap 加入可信头像投影，前端圆形展示、错误兜底；头像变化与正文 revision 分开更新，不重载正在使用的访客 App。
- 预览与公开渲染使用同一展示组件；正文草稿不存储头像原图或任意 URL。

## 验收及交付顺序

Cloud 先实现上述接口与公开身份投影，返回准确契约及部署回执；Local 再接入实际协议，不使用未部署 URL 假装可上传。

验收包括：本地/Gallery 单选、长宽图裁剪与 EXIF 旋转、触屏拖动缩放、取消零修改、失败重试、透明图片、损坏/超限/动画拒绝、产物精确 300×300 且无元数据、跨账户拒绝、匿名禁止修改、移除兜底、刷新后保留、官网/Account/公开空间同步及 CSP、正文不重发、访客 App 不因头像更新中断。桌面与 iPhone Safari 分别实测。

Cloud 实现由 Cloud 项目完成；本仓库不直接修改 Cloud 代码或生产配置。Local 实施时同步维护 Desktop 发布台账并按固定 App-Dev 开发合同验证。
