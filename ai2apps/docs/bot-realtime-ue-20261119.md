# Bot 实时语音 UE 首版实施与测试

状态：已实现，相关自动化通过，已在固定 AI2Apps-App-Dev 激活；真人麦克风、回声消除、听感和端到端时延待联合验收。没有发布 Desktop，也没有改动 Cloud 或继续使用此前的发布 Cookie 授权。

## 使用入口

在 **AI2Apps-App-Dev → 消息 → AI2Apps Bot → 右侧「语音」→「实时对话」** 配置。
本轮已选本地 Qwen3 ASR 0.6B 4-bit、Qwen3 TTS 1.7B CustomVoice 8-bit，音色 serena。
原有朗读声音配置保持独立。选择框内「安装模型…」复用原 ACPF 的 configure-only
识别/合成能力配置，安装完成重新查询目录，配置保存与麦克风启动分开。

输入区麦克风旁出现「对话模式」按钮。点击后持续收音，左列包含文本框和底部整行操作按钮，右列独立显示状态球；
临时转写在球上方的气泡中原位更新，不改写文字草稿。定稿提交成功后收起。
单次录音入口停用，文字、附件与原发送入口继续可用。点击球静音/恢复麦克风，
「停止播报」只停止声音，球旁关闭按钮结束语音；原任务继续。离开页面会结束语音。

附件默认保留在编辑区；勾选「下一句话附带附件」才与下一次语音定稿绑定。
绑定时冻结客户端已选集合，待上传/解析完成后复用持久输入组；后加文件不会混入。
失败录音/提交保留重试入口，重试使用原话轮 ID；待处理失败时暂停收音，防止无限积压。

## 实现边界

- `messager/realtime.py` 拥有独立声音配置、revision、actor/installation/client-scope/
  主聊天/控制者绑定、45 秒租约和最长一小时预算。一个 Installation/actor 同时只能有
  一个实时语音控制者；不自动夺取其他窗口。
- 最终语音经 `RealtimeInputs` 冻结与附件就绪检查，再进入原 `BotDialogue.submit`。
  幂等回执和任务所有权复用现有实现。语音不是审批接口，也不新增任务规划器或工具旁路。
- 媒体使用现有带身份认证的 `/v1/audio/transcriptions` 和 `/v1/audio/speech`。
  本轮不是原生双工 Worker WebSocket Gateway，浏览器没有拿到 Worker 令牌。
- 首版是连续采集、AudioWorklet、本地断句、分段 ASR 快照和分句 TTS：约 1.6 秒请求一次
  有界临时转写，约 700ms 静音形成候选话轮，最长一段 18 秒。ASR 模型调用本身使用既有
  HTTP 接口，不能把它报告成原生流式 ASR 或 Haru 的任务结果注入。
- ASR 一次只进行一个请求，最终转写优先；积压有界。TTS 一次合成一个片段、至多预备一段，
  队列最多 8 条回复，每条最多播报 80 段，超限提示查看文字；不会把未播完当作已告知。
- 播报来源是聊天中新增的真实 assistant 消息及 owner 投影的待输入状态；关闭、插话和
  静音不会调用任务取消或批准接口。静音不丢弃已经定稿、正在识别的输入。
- 单次录音和实时采集共享 Web Locks/页面内麦克风锁；真实浏览器测试发现的异步释放竞态
  已修复。AudioWorklet URL 随实际 `/admin/static/` 脚本来源解析。
- 声音角色经语音工坊 owner 的临时 `/voice-profiles/{id}/speech` 合成，校验 actor、
  模型和角色更新时间，复用 `render_quick_read` 的准备/调用服务，不为每个句子建立 Studio
  成品历史。普通 Quick Read 及共享 Preview & Output 保存行为保持原状。
- Haru 保留实验后端。当前可靠任务路线不把其未支持的 ASR、工具或事实注入声明为已具备。

## 联合实测

1. 戴耳机，点「对话模式」并允许麦克风；说一个简短任务，核对气泡与聊天最终消息。
2. 在 Bot 工作时打字并上传附件，核对草稿不被转写覆盖；按需勾选下一句话携带附件。
3. 播报时插话，核对声音停止、麦克风继续；分别测试静音和停止播报。
4. 关闭语音，核对采集停止、草稿/附件保留、任务仍继续；需要批准时使用原卡片。

后续仍需量测冷/热启动时延、扬声器回声、噪声断句、长会话、GPU 资源竞争及断网体验。
当前连接/租约失败会停止会话并保留任务，要求显式重新进入；尚未实现透明媒体重连和
服务端播放到达游标。首版不宣称完整原始方案所有阶段已完成。


## 首次真人反馈修正（2026-11-19）

用户确认初步可用，同时指出回合感和状态球位置。已将文本框与按钮行包在同一左列，状态球占据整体右列。桌面与390px浏览器断言检查文本框、按钮行均位于球左侧。20项输入逻辑测试、6项浏览器回归通过；App-Dev仅刷新页面，实际提供的JS/CSS哈希与checkout一致。截图与日志在 `acceptance/bot-realtime-feedback-20261119/`；ASR/TTS仍是测试夹具。

回合感是当前路线的实际限制，本轮尚未解决。原生双工仍需Host受保护的持久音频通道、连续PCM输入输出、播放/插话控制，以及语音侧与原Bot的意图和事实交换。Haru Worker虽能逐帧双向推理，但签名能力明确不支持text_input和async_result_injection，不能直接可靠复述Bot异步执行结果。后续须先验证模型适配与结果回注，再接入Bot UI，并以持续收听、同时发声、任务结果准确性和插话时延作真人验收。


## 回合模式读出开关与Mobile边界（2026-11-19）

保留现有断句ASR→Bot→TTS模式。状态球下新增默认开启的「读出回复」开关；关闭立即中止当前合成和播放、清空待播队列，后续普通回复及待确认提醒均不触发TTS。麦克风、转写、原Bot任务及聊天文字结果继续可用。再开启只读新回复，不补读关闭期间内容。选择保留于当前Bot输入组件，刷新页面后恢复默认开启。

本功能当前尚不支持Mobile：桌面消息Bot页面挂载该组件，实时会话写接口由task_host限制为同源desktop principal。390px Chrome通过只证明窄屏布局，不等于Mobile Shell、签名传输、媒体授权或真机可用；未放宽身份边界。本轮22项逻辑测试和6项浏览器回归通过，App-Dev无活动语音时刷新并核对JS/CSS字节，没有重启Local或录取用户麦克风。证据 `acceptance/bot-realtime-read-toggle-20261119/`。


## Mobile 语音接入（2026-11-19）

本节替代前面“Mobile尚不支持”的历史状态。Mobile消息Bot现在有单次语音输入和对话模式。
单次输入点击麦克风开始/停止（最长30秒），转写追加到草稿，仍由用户发送；失败录音可重试。
对话模式沿用当前断句ASR→原Bot→TTS路线，复用桌面状态球、临时气泡、静音/关闭、读出回复
开关及显式附件选择。关闭读出不会请求TTS；再次开启仅读新回复。文字和附件继续可用。

进入Bot详情的「语音与对话模式」选择已安装的识别、合成模型和音色并应用；原Desktop配置
可直接复用。安装模型仍在Desktop完成。语音配置与既有普通朗读配置独立；读取已有声音角色
且不改变声音选择时保留角色绑定。Flash/快捷工作流不出现Agent对话模式。

媒体经现有Mobile App签名网关，以owner-home principal及原Bot主聊天调用ModelInvocation。
单次上行4MiB/30秒，实时段18秒，播报段4MiB。会话绑定actor/installation/client_scope/Bot/
controller，沿用45秒租约、一小时上限、原RealtimeInputs幂等准入及权限审批；关闭语音不取消任务。
上传音频不创建Voice Studio成品；角色播报复用原临时渲染。没有新增Cloud接口或读取Cookie。
页面离开、后台及连接错误停止采集，不透明重连、不重放任务。

原生iPhone com.ai2apps.ios.dev Build11已使用既有开发签名构建、覆盖安装至原iPhone15Pro并启动，
保留数据。新增麦克风用途说明；仅受信任同源Mobile frame可弹出系统microphone权限请求，camera
和非受信任来源拒绝，不自动grant。HTML权限来自验证后的内置挂载声明，其他App默认禁止。

验收：标准AaAT入口选集61通过、1533未选（非全量）；新增Mobile owner/权限9项最终回归通过；
HTTP安全12通过；共享前端22通过、Voice Studio跨Mini-App选择1通过；真实Chrome的手机原流程、
新语音/设置、桌面共享UE和真实合成音频采集回归通过。新测试的ASR/TTS及手机音频是夹具，
真机收音、权限确认、扬声器回声和时延仍待用户验收。证据在 `acceptance/mobile-bot-voice-20261119/`。

## Mobile 入口、手动读出及无 TTS（2026-11-19）

修正真机反馈：普通 Bot 的电话按钮在未配置时也显示，点击打开并展开同一份语音设置。
每条 AI 回复新增独立「读出 / 停止」按钮，包括历史回复；手动读出不依赖麦克风、ASR 或活动语音会话。
自动读出开关只控制新回复的自动播报，关闭后仍可手动读出。两者复用同一 TTS / 音色 / 临时合成路径，
保持单一播放源；插话、后台和退出停止声音，不取消 Bot 任务，不生成 Voice Studio 输出历史。

语音设置允许只选择 ASR：可以进入对话模式持续输入，读出开关禁用并显示「配置读出」。
没有安装或当前不可用的 TTS 不阻止输入、文字和附件；手动读出引导配置，不反复报错或安装模型。
也允许只选择 TTS：用于回复朗读，电话按钮引导补充 ASR。模型安装仍在 Desktop 完成。

相关 AaAT 选集含语音、图片及共享边界共 74 项通过（1529 未选，非全量），共享输入逻辑 23 项和
Chrome 14 项回归通过；其中 ASR / TTS 为夹具。用户已反馈单次手机语音输入可用；本轮新朗读和配置
行为仍需真机复测。更新由 Dev 自身 Helper 激活，保留现有 iOS Build11，无需重建。
证据 `acceptance/mobile-voice-entry-read-20261119/receipt.json`。
