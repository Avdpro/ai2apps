# 情报中心 v0.1

日期：2026-10-07。App ID：`ai2apps.intelligence`。当前版本为 AI2Apps App-Shell 内置预览 App，不是 Cloud 服务。

## 用户流程

1. 创建频道，填写名称、关注兴趣、排除内容和采集间隔。
2. 手动添加网站/栏目/社交话题，或选择 AI Browser Profile 搜索推荐；AI 推荐只从真实读取的候选网站中选择。Google 跳转链接先由浏览器访问并解析为实际站点；普通媒体默认推荐实际 origin 的主页，社交页面保留观测到的路径。
3. 每个信息源单独保存 `profile_key`，默认 `default`。在信息源“设置”中修改 Profile。Profile 列表和生命周期复用 AI Browser 原有接口，非默认 Profile 保存时按当前 actor 验证所有权。已删除 Profile 不会自动回退。
4. 手动更新，或在页面打开期间按 1/6/12/24 小时间隔更新。重开页面只补一次过期任务。每源每轮读取列表前 3 项，无列表时读取页面正文。
5. 阅读 AI 生成的情报、原始来源、历史版本，标记“多看这类”或“不感兴趣”。下一轮分析带入近期文章与反馈。

## 浏览器与执行边界

- 通过已有 `/client/browser-profiles/{key}/launch` 生命周期入口打开指定用户 Profile 下的专用页面。使用本次唯一的本机静态页面 URL 核对 BiDi getTree 返回的单一 context，并将所有操作显式绑定到该 context；不根据焦点、顺序或窗口标题选取页面。
- 后续所有导航、正文提取、列表提取与页面访问状态判断使用认证 BiDi Gateway 和共享 `AI2AppsPageClient`。不增加浏览器语义 API，不引入 Actor DOM/截图消息，不暴露底层令牌。
- 只关闭本轮创建并绑定的页面。登录/验证码需要用户协助时保留对应 Profile 页面，更新记录说明原因；其他源继续处理。用户完成协助后重新点击更新。
- 当前复用 Web Agent 客户端基础能力，未接入完整自适应 Agent 编排。没有关页后持续执行能力，没有 Cloud 执行、平台关注/发帖、无限滚动和分页。
- 采集入口只允许公开 HTTP(S) URL。没有做 DNS 网络隔离；实际访问由浏览器完成，现有 SDK 会检查导航后的地址。服务端不抓取任意 URL。

## 数据与模型

独立 SQLite：`<instance artifacts>/intelligence/intelligence.sqlite3`，channels/sources/pages/articles/runs 均按 owner 分区。频道运行采用数据库事务认领与 30 秒心跳，失联 10 分钟后标记 interrupted。与 UI 生命周期一致，不伪装成后台服务。

正文空白归一化后 SHA-256 比较，跟踪 URL 移除常见 UTM/fbclid/gclid。一次最多 36 篇、12 万字符送入模型，超预算页面不标记处理，下一轮重试。来源级访问日志独立保存，部分失败显示 partial。生成成功后一次事务提交页面指纹和文章；模型失败不提交指纹。

模型使用已配置的 Standard 路由及既有模型调用服务/进程内聊天入口。最多一次 JSON 修复。文章以纯文本渲染；来源链接与更新文章 ID 必须属于提供的证据和同频道历史。正文引用编号必须对应证据。事件合并与事实筛选依赖模型，尚未保证所有跨语言同事件都能识别。保留最近 5 个历史版本。没有变化时允许 0 篇文章。

## 采集前排除已处理文章

列表页先提取最多 20 个候选，再通过 owner/频道隔离的 pending-pages 接口核对已成功提交的 pages 历史；过滤后才取前 3 个未采集链接打开。忽略 UTM、fbclid、gclid 与 fragment，保留有实际含义的查询参数。成功处理的原始请求地址与重定向后地址均可命中，同一轮其他信息源已读过的 URL 也跳过。现有历史页自动适用，无需重新采集。

日志显示检查数、跳过数与实际读取数。全部候选已采集时不再读取详情，也不把列表页作为新文章提交。无列表的页面型信息源仍比较正文变化。模型失败或超出本轮处理预算的页面不写入成功历史，下一轮继续重试。普通更新不再复查已收录文章的原 URL 内容修订；不同 URL 的后续报道仍可更新现有情报。

## AI 频道栏目

## 网站 WebAgent 编译复用

列表与正文提取规则从真实页面的可见 DOM 区域学习，AI 只能选择观察到的候选区域，不能生成脚本。列表候选先与通用采集确认的文章链接匹配；正文用通用 Readability/DOM 结果的多个文本片段进行比对。通过运行时比对后才激活，校验计数保存到 WebAgent evidence；失败候选不作为可用规则。

复用现有 AgentBuilderRepository、compile_source 和版本记录，不创建第二套编译器。App 管理的提取 Agent 与用户自行编写的站点 Agent 分开选择和维护，避免站点合并改写专用规则。缓存按 owner、规范化信息源 URL（保留功能查询参数）及列表/正文类型隔离，同一用户跨频道的相同源 URL 可复用；运行时仍使用每个信息源指定的 Profile，不保存 Cookie 或凭据。编译器版本改变、代次未激活或规则失效时不走缓存。

共享 BiDi 客户端 SDK 执行限定的 compiled extract_list/read_page 提取规则。实际浏览器导航、稳定性和 Cookie/访问限制检查仍保留。列表区域缺失、文章正文过短或域名变化时回退通用提取，每个信息源每轮每种规则最多尝试学习一次；下一轮可重试。此阶段固化列表和正文区域，不自动学习翻页、滚动或任意点击操作。

更新记录包含规则复用、学习、回退、学习请求次数、列表提取/学习阶段和来源总耗时。学习请求计数不等同底层模型调用次数（一次请求可能包含一次 JSON 修复）。首次学习有额外成本，网页加载及情报整理的模型时间不会因提取规则缓存而消失。

## 频道关联系统知识库

频道创建和设置提供最多 20 个知识库关联，支持选择现有私有/可写本机共享知识库，或通过原有 Knowledge API 新建专用私有知识库。新建即生成系统知识库并勾选，保存频道后才开始同步。共享库明确标示其本机可见范围；每次同步重新检查当前用户的可写范围。

保存关联会补录已有文章，采集完成时自动同步新文章与更新。知识条目包含标题、摘要、正文、频道/栏目、原始来源与 AI 整理说明，使用 artifact 类型和 intelligence.channel/intelligence.article 来源 facets，复用系统 KnowledgeStore 的 FTS、变更记录与索引路径。

文章提交与 knowledge_exports 待同步任务处于同一 Intelligence SQLite 事务。同步按用户/文章/目标库独立保存状态，确定性幂等 ID 包含 installation、actor、scope、source App、文章及目标库；即使知识库写入后进程中断、未能确认队列，重试也不会重复创建。更新在原条目上增加 revision，过期队列确认不能覆盖更新的任务。每次处理最多 50 项，失败自动重试间隔至少 60 秒；页面每 30 秒推进队列，也提供手动重试。关闭页面后未完成队列持久保留，下次打开继续，不承诺独立后台执行。

解除关联只停止该库后续同步，删除频道也不会删除已入库知识。重新关联复用已有条目并同步最新内容。用户主动删除的知识条目不会自动复活，而是记录同步失败以便处理。旧客户端省略 knowledge_bucket_ids 时保留原关联。知识库故障不会回滚已经生成的情报或采集指纹。

验证：66 项 Python、10 项 Node 测试通过，覆盖真实 PlatformDatabase/KnowledgeStore 多库（含私有和共享）、历史补录、自动提交、版本更新、失败隔离、断点重试、删除保护、解除/恢复关联、旧客户端兼容与过期确认防护。固定 app-dev 仅通过标准 Helper 重启 Local，原生标题为 AI2Apps-App-Dev: App-Dev 127.0.0.1:59235；界面新建“腕表情报”私有知识库并关联现有腕表频道，25 篇文章全部补录，待同步 0，系统知识资料库显示 25 项及原始来源。多库/新生成文章/后续版本更新通过集成测试验证，本次实机验收没有额外触发外站采集。未发布。

## 频道右侧栏对话

右侧栏提供“频道对话 / 文章详情”切换，频道操作区也提供对话入口供窄屏打开。对话依据当前频道已采集的文章回答，支持摘要、比较和上下文追问；选中文章后优先提供该文作为上下文。引用由服务端从当前证据映射为文章 ID 和标题，点击打开对应文章详情，再切回对话继续提问。正文、问题和引用标题均按纯文本转义显示。

沿用 Standard 工作模型和现有模型调用服务。中文二元词/英文词匹配加更新时间排序，最多选 20 篇文章、8 万字符，每篇正文最多 8000 字符；带入最近 8 轮对话（每轮回答最多 4000 字符）。提示明确资料为选取的子集，不能声称实时浏览或穷尽频道全部资料；区分事实与推断、入库时间与事件日期，资料不足时说明。空频道直接提示先采集，不调用模型。首版对话依据频道文章，不扩展到关联知识库内的其他资料。

conversations 表按 owner、channel、request ID 保存完整成功问答，界面展示最近 100 轮；重复提交同一请求返回已有结果，不重复计费调用模型/写入。失败保留界面问题供重试，不保存不完整问答；同频道在当前 Local 进程内串行回答，不同频道互不混用。切换频道时草稿、等待状态和答案各自独立。频道删除后不能由迟到回答恢复，删除频道同时删除其对话。无独立聊天删除入口；输入草稿只在当前页面生命周期保留。
