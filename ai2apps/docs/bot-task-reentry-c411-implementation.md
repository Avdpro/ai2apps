# Bot 任务级依赖与合理重入 C4.1.1

日期：2026-11-04。C4.1.1 用独立工作项的等待关系替代按 Bot 身份防环，允许研究 Bot 在主课题下再次处理一个独立子课题。相同 Bot、AaAT 或模型身份再次出现，都不单独构成循环。审批、权限交集、预算和实际执行仍复用 C4.1，当前验收状态见文末。

C4.1.2 对联系授权的后续调整见[Bot 暴露等级与使用授权](bot-exposure-access-c412-implementation.md)；工作项防环与上下文隔离继续沿用本阶段。

## 工作项和执行槽位

每次委派创建独立的子工作项，接收者可以是当前 Bot 或祖先使用过的 Bot。主课题和子课题分别拥有 Task-Session 与 Worker Session，只共享明确提交的说明与预期产物，不自动导入主对话、私人记忆或其他任务历史。恢复父任务时保留原会话。同对话子任务通过持久结果回接展示一次，避免子任务完成和父任务接收时重复贴出同一结果；子任务的独立记录和产物仍保留。

父任务在委派检查点结束当前轮次，释放原 Bot 的串行执行槽位，然后等待子工作项。批准过早时，子任务排队等当前轮次释放；不会抢占或并发执行同一 Bot 的两个 Task。子课题完成后按依赖次序恢复父任务。等待期间普通对话仍可进行。

例如，研究 Bot 的“主课题”可以等待同一 Bot 的“子课题”；A 的主任务也可以通过 B 再委派 A 处理不同子题。它们是不同工作项，不因 Bot 身份相同被拒绝。不同 root 使用相同的两个 Bot，甚至方向相反，也不会仅据此被拒绝。

Bot目录现在包含当前Bot，明确标记可创建独立子任务，但不可向自己发起文本咨询。目录仅提供稳定身份，不授予执行或资料访问权限。声明版本守卫继续生效，旧审批不会静默升级为新的重入授权。

## 实际等待环

新增宿主表 `messager_delegation_work`，绑定委派边、源工作项、目标工作项和内容指纹。根任务以逻辑 Task-Session 标识，子工作项以稳定委派标识命名；子任务的后续执行继续映射到同一工作项。Bot、Tool、模型身份不作为依赖图节点。

新增依赖前，在同 actor 的活动任务等待图中检查目标能否到达源；能到达则说明实际任务形成环，拒绝并指出发生关系的工作项。检查与新边持久化在同一准入事务内完成。预算耗尽、原任务停止和权限变化使用各自原因，不标成循环。

当前委派接口总是创建独立子工作项，不提供任意挂接已有任务的参数。因此正常委派本身保持树结构；等待图守卫继续防止宿主接线或恢复时产生自等待和反向等待，不能通过模型伪造目标任务引用。旧 C2/C4.1 记录按原 parent/child 关系派生工作项节点，不改写其原审阅内容或授予新权限。

## 重复工作与有限递归

同一次 invocation 的重放仍使用原收据。跨 invocation 的工作识别以同 root、同源工作项和内容指纹为范围；不再用“同目标 Bot 加相同说明”合并整条协作链中的工作。

指纹包含目标 Bot、完整任务说明、预期产物、源任务已绑定输入文件，以及本轮已有协作结果引用。`messager.bot.delegate` 新增可选 `deliverable`，要求执行 Bot 明确子题的产物目标。改标题不改变工作身份，输入材料或预期产物不同则能区分。输入引用和说明不授予读取或执行权限，委派仍不自动传输文件。

同一依赖分支把完全相同的目标、说明、输入和产物再次委派，宿主拒绝原样重复分解，并要求明确子题、输入或产物差异。这是精确内容检查，不声称能够判断自然语言是否取得研究进展。近似表述、缩小范围是否有意义由 Bot 解释与用户审阅；改写说明也不能取得新的根预算。

同一 AaAT 用不同参数执行多次仍允许，每次真实调用扣原共享额度。原 invocation 去重负责防止重放同一次效果；没有新增按 Tool 名称拒绝嵌套调用的规则。C4.1 的 3 层、8 边、8 份单轮基础 tokens 保守预留（新协作每份 64,000）、36 次 Tool 调用和 600 秒期限继续适用。

## 用户反馈与审批

委派回执明确哪个 Bot 将处理哪项独立子任务，以及原任务正在等待什么。审阅卡显示任务说明和预期产物，说明同 Bot 可以处理独立任务。新增委派仍在最初 Bot 的原对话逐项确认；下级运行中的必要输入、付费、敏感和特殊操作继续回接同一实际 Run/Interaction。

权限继续取全部祖先已批准范围与当前双方权限的交集。允许同 Bot 重入不允许借用其另一个任务的权限，也不自动共享记忆。C3 固定事件/定时计划仍不能递归扩展参与者，Event/Hook 的因果 root、同规则重入限制和配额保持原契约。
