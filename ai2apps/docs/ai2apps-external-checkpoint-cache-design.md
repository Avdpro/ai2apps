# AI2Apps 外置 Checkpoint 缓存技术方案

状态：设计已确认，待实现和验收。第一版覆盖 macOS Desktop 的 Registry Checkpoint，沿用现有 Package、签名清单和 Cloud 接口。

## 目标与现状

同一台 Mac、同一 macOS 用户的 AI2Apps 实例共用一组 Checkpoint 缓存位置。设置可添加多个外置目录，其中恰好一个位置为 Primary（默认下载位置）。同一份已验证权重可被多个实例直接读取。模型配置、安装记录和可写的准备产物继续由实例分别持有。

当前 `LocalLaunchPlan` 把各实例指向同一个内置 `checkpoint-cache-v1`，同时保留实例私有的 Hugging Face Hub 目录。`CheckpointAcquisitionService` 从共享池取回已验证快照，再在实例目录中为 Worker 创建视图。`CheckpointCache.materialize_snapshot_view()` 遇到跨文件系统硬链接失败时会复制文件。因此只增加一个下载目录仍可能在内置盘产生完整副本。本次需要同时修改下载位置选择、Local 的模型状态解析和 Worker 的权重路径注入。

## 共享配置与磁盘身份

- 在同一用户的 AI2Apps Application Support 共享区保存带版本的配置。内置位置默认可用，仍指向 `~/Library/Caches/AI2Apps/shared/checkpoint-cache-v1`；首次升级时它就是 Primary，原缓存原地使用。每个外置位置保存稳定 `location_id`、显示名称、卷标识以及卷内相对路径。当前挂载路径由 Local 根据卷标识解析，重插后允许挂载路径变化。拒绝重复位置、嵌套缓存根和无法可靠识别的卷。
- Settings 通过 Local 的受信任管理入口读写共享配置。配置更新使用跨进程锁和原子替换，其他实例在下次状态刷新或开始任务时读取最新版本。普通 Package 无权新增缓存根或指定任意读取路径。添加目录时确认卷已挂载、当前用户有权限，并校验受管子目录不会通过符号链接逃逸或落到系统盘。每个位置内部复用 `CheckpointCache` 的 `blobs`、`snapshots`、`partial` 和 `manifests` 布局。
- 界面展示卷名、路径、在线状态、是否可写、可用空间和 Primary 标记。保留轻量的位置索引，记录某个分发版本曾在哪些位置发布成功，用于解释离线状态。索引只提供位置线索，就绪状态仍由 Local 根据卷身份、签名清单和实际文件判定。

## 查找、下载与并发

1. 先取得并验证 Registry 的分发清单，沿用现有许可确认要求。缓存匹配基于分发 ID、清单摘要和签名所绑定的文件，而不是模型显示名称。
2. 使用内置共享位置上的分发锁协调所有实例。锁的位置独立于 Primary；锁键沿用分发 ID 与清单摘要。拿到锁后重查所有在线位置。优先使用当前安装绑定仍有效的快照，再按确定顺序查找其他位置。命中后直接在原位置使用；损坏条目不算命中。可兼容已有内置缓存和现有旧缓存的验证导入流程。
3. 缓存未命中时，选择任务开始时的 Primary，检查卷身份、写权限和可用空间。下载片段、断点记录、校验和发布都在同一卷完成，验证后才原子发布快照并更新位置索引。等待同一分发锁的实例在拿锁后可以看到已经发布的结果。
4. 下载任务记录目标位置和清单摘要。切换 Primary 只影响之后开始的新下载，已开始的任务和显式续传仍使用原位置。任务恢复前确认磁盘身份与断点记录；如需在另一块盘重新下载，由用户明确发起。等待锁可取消，进程退出后由系统释放锁，片段继续保存在原位置。

Primary 离线、只读、空间不足或写入失败时，提示连接磁盘、释放空间或切换 Primary。无提示回退会把大模型写到出乎预期的位置，因此下载流程应停在可恢复状态。若唯一已知副本在离线盘，显示「请连接该磁盘」；原盘无法找回时，允许用户主动确认在当前 Primary 重新下载。

## Worker 读取与准备产物

- 对 Registry 权重，由 Local 解析并验证快照真实路径，再向 Worker 传递精确的只读快照目录。绑定至少包含位置 ID、分发 ID 和清单摘要，可以在卷重新挂载后重新解析。授权边界保持在具体快照，外置卷根和其他模型不因此开放。启动或恢复时重新确认卷身份与路径约束，并使用现有验证凭据的有效性检查，变化时走原有校验流程。
- 更新安装、Model Manager 就绪状态和 Worker 启动，使它们使用同一套解析结果。现有实例视图继续兼容，包括旧版本生成的本地准备元数据。外置 Registry 快照走直接读取路径，避免调用跨卷复制的旧分支。没有 Registry 分发声明的旧模型沿用原路径。
- 可写配置、缓存与准备元数据留在实例控制下。需要生成大体积专家文件或重新布局的准备方案，实施时逐个审查：优先读取签名快照中已存在的布局；确需写入大型产物时，使用该外置卷上独立的实例私有目录，并计入空间预检。不得修改共享快照。无法满足只读源与实例私有产物约束的准备方案需要在外置安装前给出明确状态，完成专项验收后才开放。
- 推理或准备期间掉盘，受影响任务显示磁盘离线或 I/O 失败，原有安装记录保留。重新连接后重新验证位置与快照，允许重试或续传。运行中的 Worker 不切换到另一份权重，也不自动触发下载。

## 升级、移除与回退

- 加入位置和切换 Primary 都不自动搬迁数据。第一版不要求提供迁移界面。未来若加入搬迁，先确认目标空间，复制到目标卷并完整校验，原子发布后才更新引用，原副本由用户随后清理。
- 从设置移除位置只解除注册。当前下载使用的位置应先完成或取消；已有模型若依赖该位置，操作前展示影响，移除后可通过重新添加或另一份已验证副本恢复。实例重置只清理该实例的私有状态，并保留共享配置、内置缓存和外置共享缓存。
- 默认内置缓存保留原目录格式。回退到旧版时仍可读取旧版原本认识的内置权重；外置独有的权重需要支持本方案的客户端。混合版本验收要确认，支持本方案的实例共用同一把锁，旧版客户端仍按原规则处理内置缓存和实例视图。

## 实施与验收

先完成共享配置、卷身份验证和多位置获取，再接通统一就绪状态与 Worker 只读路径，最后接 Settings 和磁盘异常提示。在两个隔离的开发实例上完成实际外置 SSD 验收，之后再进入发布评估。

| 场景 | 通过条件 |
| --- | --- |
| 升级后未添加外置盘 | 内置位置自动成为 Primary；原有权重与安装记录仍可用。 |
| SSD A 和 SSD B 都可用 | A 上已有的权重原地复用；B 成为 Primary 后，新模型及其断点写到 B。在途任务保持原目标。 |
| 两个实例同时安装同一分发 | 只发生一次联网下载；两个 Worker 解析到同一只读快照。确认系统盘没有新增完整权重副本。 |
| 拔盘、同名异盘、重新挂载 | 掉线后显示具体位置；同名异盘不会命中绑定；原卷换挂载路径后可恢复。覆盖下载中、已安装和推理中掉线。 |
| Primary 空间不足、权限失效或无法写入 | 错误指出目标位置；任务可恢复；系统盘不会出现替代下载。 |
| 残缺、篡改或错误版本 | 不被标为就绪，不向 Worker 授权；保留现有签名、许可和路径边界检查。 |
| Cached-MoE 真机专项 | 至少验证一个实际的 SSD 专用 Checkpoint，覆盖准备、首次推理和重启后加载。记录 Worker 路径、准备产物位置、两块盘的实际分配空间和首轮推理表现；系统盘没有新增完整权重副本。 |
| 单实例重置 | 共享配置和外置权重保留，另一实例仍能运行模型。 |

验收记录应包含构建版本、两个实例 ID、卷和快照位置、下载来源统计、各卷实际空间变化以及失败恢复结果。测试比较物理分配空间与实际读路径，不能只用目录显示大小判断是否产生了副本。
