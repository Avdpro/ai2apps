# Bot 暴露等级与使用授权 C4.1.2

日期：2026-11-04。Bot 以 Public 或 Private 控制发现，以一条有方向的使用授权控制咨询和委派。Access 与目标 Bot 的白名单是同一条授权关系的两个视图，不存在 Bot 的 Read/Write 两级权限。本阶段适用于当前安装、同一用户拥有的 Bot；不扩展跨用户或跨安装通信。

## 发现和使用

| 目标 Bot 状态 | 调用方能否发现 | 普通咨询和委派 |
| --- | --- | --- |
| Public，尚未授权 | 可以 | 首次申请由用户批准 |
| Private，尚未授权 | 不可以 | 不可调用，知道旧 ID 也不能绕过 |
| 任意模式，已授权 | 可以 | 无需重复联系审批 |

新建和已有 Bot 默认为 Public，除非用户明确设为 Private。用户所有者的管理选择器可以列出其 Private Bot，以便手动配置；Agent 目录严格按调用 Bot 身份过滤。Private 未授权目标与不存在的目标统一返回不可用，不通过错误详情泄露当前身份。

自己默认可用于独立子任务，使用隐式自访问，不创建白名单条目。文本咨询仍不能向自己递归提问。同 Bot 重入继续遵守 C4.1.1 的独立上下文、任务等待图和根预算。

## 单向授权与双视图

A 使用 B 对应唯一关系 `owner / source=A / target=B / enabled / revision`。它不授予 B 使用 A 的权限。

| 用户操作 | A 的 Access 中的 B | B 的允许使用者 |
| --- | --- | --- |
| A 手动添加 B | 出现且开启 | 自动加入 A |
| 在 B 中添加允许使用者 A | 自动出现且开启 | 出现 A |
| 在 A 中关闭 B | 条目保留且关闭 | 移除 A |
| 从 B 中移除 A | 条目保留且关闭 | 移除 A |
| 在 A 中重新开启 B | 开启 | 自动加入 A |

开关只是可使用/不可使用，不附带只读状态。关闭条目保留，以便所有者重新开启；它不保留 Agent 的发现或调用权限。Public 撤权后仍能发现，下一次联系重新申请；Private 撤权后不能发现或调用。模式切换不撤销已有授权。

配置写入使用用户级管理 revision 防止两个视图互相覆盖。每条使用关系独立增加执行 epoch，UI 的全局编辑冲突不会无故撤销其他关系。修改关系后，旧待审阅/活动执行停止；重新允许不会恢复其旧凭证。无变化的幂等配置不会停止正在执行的任务。

## 首次批准和后续执行

未获使用权的 Public 联系请求先保存审阅卡。用户批准时同时建立长期使用授权和本次调用的准入收据；卡片明确显示调用方、目标及长期授权含义。后续普通咨询和委派使用当前授权直接准入，仍保存独立任务、执行凭证和状态回执。

授权按实际调用方保存。例如 A 委派 B 后，B 请求 C，原 A 对话中的批准建立的是 B→C，卡片显示 B 为调用方，不冒充 A。已经具备 B→C 时不再询问联系许可。允许下级继续分工仍受原任务范围、委派控制、逐层业务权限和共享额度约束。

使用权不授予目标 Bot 的私人历史、记忆或 App 权限。实际执行继续取原任务与接收方已批准能力的交集；付费、敏感、特殊声明和必需输入保留原持久 Interaction。使用权不替代定时、Event/Hook 的后台授权。

固定 C3 计划仍须审阅。确认所列参与者的计划时，一并建立发起 Bot 到参与者的使用授权，并冻结各关系 revision；后续批次校验这些收据。旧计划和执行没有新收据时默认拒绝，不从历史参与者或旧授权推断长期使用权。

## 撤销与恢复

准入收据绑定类型、请求/计划、owner、实际 source/target 和关系 revision。每次咨询执行、委派能力检查、父任务恢复和 C3 批次都复核它。撤销先持久更新 epoch，再取消相关执行；即使清理中断，旧执行也不能越过守卫。恢复检查沿用原收据，不把新授权套到旧执行上。

关闭一条关系只影响使用该关系的咨询、委派及其协作树。其他 Bot 使用关系保持独立。重新开启产生新 epoch，新的请求可以使用，旧请求仍失效。切换 Private 会停止尚未授权的 Public 待审阅请求，保留已经获准的使用者。

## 接口与数据

Messager owner 服务 `BotUseAccess` 管理四张宿主表：`messager_bot_exposure`、`messager_bot_use_state`、`messager_bot_use`、`messager_bot_use_receipts`。用户设置与 Agent 发现分开；两者共用使用权判定，模型不能提交白名单或批准标志为自己授权。

桌面所有者管理接口：

- `GET /messager/bots/{id}/bot-access`：暴露模式、Access、允许使用者和管理候选。
- `PUT .../bot-access/exposure`：revision 与 public/private。
- `PUT .../bot-access/targets/{target}`：revision 与 enabled。
- `PUT .../bot-access/callers/{source}`：同一关系的入站视图。

写入必须通过现有同源 Desktop 管理守卫。Agent 的 `messager.bot.directory` 依据真实 Run 的 Bot 身份过滤；普通咨询和委派入口不接收由模型指定的调用方或管理授权。没有新增 App/Package 绕过用户管理接口的能力。
