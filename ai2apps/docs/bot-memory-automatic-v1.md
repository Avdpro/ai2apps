# Bot 自动记忆、维护 Task 与按需召回 v1

日期：2026-11-04。继 [M1/M2 核心](bot-memory-history-m12-implementation.md) 继续实现完整日常链路；[总计划](bot-memory-and-history-plan-v1.md) 保留后续范围。

## 触发与成本

Bot 的现有轻量对话判断同时返回最多 3 个结构化候选，不为每条消息另开一个“记忆分析”模型。明确记住、以后称呼/使用的要求可排队；当前输入中的图片如果直接回答了一个真实且无中间用户消息的已知问题，可以绑定其用途。任意图片不能自动被认定为用户本人。来源必须是同一 actor/Bot 主对话中真实、未失效的用户消息及已选择附件，不能来自 Bot 通信、工具正文或记忆提示。

低确定性内容作为 review 候选，不自动写入；用户可在“待整理记忆”中确认或取消。临时扮演不修改默认偏好；不同照片可用 variant 表示用途/备选，不能自动切换默认照片。用户明确要求时，也可记住主对话或历史召回中已验证的确切输出 Artifact；模型自报的未知 ID 不可作为资源。

确定性维护不调用模型，也不再次分析图片。每 Bot 最多 24 个待处理候选，每批最多 8 项，单个自动记忆资源最多 16 MiB。超限或来源/版本不明确时不猜测、不覆盖，保留待核对状态并提示。

每轮只额外提供最多 16 条短记忆索引、6 个最近输出引用和少量问题身份。缺少旧事实/任务时，模型可以请求一次 recall；宿主查本 Bot 的有效记忆及分页历史，返回至多 8 条记忆、5 个历史任务和 8 个带步骤说明的产物引用，允许一次最终判断。没有后台全库语义扫描、嵌入或额外视觉模型。

成本接口区分：维护模型调用数（0）、按需召回轮次、加入 Context 的字符数、提供商已报告的对话总 Token。没有精确分摊记忆增量 Token 时返回 null，不把整轮 Token 误称为记忆成本，也不把复用模型回合说成零 Token 开销。每个对话模型回合仍沿原输出/总 Token 预算。

## 独立维护 Task

候选先持久化，再由 Messager owner 注册的 TodoExecutionAdapter 创建真实 managed Todo Task 和绑定的 AgentRun，使用原 Bot 串行 lane。维护执行器只处理该固定批次，不能发现或调用业务 AaAT，不继承 Bot 的 App Access；伪造一个 Run 不能处理别人的批次。

Todo 执行适配器可声明受信任的 normal/maintenance 类别。类别不来自 TaskInput、模型 priority 或数据库中用户可控的附加属性。已占用 lane 不被抢占，包含等待参数/审批的任务。空闲后优先维护；最多连续 2 个维护批次，有普通任务已等待 60 秒时优先普通任务。普通任务之间维持原顺序，不影响其他 owner/lane。

维护数据准备和文件复制在线程中执行，不占用前台事件循环或长时间持有聊天锁。写入只在短事务中复核来源、当前候选、取消和版本。批次身份、候选集合、请求键均持久化；记忆变更和候选 applied 状态在同一事务提交。提交后通知按原稳定回执恢复，不重复副作用。

若服务停在“Todo 已领取但维护 Run 尚未创建”的间隙，受信任 restore 回调只可重排确实未启动的片段；存在实际 AgentRun 的工作只能恢复原 Run，不能当作未执行重试。恢复不会授予额外权限。

## 用户反馈与执行快照

来源消息可显示“记忆待整理 · 查看/取消”。真正提交后使用 M2 的“已记住/已合并/已更新”回执以及查看/撤销入口。不确定或失效的内容说明尚未保存，引导核对，而不是假报成功。记忆整理期间输入框可用，用户可以继续直接问答或安排普通任务。

对话判断可选择最多 4 个已观察记忆 ID 和 revision。执行任务准入时复核，按需把已保存的照片等导入该执行 Session，提供标准 Artifact 身份。等待期间变更/遗忘/素材失效会拒绝旧选择，不静默改用另一张图。已准入任务保留原快照，不在执行中替换记忆或修改已审阅定时计划。Bot 通信、委派、计费、敏感操作和 App Access 守卫继续独立生效。

## 遗忘与来源隔离

清除记忆建立 epoch 和来源消息水位，取消旧候选；清除/归档/恢复对话也使旧候选失效，但不删除仍保留的有效长期记忆。旧对话即使恢复，也不能重新提炼旧记忆。撤销/取消单项贡献按“来源 + 字段/用途”封锁，不影响同一条消息里的其他独立事实，也不删除其他来源证据。

用户后来重新明确提供事实或直接回答已知问题，可用新的有效来源建立新记录；不复活旧来源。被后来新记录占用的字段，旧撤销和旧条目恢复不能覆盖。素材留存与任务审计仍遵守原 owner 的保留规则；忘记关联不等于删除共享图片或撤回已完成任务。

## 当前范围

已实现明确请求、可核验的主对话问答候选、确定性去重/替换、候选确认/取消、独立维护队列、来源水位、短索引/按需召回和执行资源快照。普通对话的低确定性候选需用户确认，没有独立语义合并模型。

通用 App 参数表单/审批的任意响应不会被自动解释为长期记忆；必须具有 owner 的明确来源和语义绑定。没有批量回溯旧对话、视觉身份推断、向量检索、完整图片编辑谱系，也没有把所有生成物自动加入记忆。手工便签和原用户确认配置入口仍兼容。

验证使用真实 SQLite、Todo、AgentRuntime 和工作区，模型与媒体内容为夹具；真实客户端仅做只读界面验收，不修改用户记忆。完整门禁 1114 项通过，最终 owner 27 项、对话流程 25 项及界面 4 项通过；App-Dev 已加载并只读验收。Dev 因活动任务保留运行，最终补充待空闲后加载。详见 [验收记录](acceptance/bot-memory-automatic-20261104/README.md)。
