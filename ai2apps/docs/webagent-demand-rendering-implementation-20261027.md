# WebAgent 按需后台渲染与输入实施计划

日期：2026-10-27。状态：P1–P3 已实现并完成本轮 App-Dev 验收；P4 同机对照完成，内存增长门槛未通过，完整验收暂缓，现有渲染保障保持开启。

## 目标与约束

默认导航、网络加载、DOM/Readability 读取不主动激活窗口，不永久申请强制渲染。布局、截图、原生输入分别获得最小运行条件；等待模型、网络或人工辅助时释放不必要资源。保护 Task/actor/Profile/context/scope、原有授权和确认边界。定位修复不能修改业务操作或参数；不确定输入禁止自动重放。不加入网站或 Mini-App 名称分支，不伪造 visibilityState 或修改网页样式。

继续使用原生 WebDriver BiDi 和现有认证 Gateway。不建立业务 REST 浏览器协议或 JSWindowActor 操作通道。原生支持尚未完成前，保留现有可工作的宿主策略，不把 Python 资源计数冒称原生渲染租约。

## 已核对基线

- Launcher/Helper 固定设置 BACKGROUND_HOST=1；Gecko 的 macOS 窗口遮挡处理按进程标记保持渲染。不是页面级租约，也不表示所有标签满速绘制。
- pointer_to、scroll 调用 activate_for_input；后者按需 unhide，并调用 browsingContext.activate，尚无最小化激活策略或系统前台激活次数记录。
- 同 owner/Profile 的原生输入由可重入 InputLock 串行。VisualControlRecovery 目前将 locate、模型复核、派发、回读、操作后模型判断全部置于该锁中。
- NativeInputNotDispatched 与不确定执行日志已存在，但统一派发边界、自动恢复和诊断仍不完整。等待人工辅助已有 admission_paused；不是渲染资源释放。
- 既有锁屏 fixture 只证明特定输入成功，不证明能耗、无焦点或资源回收达标。

## P1：缩短视觉输入临界区（本轮实施）

1. 定位、红框复核模型调用在输入锁外执行。
2. 模型返回后获取原有 Profile 锁；在锁内重新验证 context、scope、文档token、URL、viewport/scroll、目标身份/几何、可见性、命中测试和 owner preflight。
3. 只派发一次操作；锁内执行 owner DOM 回读并冻结操作后 DOM/截图。释放锁后，对冻结证据做模型判断；不得稍后把别的任务产生的状态混进该操作证据。
4. 同页在模型等待期间变化时拒绝旧目标，不直接点击、不重新执行未知操作。Profile 锁继续保护点击/输入组合、回读及证据采集。
5. 成功、异常、取消、模型失败均退出锁；日志只记录 run/context、等待/持锁耗时及派发状态，不记录正文、输入值、图片或凭据。
6. 增加任意 Provider 的并发屏障测试：模型等待时其它任务可取得同一锁；原生输入和回读期间不可；旧绑定、owner条件变化、回执丢失、取消路径保持安全。

P1 不宣称无前台激活或按需渲染已实现。验收：相关视觉/DOM修复/购物所有权测试、真实SQLite调度相关测试及完整 AaAT 边界门禁通过；检查空闲实例后以标准 Helper 激活，保留无关活动任务。

## P2：输入派发与焦点诊断

统一 pointer/key/wheel 的 pre-dispatch、dispatched、acknowledged、readback 状态；输入前失败只在既有预算内恢复，派发后不确定只回读。记录窗口恢复、标签激活与真实系统前台激活（不得把调用 activate 直接当作系统前台次数）。先验证原生定向输入的能力边界，再改变激活策略；不盲目删除可用性保障。

验收：准备失败零输入、断线零重放、正确Profile/页面输入、取消安全；普通文章、动态列表、复杂表单均覆盖。

## P3：原生按需渲染能力与资源调度

先对现有 AceFox/Gecko BiDi 原生扩展点做能力探针和协议设计评审。租约绑定实例/宿主/Task/顶层context，包含 layout/capture/input、持有者、引用计数、期限、实际作用范围。优先页面级；原生只能窗口级时如实记录窗口级，不用名称掩盖实际范围。

租约在 finally 释放；原生端处理连接断开、context销毁、Task取消和过期回收。截图冻结后释放 capture 资源，模型等待期间不持有。内容读取、合成、原生输入分别调度。不得只实现 Local 字典而继续依赖永久忽略遮挡，或在原生支持缺失时冒称资源可回收。

验收：嵌套、到期、断线、失败、取消、人工暂停均无遗留；跨实例/Profile隔离；权限与业务确认不因租约改变。

## P4：同机基准与逐步替换

在相同页面集合、并发、账户状态和观察时长下，对照默认后台、现有永久保持渲染、按需租约三组。覆盖普通文章、动态搜索列表、复杂表单，以及行程查询。记录 CPU/GPU、内存、能耗、耗时、租约持有时间和真实前台激活次数，保留原始结果与环境/源码版本。先形成同机基线，再确定阈值。

验收：任务结束后资源接近默认后台，不随累计处理页面数持续增长；正确输入、无重复副作用、无跨实例干扰。通过后才撤掉常态 BACKGROUND_HOST 忽略遮挡依赖，按标准构建器重建隔离实例并验证真实运行路径。

## 回退与交付记录

## P2 本轮实施范围

统一本地 SDK pointer/key/wheel 的保守派发边界，覆盖组合输入和多命令部分执行；保持已有 journal 的禁止未知操作重放。把诊断挂到已有动作回执，不记录输入值。传输层只有确定未开始发送才报告 false；发送期间断线按可能已派发处理。

先以原生隔离夹具验证可见但无页面焦点的定向输入，验证通过后才跳过冗余 activate。隐藏页保留有界 unhide/activate 与真实可见性核对。记录协议恢复/激活请求与页面焦点，不把它当系统前台切换；原生系统前台传感能力缺失时明确 unknown。普通读取不启用焦点准备，不改变情报读取预算、提取和访问限制策略。原生渲染租约仍属 P3。

## P3 本轮实施范围（2026-10-27）

新增受保护 BiDi 的原生窗口租约，真实 macOS widget 引用计数参与遮挡计算；获取/释放均重新计算，不调用窗口恢复、标签选择或系统焦点操作。作用范围明确为原生窗口，同窗标签共享条件，不冒称页面隔离。现有 BACKGROUND_HOST/agent 永久保障保持不变，P4 验收之前不撤除。

SDK 默认正文/DOM读取不获取租约；视觉与封面/社交补图截图在实际采集时获取 capture，冻结后释放；pointer/key/wheel 与既有 bulk editor 在原有 Profile 串行锁内获取 input。截图每宿主并发2，与内容读取额度分离。相同协程/context/用途嵌套引用，不误释放外层；长输入20秒续期，原生最长60秒到期。归属由实例私有认证连接、Task归因及明确顶层context组成，租约不新增访问或输入权限。

已实现原生到期、context销毁、会话销毁、连接关闭清理，并处理获取回执与连接关闭竞态。连接只回收自身租约，不结束共享 BiDi 会话。SDK finally/取消/人工暂停退出时释放已知句柄；丢失获取/释放回执按未确认记录，原生连接清理及TTL兜底，不重放内容操作。旧引擎明确报告不支持，保持已有策略，不能报告原生租约成功。

原生补丁与协议见 [native_rendering](../browser/native_rendering/README.md)。单元/协议和真实原生验收结果另见 [P3验收](acceptance/webagent-native-rendering-20261027/README.md)。本轮不宣称节能、后台默认节流已恢复、系统前台零切换或所有真实网站无焦点成功。
