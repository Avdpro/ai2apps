# 访客空间开发计划

## 产品与范围
内置 ai2apps.visitor-space，设备 Owner 在本机管理：默认关闭；编辑名称、简介、文字/链接/App 卡片及顺序；草稿与发布快照分离；手机/桌面预览；固定账户 URL 与二维码。Owner Mobile 开关不授予访客权限。

## 匿名访问要求（2026-10-09 修订）
访客无需 AI2Apps 账户或登录；开启空间表示允许任何持有链接的人访问已发布内容和显式开放的 Open-Entry。Owner 私有应用与管理仍要求登录授权。现有登录访客协议尚不满足这一要求；Cloud 匿名交接协议与客户端严格验证待接入，见 cloud-visitor-space-requirements-2026-10-09.md。

## 实施顺序
1. 持久化安装绑定的配置、草稿、发布版本和访问撤销代次，乐观锁防止覆盖。
2. 本机 Owner 管理 API 与系统 App；复用公开主页渲染器预览，预览不产生访客凭证。
3. 访客 bootstrap 只返回发布快照，关闭立即拒绝后续请求并撤销当前访客会话。
4. 独立 sandbox Open-Entry：只服务已发布卡片对应、摘要锁定、显式声明 open_entry 的签名 App 静态资源。无 Owner principal、无内部挂载、无宿主 API 权限；每次请求核对访客/设备/发布版本。新版本必须重新发布。
5. 访问期内轮询状态；过期清空内容并提供固定账户入口。不将 120 秒访问凭证私自延长。Cloud 长会话及新资源路由通过独立需求交接。
6. 针对权限、草稿泄漏、关闭/重开旧会话、版本冲突、路径穿越和资源摘要做测试；记录 Desktop 台账。

## MVP 边界
第一版 App 只接受纯静态、零后端权限的 Open-Entry。贪吃蛇需另一个显式声明 Open-Entry 的 Package 更新；不自动把所有 Mobile App 公布。动态模型/文件/工具调用属于后续经授权能力，不复用 Owner Bridge。
Cloud 尚未部署的新资源通道不标记就绪；UI 明示限制，允许先发布文字与链接。图片封面暂用内置主题，无外部图片追踪。

## 验收
Owner 可保存草稿且访客不可见；发布后访客见新快照；关闭后页面/资源失效，重开不恢复旧凭证。非 Owner 不可编辑；访客不能通过 URL 访问管理 API。预览不执行 App，只显示同样的卡片布局。移动窄屏和桌面都可编辑/预览。

## 实施状态
本地实现与独立 App-Dev UI 验收完成，55 项 Python 与 2 项共享预览 Node 测试通过；贪吃蛇 1.0.2 访客入口源码已准备。Cloud 新通道、长会话、签名 Package 发布与公网 iPhone 验收仍待完成。具体结果见 visitor-space-implementation-2026-10-09.md。

## 下一阶段：持续匿名浏览
用户已批准解决每 120 秒中断问题。采用一次性交接 + 匿名会话 + 可续租短租约，正常前台浏览维持会话，关闭空间即时拒绝。Cloud 合同需求见 cloud-anonymous-visitor-session-lease-requirements-2026-10-09.md；不延长旧断言、不通过自动重新交接规避过期。
