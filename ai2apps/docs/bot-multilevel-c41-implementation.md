# Bot 有界多层委派 C4.1 实施说明

日期：2026-11-04。C4.1 在已有 Bot Task-Session 和 Todo 执行之上增加受控的多层分工。A 可以在用户审阅后委派 B；只有明确允许继续分工时，B 才能提出委派 C，每次新增委派仍由用户在 A 的原对话审阅。已实现并加载 App-Dev；完整 AaAT 回归 1082 项通过。最终中断清理查询扩展另经 9 项 C4.1 回归和 1 项新增故障注入测试验证，前端 16 项通过。[验收收据](acceptance/bot-multilevel-c41-20261104/receipt.json) 区分完整门禁快照与最后局部修正，记录实际加载来源。

C4.1.1 已将本版本按 Bot 身份的保守防环升级为[任务级依赖与合理重入](bot-task-reentry-c411-implementation.md)；该升级允许同 Bot 和祖先 Bot 的独立子任务。下文按 Bot 拒绝规则是 C4.1 历史行为，当前规则以 C4.1.1 实施说明为准。

## 使用范围

`messager.bot.delegate` 的声明增加 `allow_subdelegation`，默认 false。其余目标、任务说明、模型、能力范围与审批哈希沿用 C2。用户确认允许继续分工，不代表提前同意未知的接收者或新权限。只有通过宿主审阅并准入的子任务获得有限的目录和委派控制能力。

本阶段只扩展前台发起、逐次审阅的任务委派。C3 已批准的事件和定时协作计划仍使用固定参与者，不会自动获得递归分工权限；旧 C2 持久记录仍按单层规则恢复。讨论组、动态改派、跨用户和跨安装通信不在本阶段范围。

## 执行和反馈

A 等待 B，B 等待 C 时，各自的执行轮次停在宿主已有检查点，释放 Bot 的执行槽位。用户仍可向这些 Bot 发起普通对话。依赖关系属于原 Task-Session，不通过重复的新任务猜测进度。

C 完成后，宿主先把实际结果和允许的产物回接给 B，在 B 原任务会话追加一轮；B 真正完成后再恢复 A。父任务不会把“等待 C”的 B 轮次完成检查点当成最终成果。观察器跟踪逻辑 Task-Session 的最新 job，保持上下文连续并复用已有会话；KV Cache 是否命中仍由实际模型服务决定。

发起、等待审批、开始执行、收到下级结果、完成和停止均沿用 Bot 信息流回执。原对话可以看到下级委派卡及其共享上限。具体业务参数优先由执行 Bot 根据 AaAT 声明补全；必须询问时保留实际任务说明和不确定的参数。

## 审批与权限

A 是本次协作的用户沟通入口。B 委派 C 的卡片也出现在 A；只有 A 的原会话可确认新增委派。C 执行时的必要输入、敏感或付费操作仍绑定 C 的真实 Run 和原持久 Interaction，原对话展示并回接同一交互，不创建第二份授权。接收方查看的是同一项交互。

每一层业务能力都是祖先已冻结范围与当前发起方、接收方权限的交集。B 和 C 自己拥有、但 A 未允许的 App 能力不能借道使用。执行前继续校验身份、会话归属、权限 epoch 和 Provider 版本；撤权会停止有关协作。继续分工控制与业务权限分开保存，不授予咨询、配置更改或任意创建任务的控制能力。

只传递明确委派的说明、必要结果和允许的产物，不共享其他 Bot 的主对话、私人记忆或未授权资料。返回的数据、建议和声明本身不授予权限。图片继续使用已有信息流和素材组件，本阶段没有更改图片布局。

## 依赖图与共享额度

宿主保存 root、父边、源 Bot、目标 Bot 和深度。目标不能是自己或祖先；跨独立 root 的活动 Bot 等待图也检查可达性，拒绝 A 等 B、B 又等 A。检查与边准入在同一持久事务内完成。该等待图采取保守策略，可能拒绝同一 Bot 多项工作形成的可疑等待关系。

| 上限 | 当前值 | 计量方式 |
| --- | --- | --- |
| 委派深度 | 3 层 | 原发起方深度为 0，每次委派加 1 |
| 委派边数 | 8 条 | 同 root 全部已提出的边，结束后不退款 |
| 模型 tokens | 512,000 基础预留 | 共 8 份基础额度。经用户确认的追加额度归对应执行轮次 |
| 单轮模型预留 | 64,000 | 按确定的 child/resume 收据键预留，不因失败退款 |
| Tool 调用 | 36 次 | 同 root 按真实 invocation ID 原子去重 |
| 协作期限 | 600 秒 | 首个子任务批准准入时开始，等待续额决定时暂停计时 |
| 单轮步骤 | 24 步 | 每个执行/恢复轮次的上限 |

原发起任务在提出委派以前的推理不追溯计入这份额度。tokens 是保守的轮次预留，不是实际费用估算；回接 A、B 的模型轮次也计入。用量达到本轮额度时，原 Bot 对话显示同一 Run 的续额卡。每次确认在已结算用量之上追加一份基础额度。重复提交同一个决定只记一次。选择结束时保留已完成产物并停止上级汇总。新额度只适用于已批准的这一轮，原有步数、工具和权限守卫继续执行。既有协作保留已经审阅的基础额度。Gateway 和 Router 检查同一次调用不会双扣。

## 停止与恢复

拒绝、取消、到期、撤权或实际执行失败会停止整个相关协作树；已完成的效果和产物保留。宿主取消未执行 job、停止已准入 Run、暂停逻辑任务，不自动换 Bot 或重试未知效果。

停止原因、发起边和状态先持久化成独立收据，再逐项清理。若进程在两者之间中断，恢复按原收据重做清理，包含仅等待审阅的边；不会把取消变成重新准入。子任务创建、结果接收和上级恢复继续使用固定收据键，重复观察不重复执行效果。

实现位于 Messager owner 的 `delegation_graph.py`、`delegation.py`、`dialogue.py`、`communication.py` 及 Bot 声明组合层。通用 Agent 执行层不识别具体业务 Tool 或 Bot 名称。

## 验证

`test_bot_multilevel.py` 使用真实 SQLite、Todo、Task-Session、Agent Run、原审批和权限服务，模型与业务效果为确定性夹具。覆盖 A→B→C 逐层恢复、等待期间聊天、原入口审批、原敏感交互回接、权限逐层收缩、祖先及独立 root 防环、深度限制、共享 Tool/tokens 租约和中断清理恢复。

前端测试检查下级委派卡只向原入口发送显式审批，并展示共享上限。完整 AaAT 边界门禁包括该测试组。真实模型质量、跨模型缓存表现和真实外部操作留给用户验收；夹具成功不作为这些效果的证明。
