# 分享作品 Mini-App 需求与实现方案

版本：v1.4；日期：2026-11-01；状态：首版代码及夹具验收完成，真实发布待联调。平台能力确认不等于接入验收通过。

面向 AI Browser 实现者。新增名为“分享作品”的 AI Browser Mini-App，将用户选择的作品发布到用户自己的第三方托管账号，返回可直接阅读的 HTTPS 链接。首版目标支持 Hugging Face Static Spaces 与 ModelScope Static 创空间，由 Desktop 复用用户已有的登录：HF 调用官方 CLI；MS 按用户 2026-11-01 的补充授权使用官方 SDK。Mini-App 不提供登录／令牌配置／自动安装流程；Cloudflare Pages 后置，架构允许后续增加其他满足查看链接要求的托管渠道。普通模型／数据集文件仓库、网盘下载或提取码分享页不计入本产品支持范围。

本轮实现 HF CLI／MS 官方 SDK 两个发布适配器及 Desktop/Mobile 共用的界面和后台任务；开发验收不公开真实用户作品。首版绑定用户已有的个人公开静态空间，不自动创建空间。

## 1 产品目标与范围

- 面向首批技术用户，允许首次在 Desktop 完成 HF/MS 官方 CLI 登录或令牌配置。配置成功后，从 AI2Apps 选择作品、点击“发布分享”即可获得查看链接，不要求每次手动运行命令。
- 发布完成后，用户的 Desktop 可以离线；接收者无需安装 AI2Apps，也无需登录 AI2Apps。
- 用户持有托管账号和内容，使用该账号自己的额度；不要求平台代付托管费用。
- 首个实际接入方是情报中心的频道静态 HTML 导出。后续可接 Gallery、图片、音频、视频等作品，但不把这些 App 的规则放入共享 Web-Agent。
- 首版不新增 AI2Apps Cloud API、不托管平台账号密码、不创建短链服务、不以巨型 Data URL 作为发布链接。
- 仅支持可生成作品 HTTPS 查看链接的渠道：接收者不依赖 AI2Apps、无需登录托管平台或下载 HTML/ZIP 到本地即可阅读。文件下载地址、仓库源码页和控制台页不算查看链接。
- 首版目标渠道为 HF Static Spaces 与 MS Static 创空间，Cloudflare Pages 后置，百度网盘及 HF/MS 普通文件仓库不接入。交付渠道选择框和可扩展适配结构，但只展示已经实现并验收的渠道。不得显示其他渠道“可用”或静默切换目的地。

## 2 用户流程

### 2.1 首次使用

1. 用户自行在 Desktop Terminal 安装并登录官方 HF/MS CLI。
2. 在 AI Browser 打开“分享作品”，选择渠道，点击“检查已登录环境”。宿主只执行固定的版本／身份／目标查询，不执行登录、令牌读取或安装命令。MS 通过官方 SDK 自行加载与其 CLI 相同的现有登录，不由 AI2Apps 解析凭据文件。
3. CLI 缺失、未登录、凭据失效、权限不足或版本不支持所需命令时，明确报错并提示用户回 Terminal 处理；不自动切换账号或借用浏览器 Cookie；HF 不改用 SDK 后备。
4. 展示实际查询到的账号及目标静态空间，用户确认要发布的账号／空间；发布前再次核对身份和空间类型／可见性。
5. GUI 从用户登录Shell发现 CLI 的 PATH，并补充标准安装位置；使用实际用户的 HOME 和现有官方配置路径，不创建替代凭据目录。无法发现 Terminal 的临时虚拟环境时明确说明，不扫描任意虚拟环境和凭据文件。

首版只允许当前 Desktop 安装拥有者使用此 OS 用户的 CLI 授权；手机必须以同一拥有者身份访问已连接 Desktop。其它成员不能借本机全局CLI凭据发布。发布记录仍按 owner 和实例隔离，但不复制、迁移或替用户修改CLI已有登录。用户自行管理命令行凭据；不同实例显式复用同一OS用户已登录CLI是本次产品决定，不视为浏览器Profile跨实例复用。

手机不安装CLI，不提交令牌；上传的本地作品转交到已连接Desktop后，执行与Desktop相同的准备、确认、后台任务和结果读取流程。浏览器登录状态不代表CLI已登录。

### 2.2 发布作品

1. 从来源 App 的“分享作品”入口交接，或在 Mini-App 内选择本地作品文件。
2. 展示作品标题、来源、文件大小、图片/附件数量、导出时间和本地预览。
3. 选择渠道、账号、目标项目；首版使用独立快照模式。
4. 明示“将上传到你的〔所选平台／账号／空间〕，持链接者可访问”。用户点击“发布分享”即授权本次明确范围的发布，不在正常步骤中反复确认。
5. 后台准备文件、上传、部署、验证，显示同一任务的进度。
6. 成功后展示“打开”“复制链接”和托管平台管理入口；保留分享记录。

界面关闭、切换 App、手机断开不取消后台任务。再次打开恢复原任务。手机可以发起和观察任务，实际 CLI 执行仍在已连接的 Desktop；完成部署后阅读链接不再依赖 Desktop 在线。

### 2.3 环境错误与中断

CLI 缺失、未登录、权限不足、命令不兼容时，显示经过脱敏的错误，提示用户在 Desktop Terminal 自行处理。不得尝试登录、安装、读取令牌、借用浏览器 Cookie 或切换平台。

上传前的账号检查失败不会派发上传。上传可能已经派发后发生超时、取消或断线，只允许匿名核验原快照，不自动重传，也不声称已撤回公开文件。用户可到平台管理页面处理已上传文件。

## 3 内容输入与跨 App 交接

首版支持静态站点 ZIP，以及单个 HTML 文件。HTML 转为站点根目录的 `index.html`。ZIP 必须检查路径穿越、符号链接、展开大小、文件数量和入口文件；拒绝包含服务端程序或未经授权执行入口的站点包。

情报中心复用现有 HTML 导出业务服务，包括时间范围、是否包含目录、折叠卡片、图文混排和图片嵌入选项。由情报中心生成并提供受控 artifact 引用；Mini-App 不重新读取其数据库或自行实现另一份导出器。

图片应随作品上传，使阅读页无需访问 Desktop、本地受保护资源或临时登录链接。缺失图片必须在发布前展示数量和原因，由用户决定是否发布不完整快照。不能把“有封面、正文图片全丢失”报告成完整导出。

跨 App 使用现有 AaAT 发现、声明和受控资源交接。大文件以有归属与有效期的 artifact 引用传递，不能塞入聊天正文、Tool 参数、URL 查询串或浏览器 localStorage。输入文件对调用者和 Mini-App 的访问权必须由宿主验证。

建议的业务输入（概念字段，须映射到现有契约，不表示已经存在的 API）：

| 字段 | 说明 |
| --- | --- |
| artifact_ref | 已授权作品引用；服务端解析，拒绝任意本机路径或任意 URL 抓取 |
| title | 用户可编辑的分享标题 |
| provider | 已实现的渠道标识 |
| destination_ref | 当前用户绑定的账号/项目引用 |
| publication_mode | 首版仅 `snapshot` |
| request_id | 一次用户发布意图的稳定幂等标识 |

来源 App 的“导出”只生成文件，不等于授权公开上传。由 Agent 跨 App 调用时，需保留本次明确的发布意图和内容/目标绑定；没有发布授权则打开预览确认，不替用户确认。

## 4 HF 与 MS 首版行为

### 4.1 渠道选择与部署方式

首版目标接入两个独立渠道，均为静态网页托管，不使用普通模型／数据集仓库存放 HTML 后将下载链接冒充查看链接。

| 渠道 | 目标能力 | 已确认与待验收边界 |
| --- | --- | --- |
| Hugging Face Static Spaces | `sdk: static`，部署 `index.html` 及 CSS/JS/图片 | 官方明确支持静态 HTML，直接静态服务，不需要运行计算实例；实际账号授权、上传部署、匿名读取和快照路径仍须验收 |
| ModelScope Static 创空间 | `sdk_type=static`，部署已构建的 `index.html` 及静态资源 | 官方 SDK／部署指南明确支持 static 和应用公开可见性；公开样例本轮观察到休眠后重新部署等待，尚未完成该样例正文读取，不宣称所有静态空间均即时可读 |

主路径使用用户现有已登录环境：HF 官方 CLI，MS 官方 SDK（用户补充授权，见第 13 节）。不得自动安装、调用登录命令、要求在 Mini-App 输入令牌、由应用解析凭据文件或提取浏览器 Cookie。能力不兼容时报错，不擅自切换平台或账号。

CLI子进程使用解析后的固定执行程序、结构化参数及私有受控工作目录，禁止shell=True、任意子命令、模型生成命令或用户提供命令片段。stdin关闭，避免后台出现无法处理的登录提示；继承必要的用户环境，保留官方CLI自行读取本地登录的行为。命令输出不得原样进入模型／任务历史，身份只保留经过校验的账号名称；超时、退出码、权限与版本错误使用脱敏分类。

MS 绑定必须记录实际站点（如 modelscope.cn／modelscope.ai）及在该站点观察到的账号，不推断跨站点会话、账号或资源通用。接收者不能被要求登录、申请仓库权限或切换账号才能阅读。

文件数量、单文件/总量、配额和官方上传／部署方式分别由两个适配器核实与维护，不沿用 Cloudflare 的 1000 文件／25 MiB 限制。无法确认限制或配额时不能显示“无限制”。自包含 HTML 保留原始字节及内嵌图片，不拆图、不压缩、不注入标记；ZIP 保留原有文件结构，不能静默遗漏资源。

Static 输入必须是已经可展示的产物；首版不上传源项目让平台运行任意构建，不启动 Gradio/Docker/Python 服务，不替用户选择付费资源。用户作品本身的客户端脚本与服务端／部署执行入口分别校验；本地预览在隔离沙箱中进行。

### 4.2 独立快照、休眠与链接

每次分享创建独立快照，并返回本次发布后实际观察、匿名验证过的作品查看地址。Space／创空间首页通常代表当前内容，不能自动视为某个历史作品的永久链接；Git提交或仓库文件地址也不能直接作为阅读链接。

优先验证专用 Space／创空间中独立作品目录及对应查看路径的方案，旧目录和资源不可被后续发布覆盖。具体 URL、页面路由和平台包装/嵌入行为必须真实观察，不能凭拼接规则生成“预计链接”。连续发布两份后，重新读取第一份作品验证内容摘要与图片保持不变。

若平台无法提供满足要求的快照查看路径，必须将该适配器标为未通过验收，重新提出方案；不得每次无限新建 Space／创空间，或静默改用其他渠道。首批开发目标为 HF/MS 不等于两个选项立即显示可用。

平台展示休眠、唤醒、排队或重新部署时，记录为未就绪并显示真实原因，不报告发布完成。必须在无登录环境实际加载作品正文和图片后才算匿名阅读通过。测试需覆盖非首次打开及闲置后再次打开，记录是否需要用户手动唤醒、实际等待时间、是否会要求登录或付费。MS 本次公开样例曾显示“预期10分钟内完成”，这是样例观察，不可推广为所有 static 空间的固定时限或永久特性；既有任务预算需据实测评估。

首版不承诺即时打开、自动过期、密码保护、绝对私密或永久保存；若实测存在明显冷启动等待，应在渠道选择和结果中明确告知。删除空间、作品文件、账号变化或平台策略可能使链接失效。撤销能力若尚未实现，提供管理入口和明确操作指引，不显示虚假的“一键撤销”。Cloudflare Pages 作为后续渠道保留，不在 HF/MS 失败时自动切换。

### 4.3 发布验证

上传完成和部署按钮点击成功均不是任务成功。必须：

- 观察到部署完成状态，记录实际部署标识和链接。
- 验证链接为合法 HTTPS、属于用户所选项目本次实际部署；拒绝登录页、仅展示仓库文件／说明的页面和管理控制台 URL。平台公开作品包装页可以作为查看入口，但必须实际验证其中的作品内容，不能只检查空间标题或部署标签。
- 在无登录会话的读取环境验证可公开访问，确认作品标识、标题、正文和预期图片可读取；不能仅依赖已登录页面。
- 对较大图集给出完整资源清单检查和有界实际加载检查，区分“资源存在”与“图片实际可解码”。验证范围应保存在结果中。
- 保存验证时间、部署标识与内容摘要，才允许终态 `completed`。

验证用不含账号会话的访问，不读取或复制其他 Profile 的 Cookie。公开链接的请求仍遵守共享网络访问限制和重定向校验。

## 5 任务与恢复要求

HF CLI／MS SDK 发布采用宿主现有持久后台任务机制，由“分享作品”owner适配器执行；不占用浏览器操作额度，不把命令行或HTTP调用伪装为浏览器操作。Mini-App iframe 仅提交、观察、恢复和取消任务，不直接执行命令、不持有凭据、不运行发布循环。不得另外实现独立队列。

确需浏览器辅助的步骤仍使用共享 WebAgentInvocation、Browser Task 队列、原生 BiDi 和受认证 Gateway。辅助子任务归因到同一发布记录，UI 与 AaAT 读取相同的持久进度，不把子任务完成误报为整份作品发布完成。

建议业务阶段：准备作品 → 检查登录与目标 → 上传 → 等待部署 → 验证访问 → 完成。排队、等待用户、取消、失败和结果不确定使用既有任务语义；界面和 AaAT 返回同一份持久进度，不维护第二套任务状态。

此任务与快速搜索不同：允许必要的人工协助，默认允许视觉辅助。后台发布与浏览器辅助分别使用对应正式任务框架的总时限、恢复时限/次数等参数；建议首版总执行预算 15 分钟、恢复预算 120 秒/3 次，作为待实测调整的业务默认值。映射前确认当前参数名称、计时与人工等待语义，不另建隐藏计时器绕过框架。

恢复遵循副作用不确定性约束：

- 发布前持久保存 request_id、作品摘要、目标账号/项目及已观察部署标识。
- 文件提交或部署请求发出后超时，先查询原提交／部署状态；不盲目再次提交。CLI也适用这一规则，不能因子进程退出或回执丢失就自动重跑整个发布。
- 同一 request_id 改变文件、目标或发布参数必须拒绝；重复请求返回原任务。
- Local 重启先对账原任务、页面和部署；未知结果显示“需要核实”，不能自动新建分享。
- 取消上传不代表撤销已发布内容。若已部署，保留结果并明确告知；删除是独立授权操作。
- 按既有页面所有权清理任务创建页；用户原有登录页、项目页不因任务结束被关闭。

## 6 渠道与 AaAT 架构

“分享作品”拥有发布业务语义、内容校验、渠道适配和结果解释。HF/MS 页面规则留在各自适配器/声明中；共享 Agent、浏览器 SDK 和 General Agent 不增加 HF、MS、情报中心或 Mini-App 名称分支。

每个渠道声明支持的文件类型、限制、登录入口、允许站点范围、部署方式、验证策略和管理能力。首版目标实现 HF Static Spaces 和 MS Static 创空间。新增渠道复用发布记录和任务协议，不复制队列、登录存储或确认机制。

AaAT 能力建议拆为“准备分享”“发布分享”“查询分享记录”，撤销作为后续独立副作用能力。具体 ID 由实现方按注册规范确定，UI 和 AaAT 复用同一业务服务。声明必须准确反映上传公开发布的副作用和确认政策。

托管平台控制台／仓库与作品应用站点是不同信任边界。预先声明所选渠道的管理范围，作品地址按可信部署结果进行精确绑定；不能为了验证 HF/MS 的任意空间而全局开放其他租户站点。若现有 scope 机制不能表达安全的动态结果地址，列为宿主通用能力缺口并独立实现、测试，不用通配符规避租户隔离。

## 7 本地记录与界面

持久记录至少包含：owner、Mini-App/Provider 版本、Profile、渠道、账号/项目非敏感引用、标题、artifact 摘要、任务/request ID、部署 ID、实际 URL、发布时间、状态和验证摘要。

记录必须按 owner 和实例隔离。发布记录不得存储密码、Cookie、API 密钥、原始控制台页面快照或巨大 Data URL；发布凭据由独立秘密存储／隔离凭据目录管理。日志只记录必要阶段、计数和脱敏错误。

UI 提供三个区域：作品预览、发布目标、最近分享。最近分享支持打开、复制、状态和管理入口；重复发布/更新必须由用户主动选择。移动布局可完整操作，等待协助有明显入口，不以浏览器原生弹窗作为唯一错误提示。

## 8 实现前置检查与交付顺序

1. 阅读下方仓库契约，检查现有 Mini-App SDK、受控 artifact 交接、后台任务、用户已安装HF/MS CLI环境与发布授权能力。
2. 文件上传必须由宿主解析已授权 artifact，仅将受控暂存文件交给已登录的官方 CLI；不将任意本机路径或令牌暴露给 Package。浏览器辅助确需文件输入时复用已有原生 BiDi能力。若缺受控交接能力，先增加可跨 Provider复用的最小宿主契约，不能宣称现有 submit 自动支持。

## 15 HF Static 公开页核验（2026-11-01 实测修正）

HF Static 会在原始 HTML 前或 head 中附加 `window.huggingface.variables` 与社交分享 meta。不能要求公开页原始哈希等于仓库 HTML 哈希，也不能把这类确定的不一致反复当作“等待部署”。

owner 适配器仅识别一个最多 16KiB 的固定平台附加块：无属性的变量赋值脚本（严格 JSON 数据）与限定的 og/twitter meta。移除此块后必须逐字节等于用户原始 HTML；正文／原有脚本／图片改动、额外执行脚本、跳转 meta 均拒绝。HF 静态资源可能跳转到官方 HTTPS `*.cdn.hf.co`；仅 HF 可接受此域名，且仍须逐文件内容核验，不记录临时签名查询参数。其他跳转仍拒绝。MS 不继承这些例外。记录公开 HTML 实际哈希与平台附加标记，其余文件继续原始 SHA-256 校验，图片继续解码核验。

先核验 HTML，再以最多四路读取其余静态资源。HTTP 尚未部署等暂态错误可以有界等待；内容不一致、证书失败等永久错误立即报告原因，不自动重传。提交发布后清除“处理中”占位；只读重新核验成功后显示核验总数，不沿用旧失败任务进度。原失败 Task 保留历史状态，重新核验结果由分享记录保存，不伪造原 Task 成功。

### 发布目的地记忆与自动网址

按拥有者和发布源在 Desktop 保存上次验证或准备成功的空间及应用网址，Desktop/Mobile 共用；首次升级可从已有快照恢复。切换源分别恢复，不混用 HF/MS。输入完整空间标识后使用现有已登录 CLI/SDK 只读查询官方空间元数据，自动填写可验证的直达网址，不凭空间名拼接假定域名。手动填写仍可用；平台未返回网址时明确提示填写一次并记忆。迟到的查询不能覆盖用户切换源、空间或手动输入的网址。

### 2026-11-01: self-contained social cover metadata

Preparation may transform embedded data-image values in og:image/twitter:image into one600px hashed JPEG plus the explicit target Space's absolute snapshot image URL. Only those metadata values change; body data URLs and all non-metadata page content remain unchanged. Generated resources are included before manifest/digest/consent, uploaded only through the existing confirmed publication flow, then anonymously verified with all other snapshot files. Ordinary HTML without embedded social image metadata retains its exact original bytes. No post-confirmation rewrite, external image fetch or automatic upload is allowed. Existing snapshots are immutable and not retrofitted.

### 实施与验收

- Mini-App 0.1.2 增加「发布图文／视频」。本地草稿按拥有者保存，记录正文、媒体大小和哈希。X 上限为四张图片或一个 MP4，Rednote 支持多图或一个 MP4/MOV。Desktop 单次素材暂限 128 MiB，Mobile 经过现有网关暂限 19 MiB。
- X 开发接入使用 Local 进程中已配置的 OAuth 2.0 用户访问令牌 `AI2APPS_X_USER_ACCESS_TOKEN`，需要 `users.read`、`tweet.read`、`tweet.write` 和 `media.write`。首版无交互授权向导或自动续期。网页会话不参与官方 API。令牌不进入界面、工具参数、任务记录或输出。准备时读取 X 账号，派发前再次比对；批准后才在 System Task 上传媒体、等待处理并发帖。同一草稿最多派发一次。丢失回执标记为「结果未知」，由用户到 X 核对。
- `share.social_prepare` 读取本 Session 的受控附件或产物，`share.x_publish` 要求当前 Run 对完整参数的表单审阅，随后通过 `publish` 效果触发用户单次批准；`share.social_status` 回读持久状态。Bot 使用相同工具、归属与审阅规则，已授予 Mini-App 访问的 Bot 仍需等待本次批准。共享 Agent/Bot 授权代码未改。
- Rednote 在 Desktop 打开 AI Browser 默认分身的创作中心。用户可下载素材、复制文案并在平台提交；Mobile 提供当前设备的网页入口。Dev 的已登录创作中心分别接受合成 PNG 和 MP4，两者均观察到可用的「发布」按钮，未点击。官方 Mobile SDK 尚未接入。
- 固定 App-Dev 重启后核对 App/Helper 的源目录、Local 导入路径和页面资源。原生 Mini-App 创建了带图片的 Rednote 本地草稿，显示「待手动发布」及创作中心入口。X 的 AaAT 和已授权 Bot 均通过真实审批交互与官方 HTTP 夹具验证，正式 X 发帖留待已授权账号联调。完整 AaAT 回归运行至已有 Bot 记忆回传失败处后停止。
