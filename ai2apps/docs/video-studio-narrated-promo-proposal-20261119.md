# Video Studio 旁白短片工作流方案

日期：2026-11-19。状态：研究与设计，尚未实现。

## 研究结论

MoneyPrinterTurbo 的主线是主题或脚本 → 脚本/素材词 → 配音 → 字幕 → 素材获取 → 剪辑与渲染。项目提供 Agent Skill、WebUI、API、CLI、批量任务和阶段进度。素材可以来自用户文件、图库或视频模型；TTS 时间戳或 Whisper 用于字幕。新版本提供本地项目的场景修改和复用未变更渲染产物。其源码中的 `generate_terms` 在启用 `match_materials_to_script` 时按脚本顺序生成素材词；这一选项表明全局主题词与叙事顺序之间存在需要显式处理的差别。

借鉴的是可见、可恢复的制作流程，以及允许用户在每一阶段替换输入。AI2Apps 不嵌入其执行器、WebUI、凭据配置或提供商路由。Video Studio、Voice Studio、Models、Gallery、Video Task 与 Video Composer 继续各自拥有现有数据和能力。

## 产品定位与第一期范围

在 Video Studio 增加内置 Mini-App **旁白短片**，提供“产品宣传”和“知识讲解”两个起始模板。第一期支持 30–90 秒、16:9 和 9:16、单旁白、用户确认的本地/Gallery 素材、静态图的轻动效、可选逐镜视频生成、配乐、字幕和 MP4。输出同时保存可编辑的 Composer 项目。脚本、角色、镜头、素材和导出均能从草稿恢复。

第一期不承诺自动事实研究、图库搜索、自动发布、多人物对白或长篇剧集。知识讲解的事实依据和产品宣传的功能/性能声明，先由用户提供材料；LLM 生成稿件时保留每条主张所依据的材料引用，无法验证的主张进入待确认状态，不直接进入配音与成片。

## 用户流程

1. 输入主题、受众、片长、语言、画幅和目标；宣传模板另填产品名称、核心卖点、行动引导，并导入官方文案、截图、录屏或网页素材。
2. 生成 1–3 个大纲与口播稿候选。用户编辑、选择并锁定稿件。每个口播段落是稳定的 `beat_id`，标明目的、文案、画面意图和依据。
3. 选择 Voice Studio 的已就绪 Character，试听一句，再合成分段旁白。使用真实音频长度及句/词时间戳建立时间轴；字幕优先从已确认口播文本与语音时间戳生成，必要时回听核验。
4. 对每个 `beat_id` 展示素材候选：用户素材/Gallery、已有视频生成结果、静态图与模板动效。用户可替换、裁剪、重排；缺少画面时才选择 Video Studio 的本地或 BYOK 模型生成一个镜头。付费任务提交前展示模型、镜头数、预估费用范围与不可保证事项。
5. 生成 Composer 草稿，按实际旁白时间放置画面、字幕、音轨和配乐。用户在 Composer 中继续编辑，导出 MP4；共享 Output 显示任务和成片。

默认先做“旁白驱动”：语音的实际时长确定镜头起止。某个镜头比目标时长短时，先选择延长、替换或补图；不能仅拉慢视频或让字幕跨越下一句。改动一个 `beat` 只使其下游音频、字幕、镜头和合成缓存失效，不重做整条片。

## 工作流数据合同

新增 owner 管理的 `narrated_video_project/v1`，保存用户/实例归属、revision、输入材料引用、已批准脚本版本、画幅、语言、配音选择、素材选择、状态和 Composer 项目引用。每个 `beat` 保存稳定 ID、已确认文案、依据引用、旁白音频 Artifact、实测时长、字幕片段、候选素材、已选素材、裁剪范围及生成任务 ID。外部文件只保存已验证的归属引用和内容摘要；API Key 不进项目或任务快照。

持久任务阶段：`draft → script_review → voice_ready → media_review → composition_ready → render → completed`，另有失败、取消和等待配置状态。阶段进度显示实际完成的句子/镜头数；不伪造供应商未提供的百分比。浏览器刷新、切换 Mini-App 或 Local 重启后，复用原项目和任务状态；未知的付费提交状态先查供应商任务，不能盲目重试。

## 与现有 AI2Apps 的连接

| 现有 owner | 复用方式 | 需要补的接口或适配 |
| --- | --- | --- |
| Models / ACPF | 从模型 App 选择 LLM、TTS、图像和视频能力；按本次方案检查就绪 | 旁白短片 owner 按所选阶段和模型声明实际依赖；设置返回后保留草稿 |
| Voice Studio | 使用已验证 Character 与其模型；生成旁白 Artifact | 新增经 owner 校验的分段合成调用；不调用私有方法或复制角色数据库 |
| Gallery / 统一素材槽 | 导入用户照片、截图、录屏和既有输出 | 素材归属、来源、许可/署名和时长元数据随项目冻结 |
| Video Generation Task | 对缺失镜头调用本地 H3 或 BYOK 视频模型 | `beat_id` 与供应商任务关联；单镜头重做和取消保持现有队列语义 |
| Video Composer | 保存可编辑项目、统一时间线和 MP4 渲染 | 从 `beat` 列表构建已验证的 Composer 项目；字幕可导入为文字片段或引用字幕轨 |
| Video Studio shared Output | 展示当前任务、历史与最终 Artifact | 新 Mini-App 的结果投影到宿主唯一 Output，不建自己的播放/下载历史 |

Composer 目前接受视频/音频轨、媒体与文字片段，项目总时长上限为 600 秒；第一期 30–90 秒在现有上限内。具体素材导入、文字字幕与音量混合仍须以真实 Composer 项目做端到端验证。

Agent / AaAT 只能通过旁白短片 owner 的可信声明和适配器发现、准备、调用与解释结果。业务脚本、素材选择、事实依据、审核规则属于 Video Studio owner；不要把项目名或 `beat` 规则写进通用 Agent。每个阶段按实际模型需求声明，配置路径由当前 Video Studio placement 与 ACPF 校验。

## 分期与验收

### P0：可编辑宣传短片

实现项目草稿、口播稿审核、Character 分段配音、用户素材逐句分配、字幕、背景音乐、Composer 草稿与成片。视频生成先只作为手动补镜头动作。验收使用 60 秒、约 8 句的产品宣传样例：刷新/重启后草稿与任务可恢复；替换第 4 句素材或口播只重做受影响部分；每句画面与声音起止误差在 2 帧内；字幕无越界；导出与 Composer 预览一致。

### P1：自动素材建议与镜头生成

在已有用户素材中按 `beat` 检索和排序，提供候选及原因。缺口可以批量提议图像/视频镜头，但必须先展示计划和费用，再经用户确认提交。验收覆盖模型缺项配置、BYOK/本地模型选择、单镜头失败重试、取消后不重复收费提交。

### P2：知识讲解与规模化

在 P0 的依据引用和主张审核稳定后，接入可引用的研究素材；增加图表、屏幕录制与解释动画模板。图库搜索、授权素材摄取、多语言版本和批量变体分别作为后续能力，不与第一期强耦合。任何外部图库接入先核对其 API 与商用许可。

## 主要风险

- **事实与品牌准确性：**LLM 不得凭空补产品指标；未经确认的脚本不能自动成为成片旁白。
- **音画节奏：**以真实旁白音频驱动时间线，避免按字数估算片长后一次性拼接。
- **成本与重试：**视频镜头是付费/耗时步骤；冻结请求、记录外部任务 ID，未知状态不自动重投。
- **素材权利：**外部图库、音乐、字体及产品截图记录来源与许可；不能把“可下载”当作“可用于商用宣传”。
- **模型依赖：**实际选择的 LLM、TTS、视频模型分别就绪；缺项只引导配置所需阶段，保留已有稿件和素材。
