# Doc Studio MVP 设计

状态：设计提案 · 2026-11-11

Doc Studio 是 AI2Apps 内置的文档创作 App。用户从一个或多个素材包建立文章工程，在「撰写文章」Mini-App 中生成、修改和导出稿件。其它 App、Mini-App 和 Bot 可以通过 AaAT 读取获准的工程资料和已生成产物。首个完整链路是从情报中心选取文章，生成 X Post 和 HTML，再由「小红书图文」Mini-App 生成竖屏分页图片。

## 1. MVP 范围

| 阶段 | 用户可完成的操作 |
| --- | --- |
| A · 创作链路 | 在情报中心从单篇或多篇文章发起创作。Doc Studio 可新建工程或向现有工程导入素材包。选择内容风格和目标形式，生成并修改稿件，产出 X Post 或独立 HTML，在统一的「预览与输出」区预览、复制或保存。 |
| B · 工程复用 | 在「小红书图文」中选择工程，以及一版稿件或已生成的 X Post／HTML，选取工程中的图片，使用内置模板生成竖屏分页图。通过 AaAT 验证其它调用方也能发现工程并按权限读取素材和产物。 |

MVP 提供总结、分析、转发点评和新闻稿四种风格，允许补充写作指令。各风格都在正文开头交代主体和事件，让读者直接理解稿件。新闻稿再用中性口吻补充有来源的背景与事实。质疑、研究、调侃，以及微博 Post、Markdown、DOCX、PPTX、口播稿列入后续扩展。研究风格如果需要补充外部证据，应走独立的检索授权流程。小红书首版提供一套分页模板，可调整背景、强调色、字号和选图。长图、贴纸库、自定义字体、自动发布和协作编辑后续再做。

## 2. 工程与产物

| 对象 | 归属和内容 |
| --- | --- |
| 文章素材包 | 生产方交付的有版本清单。条目含标题、正文或摘录、原始 URL、来源 App 和来源条目 ID、采集时间。图片含授权资源引用、说明、出处、封面标记，以及可取得的段落锚点。 |
| 文章工程 | Doc Studio 持有。保存标题、素材包导入记录、工程内素材引用、稿件与输出索引。支持多个素材包，保留各自的出处。 |
| 稿件与版本 | 一份工程可有多份稿件，例如总结型 HTML 和点评型 X Post。每个保存版本记录风格、目标、语言、素材范围、引用关系，以及生成或人工编辑来源。 |
| 输出 | 从具体稿件版本或既有输出生成的固定产物。记录格式、生成参数、来源版本、资源引用和生成状态。重新生成时创建新输出，旧输出仍可预览。 |

素材包是一次交付，工程保存可继续使用的正文快照及经授权纳入工程管理的图片资源。Doc Studio 在导入时校验权限和资源范围；持久化资源必须按工程的访问与保留规则管理。素材包修订通过显式导入生效，既有版本继续指向当时采用的素材。相同包和版本重复导入应可安全重试。不同包重复引用同一原文时，可合并工程内素材条目，同时保留各包的出处；仅凭标题相似不合并正文。缺图时保留可用文字和来源，在工程内提示具体缺项。

正文使用可排序的内容块，首版支持标题、段落、列表、引用和带图注的图片。来源标记与正文块关联，图片块引用工程资源。图片原有位置随素材包传入，输出时按目标形式决定保留、移动或省略。无法定位到对应段落的图片供用户选用。

## 3. 创作与界面

1. 用户从情报中心的文章、栏目、热点或频道发起撰写，也可以多选文章。情报中心先准备归属当前用户的素材包，展示文章清单，再由用户选择加入 Gallery、在 Doc Studio 新建工程或加入已有工程。栏目、热点和频道默认使用最近更新的最多 20 篇。Gallery 保存带清单的 ZIP，并报告未能内嵌的图片。两种工程操作提交后台导入，打开 Doc Studio 后可继续查看进度。此阶段工程操作在桌面端开放。
2. Doc Studio 宿主管理 Mini-App 导航、Gallery、Mini-Chat 区域和共用的「预览与输出」。文章工程由「撰写文章」Mini-App 管理，创建、改名、删除和切换位于其工作区。其他 Mini-App 可选择明确授权的工程和产物作为输入。
3. 「撰写文章」分别选择写作风格和目标形式。例如「分析 + X Post」和「分析 + HTML」可以独立生成。用户也可以显式选择一版稿件作为改写输入。生成完成后保存一个可修改的稿件版本，导出绑定明确的版本。
4. HTML 使用工程里的结构化内容、图片和来源链接，可保存为独立文件。预览和导出清理不受信任的富文本。X Post 可复制，生成时按照目标形式处理篇幅，保留可用的出处线索。
5. 「小红书图文」让用户明确选定输入版本、选图并预览分页。读取既有 HTML 或 X Post 时，优先通过输出记录取得对应的结构化稿件和资源，按用户所选版本排版。导出一组按顺序编号的竖屏图片，并记录输入和排版设置。

AI 生成、HTML 渲染和分页渲染均报告各自的进度与错误。生成失败、取消或重试时保留已保存版本，失败记录与可用输出分开显示。离开页面后可回到工程查看后台任务结果。渲染产物在成功写入后才作为可用输出展示。

## 4. AaAT 与跨 App 边界

- **素材提供方**负责挑选并打包内容、声明来源和资源授权。情报中心是首个提供方，其余 App 可按同一素材包约定接入。
- **Doc Studio**声明工程与素材能力，提供按名称查询和按 ID 读取工程、列出和读取素材及输出、导入素材包等入口。查询返回精简摘要和稳定引用。正文与文件按需读取，避免将整个工程和图片二进制塞入 Agent 上下文。
- **调用方**以真实身份和已授权的能力调用。Doc Studio 每次检查工程、版本和资源访问权限。可发现性、工程 ID 或产物引用本身不授予访问权。工程归属从可信运行上下文取得。
- **UI 与 AaAT**共用 Doc Studio 服务和授权逻辑。参数错误返回可修复的字段信息，调用方可纠正后重试。需要人工确认的效果走系统确认流程，由用户决定；MVP 的写入入口以导入为主，公开发布和删除暂不开放为 AaAT。通用 Agent 保持与工程、内容风格和 Mini-App 业务无关。

## 5. 开发现有能力的衔接

情报中心当前的稿件整理、素材选择和写作与频道关联。阶段 A 优先复用经过验证的证据组织、引用和提示词逻辑，并由 Doc Studio 负责新工程、稿件版本和输出。情报中心入口可以先并行验证，切换后导向 Doc Studio；已有频道稿件继续通过原入口读取，存量迁移另行设计。

开发时优先核对现有 Studio 的宿主管理、Mini-App 注册、任务与输出机制。先走通一个内置 Mini-App，再用第二个 Mini-App 验证工程复用和共享输出。工程与产物先存于 Local，远程端按已有授权入口使用。跨设备同步和外部发布另行定义。

## 6. 验收

1. 从情报中心选择两篇带图文章创建工程，再导入一个素材包。重新打开后，素材、图片和来源对应正确。重复导入同一版本不重复创建条目。
2. 在同一工程生成 X Post 和 HTML。手动修改稿件再导出时，两次导出分别指向各自版本。HTML 中的图文、引用和来源可核对，X Post 可复制。
3. 中途取消或模拟模型失败后，已保存稿件和输出可继续使用；重试只产生预期的一份成功输出。
4. 从同一工程生成小红书分页图。切换 Mini-App 后仍能从宿主统一输出区找到 HTML 和图片。修改源稿后，已生成的旧分页图仍对应原版本。
5. 通过 AaAT 用工程 ID 读取素材及产物，按名称查询只返回当前调用方可访问的工程。用无权调用方读取同一 ID 时，正文、图片及下载均不可访问。测试覆盖参数修复、重复导入和跨调用方权限隔离。

## 阶段 A 实现约定

- 情报中心按当前登录用户读取已保存文章，交付版本化素材包引用。Doc Studio 接收明确选择的目标工程，再由 Local System Task 拷贝受支持的图片并提交工程素材。素材包内容、项目归属和资源访问都由 Local 校验。重复导入同一个包版本保留已有快照，图片缺项会在工程素材中显示。
- 「撰写文章」使用现有 Standard 工作模型与情报中心引用校验。工程可保存 X 普通帖、X 长帖和 HTML，也可选一版作为改写起点。导出固定绑定稿件版本。普通帖按 280 个加权字符校验，长帖按成稿的 25,000 个字符校验。X 帖在可用时附第一个引用的来源链接，超长时显示实测长度和上限。HTML 在引用附近附该素材的首张可用图片并内嵌图片数据。
- Doc Studio 使用现有 Studio 宿主的布局、后台任务及原生下载方式。文档预览适配器由 Doc Studio 宿主持有，统一读取工程的产物列表，渲染纯文本和隔离 HTML。Mini-App 编辑区只提交生成、编辑和导出意图。阶段 B 可为分页图片加入预览适配并复用同一工程和产物列表。
- 稿件生成后进入逐段编写。单段 AI 改写使用已有 System Task 队列，预览确认后应用到原段落。Gallery 图片经当前用户和工程校验后保存为工程副本，工程素材图片直接引用已有副本。段落之间落图另起一行，在现有图片上落图加入该行。稿件版本保留顺序和图片行，独立 HTML 内嵌排版后的图片，X 帖导出纯文本。
- AaAT 工程发现、跨调用方读取与相关权限验收属于阶段 B。阶段 A 的交接入口使用现有 Shell 导航和 Local 认证，无需 Cloud 改动。

## 写作 Mini-Chat 与 ASCBot

- 「撰写文章」通过现有 App Chat v2 注册一个绑定文章工程的持久会话。当前工程作用域由 Local 复核。Chat 可读取有界界面快照、修改声明的草稿字段、选中已有产物，以及通过所属 System Task 提交生成或导出。提交回执表示任务已接受，完成状态由宿主输出区显示。
- 新建、改名和删除是写作界面的直接操作。删除需要确认，活跃任务会阻止删除。已删除工程的素材副本、稿件版本和产物在同一事务中清理。工程、原素材包和 Gallery 各自持有其资源。
- Doc Studio 标题栏使用现有 ASCBot 创建界面。可移植状态仅包括写作风格、目标形式和语言。快捷入口恢复这些设置，不启动写作任务。

## 翻译文档 Mini-App

- PDF「保留表单」模式由本地模型分批翻译静态标签，在原坐标替换文字。AcroForm 字段树、填写值、控件外观和页尺寸保留，填写内容不进入模型。首版处理可提取的横排静态标签，不支持 XFA、已签名或旋转页面。

- 独立于文章工程。上传 TXT、Markdown、DOCX 或带文字层的 PDF，也可直接粘贴文本。DOCX 默认在原文档副本上替换译文，保留段落样式、表格和媒体。PDF 默认重新分页并按检测到的单栏或双栏排版，图表及识别出的公式从原页取图保留。DOCX、PDF 仍可选择 Markdown。图片不进入模型。
- Local System Task 依序翻译，每次发送当前段落、前两段的原文和译文、后两段原文。保存已译段落作为检查点。用户可以选择已有本地或云端对话模型。指导方案独立保存，任务提交时固定当前方案内容。
- 翻译任务进度和下载复用 Doc Studio 宿主的「预览与输出」。任务、指导方案和产物按当前用户隔离。

## Mini-Chat、AaAT 与 ASCBot

- 撰写文章的 Mini-Chat 绑定当前工程。通用 Agent 和获授权的 Messager Bot 可通过 `doc_studio.list_projects` 查找工程和稿件版本，再把工程 ID 交给 `doc_studio.generate` 或 `doc_studio.export`。生成和导出返回任务回执，工程归属由 Doc Studio 校验。
- 翻译文档的 Mini-Chat 可修改当前表单。`doc_studio.translate` 接收粘贴文本或当前会话已授权的文件，使用同一翻译任务服务。`doc_studio.translation_status` 返回任务进度和已发布的产物。
- 文章卡片的 Mini-Chat 可更新正文、画幅和内置模板。安装文章卡片包后，AaAT 可用 `doc_studio.export_article_cards` 自动分页并发布首张 PNG 或整篇 ZIP。手动分页、封面、自定义模板和逐页编辑通过编辑器导出。
- 翻译文档的 ASCBot 保存目标语言和输出偏好。文章卡片的 ASCBot 保存画幅和内置模板。打开快捷入口会恢复选项，源文档、稿件、素材和权限留在各自的使用环境中。
