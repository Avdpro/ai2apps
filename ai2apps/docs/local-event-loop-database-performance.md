# Local 数据库与事件循环性能边界

2026-10-16。针对 Dev 采集并行时前端响应变慢的首轮修复。

## 已确认热点

原 PlatformDatabase 每个短事务新建并关闭 SQLite 连接。在包含 538 个 schema 对象的 Dev 数据库上，重复准备 SQL 会反复解析表结构。原生采样中主线程大量时间位于 SQLite schema 初始化及相关锁路径。浏览器续租还在每次事件唤醒后遍历历史任务，逐项更新并重新读取活跃任务。

## 当前实现

- 每个 PlatformDatabase 最多保留 8 个空闲连接，事务独占借出的连接；嵌套事务使用另一连接。没有空闲连接时新建，不同步等待连接池名额。跨 API 工作线程复用时不同时使用同一连接。
- 事务保持显式 BEGIN/COMMIT/ROLLBACK。BaseException 也回滚，提交回调仅在成功提交后运行；归还前清理事务、恢复 row_factory 和外键设置。公开 connect() 仍返回由调用者负责关闭的独立连接。
- Runtime stop 关闭空闲连接，借出的连接归还时关闭；不改变 owner、App、Session、Profile 或根任务准入边界。
- 浏览器租约每 15 秒批量续至 90 秒，不修改可见进度或产生续租事件，不再遍历和反序列化历史任务。
- 浏览器续租、待处理交互查询、情报推送意图检查、系统任务适配器的浏览器活动统计转入工作线程，避免相应 SQLite 锁等待直接阻塞事件循环。浏览器协议和执行/清理归属不变。

这不是“所有同步工作已移出事件循环”的承诺。Agent 创建、部分业务保存和调度仍有同步路径；后续依据实际事件循环采样逐项优化。不能用提高心跳超时替代阻塞治理，也不能为了响应快而放宽事务或安全边界。

## 验证与实测

事务测试覆盖回滚、BaseException、提交回调、嵌套、跨线程写、关闭归还，以及工作线程续租被写锁阻挡时事件循环继续运行。

相同 Dev 数据库上，100 次轻量查询：独立连接约 313ms，事务连接复用约 3.6ms。该读查询微基准不代表完整采集加速倍数。

空闲后分别通过 Helper 重载 App-Dev 和 Dev。App-Dev PID 86687/60253，Dev PID 86701/60468；健康接口均 200，实际日志记录 storage/database.py 从当前 checkout 导入。10 秒空闲测量 App-Dev CPU 约 3.5%，Dev 约 6.6%；bootstrap 中位响应分别约 3.4ms、3.2ms，最大约 4ms、14.2ms。这里没有活跃采集，不能与此前采集中 136% CPU 直接比较；真实多源高负载和长时间运行仍需持续观察。
