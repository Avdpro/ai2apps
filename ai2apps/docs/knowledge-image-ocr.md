# 知识库图片识别

新导入的图片在保存原件后创建持久化识别任务。重复导入同一图片复用已有条目，不重复识别；历史图片可从条目上的识别按钮手动加入任务，不自动扫描历史库。

## 模型与隐私规则

Knowledge 自己负责选择和授权，使用实时模型目录及明确设置的模型档位，不调用带隐式降级的默认模型解析器。仅使用明确支持图片、已就绪且未隐藏的模型。

1. 有签名 OCR 声明且无外网权限的本地 Package OCR，或明确声明 OCR 的本地/隐私模型。
2. 隐私低强度 `work_simple`。
3. 隐私中强度 `work_standard`。
4. 以上均不可用时，逐张询问是否允许把该图片交给选定的非隐私模型。选择顺序为系统多模态 `image_recognition`、系统低强度 `work_simple`、系统中强度 `work_standard`、API 默认模型。

授权绑定图片版本、随机令牌、具体模型及其目标地址/Package 版本，只允许一次执行。选定模型或目标变化后重新询问。拒绝后保留图片原件。隐私模型失败不会自动改用非隐私模型；模型超时、中断和失败也不自动重放。重试是用户的显式操作。

## 结果与任务

OCR 原文与通用多模态模型给出的图片简述分别保存，并生成可搜索的文本块。文字和图片简述均标记为不可信来源内容，不能产生操作授权。仅完整输出进入索引；被截断或格式不合法的结果进入失败状态。原始图片及其校验值不变。

图片的所有者可查看任务、授权、取消及重试，共享库读取权限不授予这些控制权限。任务执行前重新核对身份、条目版本、图片校验值和授权。取消或删除后，即使模型稍后返回，也不能写入结果。重启后进行中的任务标记失败，避免不确定的外部请求被重复执行。

图片解码有大小上限，处理 EXIF 方向和透明背景；仅裁掉明显的大面积白边，并限制传输尺寸。手写、复杂公式和稀疏页面仍可能识别错误，不能把 OCR 当作原件的权威替代。

## 实现边界

- `knowledge/ocr.py`：Knowledge 所有的模型优先级、图片预处理、任务执行和输出检查。
- `knowledge/ocr_store.py`：持久化状态、一次性授权、并发版本检查和索引写入。
- `model_invocation.py`：通用 Host 模型调用与目录回调，不包含 Knowledge 业务规则。
- `api/knowledge.py` 与共享 OCR 面板：所有者授权和任务控制；全屏与 Mini-App 复用。
- 平台数据库迁移 97；独立 Knowledge 数据库版本 2。

## 文件添加与自动归类（2026-10-30）

桌面添加窗口的笔记、网页、文件三种模式使用相同高度，顶部和底部固定，仅中间内容滚动。文件模式支持多文件、拖放到整个对话框、图片缩略图、文本片段预览、单项移除及对象 URL 清理。解析复用现有导入器，包含 Markdown、CSV、JSON、XML、代码、YAML、日志等文本格式。

知识桶默认“自动”。原件先保存到私有收件箱，随后由 Knowledge 所有的持久化任务基于正文选择已有私有桶。图片等 OCR 完成后再归类；音视频先使用已安装、无外网权限的本地 Package ASR 提取音轨文字。缺少模型或提取器时保留待处理，不使用文件名猜测。视频处理的是音轨，不是完整视频画面理解。显式选择目标桶则保留用户选择。

归类使用隐私低/中强度模型优先；若需系统低/中强度或 API 默认模型，界面先逐条确认，明确告知将发送提取文本和私有知识桶名称。令牌绑定内容版本、模型/Package/提供商目标和候选桶集合；重启清除尚未开始的批准。只能选择当前可见且属于该用户的私有桶，不能创建桶或扩展共享范围。失败/不确定调用不自动重放。

平台迁移98包含归类任务及批量导入的自动目标标记。87项相关Python测试、前端授权轮询测试及文件预览/去重/清理检查通过。归类与ASR模型调用使用隔离fixture验证，未宣称真实ASR推理质量或真实AI分类准确率；真实OXR识别证据仍见上文。原生App-Dev验证三种模式等高、默认自动、合成图片选择/缩略图/移除，未保存测试图片到用户知识库。

## 多文件合并为一条知识（2026-10-30）

桌面与移动文件添加入口均提供“合并为一条知识”，默认关闭，可填写记录标题。适用于一张购物单的多张照片、连续拍摄的文档页或一组相关文件。原件按选择顺序保留，每份独立提取/OCR/ASR及授权，提取结果按附件顺序汇总为同一个父记录。正文不交给额外模型重写。文件名与附件序号写入文本块来源元数据。

列表、全文搜索和向量候选只返回父记录，附件处理单元不会作为独立知识重复出现。已有单独记录不会因相同文件被合并而被隐藏或改动；普通文件去重不会复用内部附件。导入任务重启复用确定的记录/附件标识，不重复创建或重放已进行的媒体处理。父记录删除后原件访问、未开始的导入和后续识别均受父记录可见性约束。

未完成的附件显示待提取说明，已完成部分可检索；自动归类等待所有可处理内容完成。缺少模型、拒绝授权或不支持提取的文件不会仅凭文件名强行归类。桌面记录页面可查看汇总和逐个下载原件，128MiB以内可打包ZIP；移动阅读页提供附件下载。每个文件的非隐私授权保持独立。

### 连续截图 OCR 边界去重（2026-10-30）

合并记录新增默认开启的连续截图重叠检测，可在导入时关闭。仅对相邻且均已提取的图片，比较上一张 OCR 末尾与下一张开头；至少三条不同的连续非空行、48 个规范化字符，逐行匹配，数字必须一致。支持空白/全半角规范化与长行少量 OCR 字符误差。保留双方独有内容；完整重复页、短表头、不同数字、非相邻和非图片内容不会裁剪。边界最多100行，每行最多2000字符；不满足条件保留原文。

子附件原件及原始 OCR 不变，父记录和检索 chunk 使用派生正文，并保存匹配文本及删除行数供核查。桌面记录阅读页显示重叠报告及原始提取内容，ZIP 同时包含 knowledge.txt 与 original-ocr.txt。此版是本地、无额外模型调用的 OCR 正文处理，不生成拼接长图；重复页眉或 OCR 大幅差异可能使检测保守漏检。语义相同无法仅靠本规则保证是同一事实。

### 2026-10-30 实机内存准入故障

手机截图的 PNG Base64 被通用聊天资源估算器当作文本，导致单图临时内存估算约32GiB。128GiB Host 当时可用约52GiB，加上3GiB驻留估算及19.2GiB安全余量，请求无法准入，尽管计算槽空闲；知识库180秒调用期限先到。通用估算器现将图片传输缓冲与文本/视觉上下文分开，视觉预算使用图片头尺寸、未知图片保守预算，不读取远程URL，维持原安全余量及上下文上限。实际两图修正后均约3.895GiB临时估算，已在App-Dev原任务上分别完成527/900字符识别，合并记录ready=1、正文1469字符。未修改或发布OXR Package或Runtime。
