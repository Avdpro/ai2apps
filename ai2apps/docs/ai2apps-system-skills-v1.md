# AI2Apps 系统 Skill 技术方案 v1

状态：Discover 导入、Bot 技能管理、Harness 指令及文本参考文件的按需读取已实现。其余见实施顺序。

## 产品入口

**Discover → Skills** 管理工作区里的 Skill。用户可以浏览官方 Skill、导入本地目录或 GitHub 链接，并在已安装列表查看来源、版本、许可证、配套文件和依赖。详情提供预览、更新、导出、卸载和「添加到 Bot」。安装完成后，Skill 可供工作区内多个 Bot 选择。

**Messager → 右侧栏 → Skills** 独立显示当前 Bot 已添加的 Skill，默认列表为空。「添加技能」列出工作区中已安装、兼容且尚未添加的 Skill，选择后默认启用。取消勾选会停用 Skill 并保留列表条目；「移除」会从该 Bot 的列表中移除条目，但不会卸载系统中的 Skill。禁用或移除均撤回该 Bot 的运行授权，重新启用不会恢复旧授权。用户可以点名调用已启用的 Skill，Bot 也可根据任务和描述选择使用。首轮在消息开头输入 `/skill <名称或 ID>` 显式调用；同名时使用 ID。

**Bot 和 Coder** 都可生成标准 Skill 目录。Bot 在对话中交付可预览、可导出的 Skill 草稿，用户点「安装到 Discover」后进入同一套校验和安装流程。Coder 可将目录写到当前项目的 `.agents/skills/<name>/`，随项目提交共享，也可在 Discover 中导入。Coder 启动外部 Codex、OpenCode、Claude Code CLI 时，各 CLI 继续使用自己的发现设置。Coder 的 AI2Apps 原生 Harness 通过同一个 Skill 服务加载可用内容，并按项目授权读取项目目录。

## 格式与兼容

以 [Agent Skills 规范](https://agentskills.io/specification) 为交换格式。每个 Skill 目录包含 `SKILL.md`，以 YAML front matter 声明 `name`、`description`，正文为 Markdown。目录可带 `references/`、`assets/`、`scripts/` 等文件，引用路径以 Skill 目录为基准。保留原始文件和可选字段，导出时可原样交给其他客户端。

| 来源 | v1 兼容范围 |
| --- | --- |
| [Codex](https://learn.chatgpt.com/docs/build-skills) | 支持标准目录，可从 `.agents/skills` 中选取。Codex 专用展示和插件元数据随文件保留。 |
| [OpenCode](https://opencode.ai/docs/skills) | 支持标准目录，可从 `.opencode/skills` 中选取。识别 `metadata.opencode/autoinvoke` 为自动选择限制。 |
| [Claude Code](https://code.claude.com/docs/en/skills) | 支持标准目录，可从 `.claude/skills` 中选取。识别 `disable-model-invocation` 和 `user-invocable` 为加载方式限制。 |

自动和显式使用限制在服务端执行。遇到需要专有语义的 `context: fork`、`hooks`、动态命令展开、模型切换等字段或内容时，导入预览列出兼容差异。依赖未实现的执行语义时，该版本仍可预览和导出，启用前显示原因。`allowed-tools` 可以作为依赖提示，实际权限以宿主判定为准。v1 验收覆盖三家的标准目录格式，后续按实需补专有扩展。

## 安装与更新

三种来源统一走「解析来源 → 暂存 → 校验 → 预览 → 安装」流程。预览展示 Skill 名称、描述、来源、版本、文件清单、脚本、依赖和兼容问题。安装将已校验目录提交到工作区的受管存储，再切换目录记录指向的版本。失败时继续使用上一个已提交版本。

| 来源 | 解析与版本 |
| --- | --- |
| 本地目录 | 选择包含 `SKILL.md` 的文件夹。保存完整快照，日后可重新选择目录并预览更新。桌面目录选择器把选中的目录交给本机服务。远程客户端通过用户选择的文件交付内容，由服务暂存并校验。 |
| GitHub | 接受 `github.com` 仓库链接和具体目录链接。仓库链接列出候选 Skill，目录链接预选目标。将引用解析为提交 SHA，再读取该提交下的目录。保存仓库、目录、跟踪引用与提交 SHA。分支或标签变化时先预览版本差异，再更新。私有仓库需要宿主已有的 GitHub 授权，可用本地导入覆盖 v1 的匿名读取场景。 |
| 官方 Package | Discover 的 Skills 分类展示官方目录。按签名发布物验证发布者、版本、清单和文件摘要。一个 Package 可以携带多个标准 Skill 目录，安装后为每个目录建立可单独启用的 Skill 记录。Package 整体更新，按各 Skill 的稳定标识保留 Bot 关联。 |

当前 [Package 合约](../packages/contract_v1.py) 支持 App、Agent、Service 三种类型。官方交付拟新增 `skill` 类型，承载标准目录和声明式清单，沿用签名、版本和原子安装机制。实现前需打通 Local 类型校验、归档检查和 Discover 分类。如果 Cloud Registry 现行契约不能接收或查询该类型，另写 Cloud 需求交付 Cloud 项目实施。Local 导入、Bot 启用和运行可先使用独立测试数据验收。正式发布沿用 [Package 发布手册](../../docs/ai2apps-package-publication-runbook.md)。

导入器在提交前校验清单、路径和资源上限。目录遍历、绝对路径、符号链接、硬链接、特殊文件、同名路径冲突，以及超出限制的文件数、解压大小、目录深度都在导入阶段报错。GitHub 读取沿用宿主的受控网络入口，校验下载源和重定向，导入时只读取文件。元数据、Markdown 和压缩包均按外部输入处理，预览渲染使用安全的 Markdown 渲染器。

## 外部 Skill 安全评估

Discover 的本地目录和 GitHub 导入、更新预览提供「安全评估」。用户主动发起，安装仍由用户单独确认。导入校验先检查格式、路径、文件大小和兼容性，AI 再对该版本的静态内容进行审阅。评估输入使用已暂存的版本，外部文件里的指令作为待审文本。评估只访问这份快照，既不执行脚本，也不请求文件里列出的 URL。使用云模型时，在开始前显示所用模型及会发送的文件范围。

评估结果按风险点列出严重度、文件和可定位的证据、可能影响及处理建议。首轮关注超出任务范围的指令、敏感数据读取或外传、外部命令和网络依赖，以及会写入、删除或发布内容的操作。报告列出已审、跳过和无法审阅的文件，部分覆盖要明确标出。报告绑定来源和内容摘要，内容更新后提示重新评估。模型的建议不授予任何执行权限，导入器的硬性校验始终生效。

## 持久化与运行

- **安装记录**以工作区和稳定 `skill_id` 标识，保存来源、显示元数据、当前 `revision_id`、可用状态和兼容诊断。同名 Skill 可并存，选择器显示来源用于区分。官方标识由 Package 和 Skill 目录标识组成，本地和 GitHub 导入由宿主分配稳定 ID。重复安装同一来源和内容应复用已有记录。
- **版本记录**保存来源版本和文件清单摘要，版本目录不可变。保存文件、提交版本指针和 Bot 关联更新须支持重复请求和并发。更换来源应明确显示来源变更，由用户确认是更新现有安装还是另装一份。
- **Bot 关联**按工作区、Bot 和 `skill_id` 保存，由 Bot owner 校验。部署时已有 Bot 默认启用列表为空。卸载前展示哪些 Bot 正在使用，并在卸载后从可用列表移除。历史执行仍能显示当时实际使用的版本。
- **Run 快照**在对话回合或 Task Run 准入时保存可见 Skill ID 和版本。恢复同一 Run 使用同一版本，部署后开启的新回合或新执行读取当前设置。运行时加载之前复核工作区、Bot、启用和卸载状态，以及快照版本。更新可让旧 Run 继续使用旧版本，禁用或卸载后中止该 Run 的后续 Skill 读取和受其驱动的下一步，已有结果仍可查看。委派子 Task 在准入时按接收 Bot 的设置生成自己的列表。
- **审计**记录 Run、Skill ID、版本、来源、显式或自动选择，以及成功或失败状态。回执记录标识及状态，正文和私有工作区路径只在其原授权范围内读取。

Harness 先在独立选择步骤提供可用 Skill 的名称和描述，也可从用户显式引用解析选择。宿主复核关联与版本后按 ID 加载 `SKILL.md`。若该版本有文本参考文件，再让模型根据当前请求、正文和相对路径选出必要文件。未选文件的内容不会读取或交给模型。Skill 作者应在正文里用相对链接说明每个参考文件的用途。

参考文件从 Run 固定版本的已安装目录读取，只支持 `references/` 下受支持的 UTF-8 文本。每个 Run 最多选择 4 份，每份最多 8 KiB；模型可选零份。路径必须与版本清单完全匹配，禁止跨 Skill 或读取本机任意路径。读取结果标明相对路径，无法读取时报告原因。选择步骤和选定路径保存在原 Run 中，恢复时复用；模型用量计入原预算，选择结果不会当作回复或工具调用重放。首轮实现不递归展开文档链接，不执行脚本，二进制资源留待后续实现。无需为各业务 Skill 修改 General Agent 提示词。

Skill 是工作指引，权限由现有 Bot、Task 和 ToolGateway 判定。Skill 中列出的工具、MCP、解释器和网络依赖仅用于判断可用性和展示缺项。脚本若可执行，必须通过现有受限执行能力，以明确的工作目录、参数、输入输出范围及预算运行，遵循对应的用户授权。v1 可以保留并预览脚本，对缺少适配执行器的依赖显示不可运行。安装、预览和加载均无脚本副作用。App/AaAT 声明、参数准备和交互仍走 [AaAT 声明与 Context 契约](aaat-declaration-context-v1.md)。

## 生成与交付

Bot 通过工作区或会话产物生成标准目录，交付前运行同一格式和路径校验。草稿可以预览文件树、Markdown、依赖和兼容诊断。交付卡使用会话所属的草稿标识打开 Discover 安装预览，由宿主重新解析并校验其来源和权限。用户可先编辑，再安装或导出。Coder 使用项目文件能力在授权目录落盘，导入后工作区版本与项目副本按各自的更新流程维护。官方发布由具备权限的发布者通过签名流程完成。

## 从 Skill 创建 Studio Mini-App

当前实现支持在 Discover 的已安装 Skill 详情里手动配置参数，并选择 Imagine Studio 的图像流程。表单支持短文本、多行文本、数字、开关、枚举和素材库图片。其他 Studio 在选择器中标为暂不兼容。名称、字段定义、工作室和完整 Skill 版本由 Local 保存。

Imagine Studio 校验输入、素材归属和绘图模型支持的尺寸后，一次提交同时登记 Studio Run 和后台作业。作业使用隐私配置的标准任务模型，从固定版本的 Skill 和表单值准备绘图提示词。参考文件按需选取，每次最多四份，每份最多 8 KiB。随后通过 Imagine Studio 原有图像生成与共享 Output 管道产出一张 PNG。Skill 内容不会注册为工具或执行脚本。更新 Skill 后已有表单仍使用创建时的版本。卸载 Skill 时移除入口，先前的 Studio 产物照常保留。

后续设计包括 AI 起草参数表单、根据版本差异切换已有 Mini-App 使用的 Skill，以及扩展其他 Studio 工作流。使用边界和宿主输出遵循 [Studio Mini-App Package 合同](../../docs/ai2apps-studio-mini-app-package-contract-v1.md)。

## 实施顺序与验收

1. 实现共用验证器、工作区版本存储、导入预览与安装服务。接 Discover 的本地和 GitHub 导入，覆盖安装、更新、导出、卸载和同名来源识别。
2. 接 Messager Bot 技能和 Harness 按需加载。覆盖点名加载、自动匹配、不同 Bot 隔离、进行中 Run 恢复、版本升级、禁用与委派。用不同工具提供者验证 Skill 只能行使原有权限。
3. 接外部 Skill 安全评估，和 Bot 草稿交付复用 Discover 的暂存与预览。验收正常样本、有风险的样本、部分覆盖、更新后报告失效，以及草稿生成、预览、安装、启用到运行的完整流程。
4. 接参数表单和 Studio 选择，先完成一个可安装和可运行的 Skill Mini-App。验收表单校验、不兼容的 Studio、版本切换及宿主统一输出。
5. 接 Coder 项目目录。至少选用标准 Codex、OpenCode、Claude Code 目录各一份，验证原样导入和相对引用。
6. 接官方 Package、Discover 目录和更新。验收签名正确的测试发布物、签名错误和内容摘要不符的拒绝分支，以及更新后 Bot 关联保留。生产目录验收在 Cloud 合约和正式签名齐备时进行。

自动化测试覆盖无效 front matter、缺失引用、路径越界、归档上限、同名 Skill、跨工作区访问、禁用后恢复和安装提交失败。改动共享执行后，从 Git 根目录运行 `python ai2apps/tests/run_aaat_boundaries.py`，另用 Dev 或 App-Dev 按正常入口验收 Discover 到 Bot 的实际操作。验收记录注明哪些用例使用测试发布物或预设模型，哪些使用真实客户端和模型。实现开始后同步登记 Desktop release ledger。
